Sau bài này bạn sẽ

  • Chọn đúng file settings (user, shared project, project local, managed) cho từng loại cấu hình và giải thích được precedence giữa chúng.
  • Viết được permission rules allow / ask / deny đúng cú pháp và hiểu thứ tự đánh giá deny → ask → allow.
  • Cấu hình hooks (PreToolUse, PostToolUse, SessionStart, Stop…), đọc input JSON từ stdin và điều khiển kết quả bằng exit code hoặc JSON output.
  • Kết nối MCP server vào Claude Code bằng claude mcp add, chọn đúng scope (local / project / user) và quản lý bằng /mcp.
  • Áp dụng các biện pháp bảo mật: least privilege, chống prompt injection, managed settings cho tổ chức, sandbox.

⚙️Settings: các file, scope và thứ tự ưu tiên

Settings là các khóa JSON thay đổi hành vi của Claude Code: model khởi động, lệnh nào được chạy không cần hỏi, file nào bị cấm đọc, giao diện terminal, và những gì tổ chức bắt buộc. Claude Code đọc chúng từ bốn file, cộng thêm managed settings từ tổ chức.

Lưu ý: ~/.claude là thư mục .claude trong home directory (trên Windows là %USERPROFILE%\.claude), còn .claude không có dấu ngã là thư mục trong project. Ngoài ra Claude Code còn tự ghi một file thứ năm là ~/.claude.json. File này chứa thông tin tài khoản, cấu hình MCP server (scope local và user), trạng thái theo project như quyết định trust, và các khóa global config mà /config ghi. Bạn không cần sửa tay file này.

Thứ tự ưu tiên (precedence)

Khi cùng một khóa xuất hiện ở nhiều nơi, Claude Code lấy giá trị ở tầng cao nhất có đặt khóa đó:

  • Mảng được gộp, không ghi đè. Nếu nhiều file cùng đặt permissions.allow, Claude Code nối các danh sách lại. Mỗi file chỉ thêm quy tắc, không xóa quy tắc của file khác. Một vài khóa về model có quy tắc riêng.
  • Biến môi trường không phải một tầng. Mỗi cặp biến/khóa có quy tắc riêng. Ví dụ ANTHROPIC_MODEL export trong shell sẽ thắng khóa model ở mọi file.
  • Ngoại lệ bảo mật: với vài khóa có tính hạn chế, giá trị chặt hơn ở tầng thấp vẫn được tôn trọng. Ví dụ disableClaudeAiConnectors: true ở bất kỳ scope nào cũng có hiệu lực, kể cả khi managed đặt false.

Ví dụ file settings

File settings là JSON nghiêm ngặt: một chú thích // hay dấu phẩy thừa cuối cũng là lỗi cú pháp. Ví dụ dưới đây lấy từ tài liệu, cho phép chạy lint/test không cần hỏi và cấm đọc .env:

// ~/.claude/settings.json  (chú thích này chỉ để giải thích – file thật KHÔNG được có //)
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run test *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)"
    ]
  }
}

Dòng $schema trỏ tới JSON schema công khai, giúp VS Code, Cursor… gợi ý và kiểm tra khóa ngay khi gõ. Schema có thể chậm hơn bản CLI mới nhất, nên cảnh báo trên một khóa vừa ra chưa chắc là cấu hình sai.

Ba cách thay đổi setting

  1. Menu /config – mở tab Config trong terminal. Chỉ có một nhóm tùy chọn cá nhân (theme, editor mode, verbose…). Phần lớn được lưu vào ~/.claude/settings.json.
  2. Sửa file settings – mở file của scope bạn muốn rồi thêm hoặc sửa khóa. Claude Code theo dõi file và tự nạp lại phần lớn thay đổi (kể cả permissions và hooks) mà không cần khởi động lại.
  3. Chỉ cho một phiên – claude --settings '{"model": "claude-opus-5-5"}', một flag riêng như --model, hoặc biến môi trường như ANTHROPIC_MODEL.

Sau khi sửa, chạy /status và xem dòng Setting sources để biết file nào đã được nạp. Nếu có giá trị bị từ chối, claude doctor sẽ liệt kê chi tiết.

Mẹo thực chiến (Pro Tip)

Nhóm muốn mọi người dùng chung quy tắc quyền và hooks, nhưng bạn muốn dùng model khác ⇒ để cấu hình chung trong .claude/settings.json (commit), còn ghi đè cá nhân thì đặt trong .claude/settings.local.json. Tầng project local cao hơn shared project, nên chỉ phiên của bạn bị ảnh hưởng.

Lỗi thường gặp
  • Commit một khóa nhưng đồng đội không thấy có hiệu lực. Một số khóa không áp dụng từ file trong repository (scope chỉ là User, Managed hoặc Global config). Ngoài ra permissions.allow, additionalDirectories và phần lớn env chỉ áp dụng sau khi từng người trust thư mục. Riêng deny và ask có hiệu lực ngay.
  • Đặt defaultMode: "bypassPermissions" trong project settings. Giá trị auto và bypassPermissions không có hiệu lực từ project hoặc local settings. Phải đặt ở user hoặc managed settings.
  • Thêm chú thích // vào settings.json. Claude Code báo Settings Error khi khởi động.

🔐Permissions: allow, ask, deny và permission modes

Claude Code dùng hệ thống quyền nhiều tầng. Bạn khai báo permission rules trong khóa permissions của settings, hoặc xem và sửa trực tiếp bằng lệnh /permissions. Lệnh này liệt kê mọi quy tắc kèm file settings chứa quy tắc đó.

  • Allow – Claude Code dùng tool mà không cần bạn duyệt.
  • Ask – hỏi xác nhận mỗi khi Claude muốn dùng tool đó.
  • Deny – cấm Claude Code dùng tool đó.

Thứ tự đánh giá: deny → ask → allow

Tài liệu viết: "Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the outcome, and rule specificity doesn't change the order." Nghĩa là quy tắc khớp đầu tiên theo thứ tự đó quyết định kết quả. Quy tắc cụ thể hơn không được ưu tiên.

Ví dụ từ tài liệu: deny rule rộng Bash(aws *) chặn mọi lệnh khớp, kể cả lệnh khớp một allow rule hẹp hơn như Bash(aws s3 ls). Quy tắc này áp dụng cả giữa các scope: user settings allow mà project settings deny thì deny thắng, và ngược lại.

Lưu ý về "Yes, and don't ask again"

Khi bạn chọn tùy chọn này trên lời hỏi chạy lệnh Bash, Claude Code lưu một allow rule vào .claude/settings.local.json. Nhưng allow rule ở file local không thắng một ask rule từ project hoặc managed. Vì vậy có khi bạn đã chọn "đừng hỏi nữa" mà vẫn bị hỏi.

🪝Hooks: sự kiện vòng đời và cách cấu hình

Theo tài liệu, hooks là các lệnh shell do người dùng định nghĩa. Claude Code chạy chúng ở những thời điểm cụ thể trong lifecycle của phiên làm việc. Bạn dùng hooks để format file sau khi sửa, chặn lệnh trước khi chạy, gửi thông báo khi Claude chờ bạn, nạp ngữ cảnh lúc bắt đầu phiên, và nhiều việc khác.

Cấu trúc cấu hình: sự kiện → matcher group → handler

Hooks được khai báo trong khóa hooks của file settings (user, project, local, managed), trong hooks/hooks.json của plugin, hoặc frontmatter của skill/subagent. Gõ /hooks trong Claude Code để mở trình duyệt hooks và kiểm tra hook đã được nạp chưa. Cấu trúc lồng ba tầng:

{
  "hooks": {
    "PreToolUse": [                       // tầng 1: tên sự kiện
      {
        "matcher": "Bash",                   // tầng 2: matcher group – lọc theo tên tool
        "hooks": [                         // tầng 3: danh sách handler
          {
            "type": "command",
            "if": "Bash(rm *)",              // lọc thêm bằng cú pháp permission rule
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh",
            "args": []
          }
        ]
      }
    ]
  }
}

(Chú thích // chỉ để giải thích; file settings thật không được có chú thích.)

  • matcher: "*", "" hoặc bỏ trống = khớp tất cả. Danh sách tên chính xác ngăn bởi | hoặc , (ví dụ "Edit|Write"). Nếu chứa ký tự khác thì được hiểu là JavaScript regex (ví dụ "mcp__memory__.*", "^Notebook").
  • if: chỉ dùng cho sự kiện tool, chứa đúng một rule theo cú pháp permission (không có && hay ||).
  • Các hook khớp chạy song song. Handler giống hệt nhau khai báo ở nhiều file chỉ chạy một lần.
  • Biến tiện ích: ${CLAUDE_PROJECT_DIR} (thư mục gốc project), ${CLAUDE_PLUGIN_ROOT} (thư mục cài plugin).

📤Hooks: input, exit code và JSON output

Hook nhận dữ liệu dưới dạng JSON qua stdin, và trả kết quả bằng exit code hoặc bằng một object JSON in ra stdout. Nắm chắc ý nghĩa ba nhóm exit code là bạn viết được phần lớn các hook thông dụng.

Input JSON

{
  "session_id": "abc123",
  "transcript_path": "/home/user/.claude/projects/.../transcript.jsonl",
  "cwd": "/home/user/my-project",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "npm test", "timeout": 120000 },

Đây là ví dụ rút gọn từ tài liệu: năm trường đầu là trường chung, ba trường cuối (tool_name, tool_input, tool_use_id) là của sự kiện tool. Input thật còn có thêm vài trường như prompt_id và effort. Khi hook chạy bên trong subagent, input có thêm agent_id và agent_type.

Ba nhóm exit code

✅Exit 0

  • Thành công.
  • Nếu stdout là một object JSON thì các trường của nó được áp dụng.
  • Với UserPromptSubmit, SessionStart và vài sự kiện khác, stdout dạng text được thêm vào ngữ cảnh của Claude.

⛔Exit 2

  • Lỗi chặn (blocking error).
  • Ở sự kiện chặn được: dừng hành động. stderr là lý do gửi ngược cho Claude.
  • Ở sự kiện không chặn được: bị bỏ qua, stderr hiển thị cho người dùng.

⚠️Exit khác (1, 3…)

  • Lỗi không chặn: hành động vẫn tiếp tục.
  • Hiện thông báo <hook name> hook error.
  • Exit 1 KHÔNG phải là chặn.
Lỗi thường gặp
  • Dùng exit 1 để chặn lệnh nguy hiểm. Exit 1 chỉ là lỗi không chặn: lệnh vẫn chạy. Phải dùng exit 2 (kèm lý do ở stderr) hoặc JSON permissionDecision: "deny".
  • In thêm log ra stdout khi muốn trả JSON. Tài liệu yêu cầu chỉ in đúng object JSON rồi exit 0. Log gỡ lỗi nên ghi ra stderr hoặc file.
  • Hook bị treo hoặc không khởi động được. Mặc định hành động vẫn tiếp tục (fail-open), kể cả với PreToolUse. Muốn chặn khi hook lỗi thì thêm "onFailure": "block".

JSON output

Thay vì exit code, hook có thể in một object JSON để điều khiển chi tiết hơn:

TrườngMặc địnhTác dụng
continuetruefalse = dừng Claude hoàn toàn. Riêng nó không chặn một PreToolUse call; cần đi kèm permissionDecision: "deny"
stopReason–Thông điệp hiển thị khi continue là false
systemMessage–Cảnh báo hiển thị cho người dùng
hookSpecificOutput–Quyết định riêng theo sự kiện (bắt buộc có hookEventName). Với PreToolUse: permissionDecision = allow / deny / ask / defer, kèm permissionDecisionReason
additionalContext–Nằm trong hookSpecificOutput, chèn text vào ngữ cảnh của Claude dưới dạng system reminder
decision: "block" + reason–Kiểu quyết định ở cấp ngoài cùng, dùng cho các sự kiện khác

Ví dụ 1 – Chặn sửa file nhạy cảm (PreToolUse + exit 2)

#!/bin/bash
# .claude/hooks/protect-files.sh – theo ví dụ trong "Automate actions with hooks"
INPUT=$(cat)                                              # đọc input JSON từ stdin
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
FILE_PATH="${FILE_PATH//\\//}"                             # chuẩn hóa dấu \ trên Windows

PROTECTED_PATTERNS=(".env" "package-lock.json" ".git/")
for pattern in "${PROTECTED_PATTERNS[@]}"; do
  if [[ "$FILE_PATH" == *"$pattern"* ]]; then
    echo "Blocked: $FILE_PATH matches protected pattern '$pattern'" >&2  # lý do gửi cho Claude
    exit 2                                                # 2 = chặn
  fi
done
exit 0
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command",
                     "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh" } ] }
    ]
  }
}

Đăng ký trong .claude/settings.json và nhớ chmod +x script trên macOS/Linux. Tài liệu cảnh báo: Claude vẫn có thể sửa các file đó bằng lệnh shell. Vì vậy nên thêm Edit deny rule cho từng đường dẫn, và nếu cần chắc chắn thì bật sandbox.

Ví dụ 2 – Tự format sau khi sửa (PostToolUse)

{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command",
          "command": "f=$(jq -r '.tool_input.file_path') && npx prettier --write --ignore-unknown \"$f\"" } ] }
    ]

Ví dụ 3 – Nhắc lại ngữ cảnh sau khi compact (SessionStart)

{
  "hooks": {
    "SessionStart": [
      { "matcher": "compact",
        "hooks": [ { "type": "command",
          "command": "echo 'Reminder: use Bun, not npm. Run bun test before committing.'" } ] }
    ]
  }
}

Matcher compact nghĩa là hook chỉ chạy khi phiên tiếp tục sau compaction. Với SessionStart, text in ra stdout được thêm vào ngữ cảnh của Claude. Nếu muốn nạp ngữ cảnh ở mọi lần bắt đầu phiên, tài liệu khuyên dùng CLAUDE.md thay vì hook.

Ví dụ 4 – Từ chối bằng JSON (PreToolUse)

#!/bin/bash
COMMAND=$(jq -r '.tool_input.command')
if echo "$COMMAND" | grep -q 'rm -rf'; then
  jq -n '{ hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: "Destructive command blocked by hook" } }'
else
  exit 0
fi
Hook và permission rules phối hợp thế nào?

Theo trang Configure permissions, quyết định của PreToolUse hook không vượt qua permission rules: deny rule khớp vẫn chặn, ask rule khớp vẫn hỏi, kể cả khi hook trả "allow". Ngược lại, hook chặn (exit 2) chạy trước khi permission rules được xét, nên nó chặn được cả lệnh mà allow rule cho phép. Từ đó có mẫu: allow toàn bộ "Bash", rồi dùng PreToolUse hook để từ chối vài lệnh cụ thể.

Mẹo thực chiến (Pro Tip)

Viết Stop hook để buộc Claude chạy test cho tới khi pass ⇒ phải đọc trường stop_hook_active trong input và thoát sớm nếu nó là true, tránh vòng lặp vô hạn. Claude Code sẽ bỏ qua Stop hook sau khi nó chặn 8 lần liên tiếp mà không có tool call nào xen giữa.

🧩MCP servers trong Claude Code

Ở bài 27–30 bạn đã học Model Context Protocol (MCP) từ phía giao thức. Ở đây Claude Code đóng vai MCP host: bạn chỉ cần khai báo server, Claude Code tự kết nối và đưa tool của server vào cho Claude dùng, với tên dạng mcp__<server>__<tool>.

Thêm server bằng claude mcp add

# 1) Remote HTTP – cách được khuyến nghị cho server từ xa
claude mcp add --transport http notion https://mcp.notion.com/mcp

# Kèm header xác thực (đừng commit token thật vào repo!)
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer your-token"

# 2) Local stdio – mọi thứ sau "--" được chuyển nguyên cho server
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable \
  -- npx -y airtable-mcp-server

# 3) SSE – đã deprecated, chỉ dùng khi server chưa hỗ trợ HTTP
claude mcp add --transport sse asana https://mcp.asana.com/sse

# 4) Từ một khối JSON có sẵn
claude mcp add-json example '{"command":"npx","args":["-y","@example/mcp-server"]}'
FlagÝ nghĩa
--transport / -thttp, sse, stdio (ws chỉ qua add-json)
--scope / -slocal (mặc định), project, user
--env / -eBiến môi trường KEY=value cho server, lặp lại được
--header / -HHeader HTTP, lặp lại được
--Ngăn cách option của Claude Code với lệnh và tham số của server stdio

Ba scope cài đặt MCP

Một file .mcp.json (scope project) trông như sau. Nó hỗ trợ mở rộng biến môi trường ${VAR} và ${VAR:-default} trong command, args, env, url, headers, nhờ đó token không phải nằm trong repo:

{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}

Lưu ý bảo mật trong tài liệu: ở url và headers của server remote, các biến chứa credential như ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN luôn được mở rộng thành chuỗi rỗng. Cơ chế này ngăn một project gửi credential của bạn tới server mà project đó tự chỉ định. Một entry có url nhưng thiếu type sẽ bị coi là stdio và bị bỏ qua kèm lỗi.

Quản lý và xác thực

  • claude mcp list liệt kê server kèm tình trạng, claude mcp get <name> xem chi tiết, claude mcp remove <name> gỡ server.
  • Trong phiên, /mcp hiển thị trạng thái (✔ Connected, ! Needs authentication, ✘ Failed to connect, ⏸ Pending approval), số tool, và cho bật/tắt từng server.
  • OAuth: chạy /mcp rồi đăng nhập trên trình duyệt. Token được lưu an toàn và tự làm mới. Từ shell thì dùng claude mcp login <name>.
  • Phê duyệt server project: trong phiên tương tác, Claude Code hỏi trước khi dùng server từ .mcp.json. Đặt lại lựa chọn bằng claude mcp reset-project-choices. Trong claude -p và Agent SDK, các server này được nạp không hỏi.
  • Resource: tham chiếu bằng @server:protocol://resource/path, ví dụ @github:issue://123.
  • Nhập từ Claude Desktop: claude mcp add-from-claude-desktop. Ngược lại, claude mcp serve biến chính Claude Code thành một MCP server stdio.

Giới hạn output và tool search

10.000token – ngưỡng cảnh báo khi output một MCP tool vượt quá
25.000token – giới hạn mặc định, chỉnh bằng MAX_MCP_OUTPUT_TOKENS
50.000ký tự – kết quả text dài hơn được lưu ra file
128ký tự – tên đầy đủ mcp__server__tool dài hơn sẽ bị bỏ

Tool search được bật mặc định: chỉ tên tool và server instructions được nạp lúc đầu, còn định nghĩa tool được nạp khi Claude cần. Vì vậy thêm nhiều MCP server cũng ít tốn context window. Các biến môi trường liên quan: MCP_TIMEOUT (timeout khởi động), MCP_TOOL_TIMEOUT (timeout gọi tool), ENABLE_TOOL_SEARCH.

Mẹo thực chiến (Pro Tip)

Cả nhóm cần dùng chung một MCP server (ví dụ Sentry của công ty) ⇒ claude mcp add --scope project ... để tạo .mcp.json rồi commit; token để trong biến môi trường ${SENTRY_TOKEN}. Server chỉ bạn dùng thử ⇒ scope local. Server cá nhân dùng ở mọi project ⇒ scope user.

Lỗi thường gặp
  • Quên -- với server stdio: Claude Code sẽ tự đọc các flag của server như flag của mình.
  • Đặt tên server ngay sau --env: CLI hiểu tên đó là một cặp KEY=value nữa. Hãy chen một option khác, ví dụ --transport stdio, vào giữa.
  • Viết permission rule mcp__github__create_issue(repo:x) trong settings: Claude Code bỏ qua mọi rule mcp__ có ngoặc đơn.

🛡️Bảo mật: least privilege, prompt injection và quản trị tổ chức

Prompt injection – mối nguy chính của agent

Prompt injection là kỹ thuật kẻ tấn công chèn văn bản độc hại để ghi đè hoặc thao túng chỉ dẫn của AI. Với Claude Code, nguồn văn bản đó có thể là README của một repo lạ, comment trong code, trang web được fetch, hoặc output của một MCP server. Tài liệu MCP cảnh báo: server lấy nội dung từ bên ngoài có thể khiến bạn bị prompt injection.

Thực hành tốt nhất theo tài liệu khi làm việc với nội dung không tin cậy:

  1. Xem lại lệnh được đề xuất trước khi duyệt.
  2. Tránh đưa nội dung không tin cậy thẳng vào Claude (pipe trực tiếp).
  3. Kiểm tra thay đổi ở các file quan trọng.
  4. Dùng máy ảo (VM) để chạy script và tool call, nhất là khi tương tác với dịch vụ web bên ngoài.
  5. Báo hành vi đáng ngờ bằng /feedback.

Bảo mật cho hooks và MCP

  • Hooks chạy với quyền của bạn và kế thừa biến môi trường. Hook trong .claude/settings.json của repo lạ là code người khác viết, nên luôn đọc trước khi trust thư mục.
  • if chỉ là best-effort. Khi Claude Code không tách được một lệnh Bash, hook vẫn chạy. Muốn allow/deny cứng thì dùng permission system, đừng dựa vào hook.
  • Dùng exec form (args) cho hook có tham số đường dẫn: không có shell phân tích tham số, nên tránh được shell injection.
  • Viết additionalContext dạng mô tả sự thật. Text kiểu mệnh lệnh giống system có thể kích hoạt cơ chế phòng chống injection của Claude.
  • MCP: tự viết server hoặc chỉ dùng server từ nhà cung cấp bạn tin. Anthropic duyệt connector theo tiêu chí niêm yết nhưng không kiểm toán bảo mật MCP server nào. Xem .mcp.json cũng không thấy hết server một phiên có thể nạp (còn user/local scope, plugin, connector).

Liên hệ chuẩn IPA

Các nguyên tắc trên khớp với tinh thần tài liệu 「安全なウェブサイトの作り方」 và 「セキュア・プログラミング講座」 của IPA: cấp quyền tối thiểu, không để credential trong mã nguồn, kiểm tra đầu vào không tin cậy (ở đây là văn bản có thể chứa prompt injection), và ghi log để kiểm toán. Bài này không trích số liệu cụ thể từ IPA.

🧪Thực hành

  1. Bài tập 1 – Settings an toàn cho nhóm. Trong một repo Node.js, tạo .claude/settings.json: allow Bash(npm run lint) và Bash(npm run test *); ask Bash(git push *); deny Read(./.env), Read(./.env.*), Read(./secrets/**). Sau đó tạo .claude/settings.local.json để đổi model cho riêng bạn.
    Kết quả mong đợi: /status hiển thị cả Shared project settings và Project local settings. /permissions liệt kê đủ quy tắc kèm file nguồn. Yêu cầu Claude "đọc file .env" thì bị từ chối.
  2. Bài tập 2 – Hook chặn file nhạy cảm và tự format. Tạo .claude/hooks/protect-files.sh như ví dụ 1, đăng ký PreToolUse với matcher Edit|Write. Thêm PostToolUse chạy Prettier. 
    # Tự kiểm thử script không cần Claude: giả lập input JSON qua stdin
echo '{"tool_input":{"file_path":"/repo/.env"}}' | .claude/hooks/protect-files.sh
echo "exit=$?"     # mong đợi: in "Blocked: ..." ra stderr và exit=2
echo '{"tool_input":{"file_path":"/repo/src/app.js"}}' | .claude/hooks/protect-files.sh
echo "exit=$?"     # mong đợi: exit=0
    Kết quả mong đợi: /hooks hiển thị hai hook. Khi bạn bảo Claude thêm comment vào .env, edit bị chặn và Claude nhận được thông điệp Blocked:. Sửa một file JS có nháy đơn thì Prettier đổi sang nháy kép.
  3. Bài tập 3 – Kết nối MCP server cho nhóm. Chạy claude mcp add --transport http --scope project docs https://example.com/mcp (thay bằng server thật bạn tin cậy). Mở .mcp.json, chuyển token sang ${DOCS_TOKEN}. Chạy claude mcp list và /mcp.
    Kết quả mong đợi: server hiện ⏸ Pending approval cho tới khi bạn duyệt, sau đó là ✔ Connected. Tool hiện với tên mcp__docs__.... Thêm allow rule mcp__docs__* để khỏi bị hỏi mỗi lần.
  4. Bài tập 4 – Stop hook kiểm tra test (nâng cao). Viết Stop hook chạy npm test. Nếu fail thì in lý do ra stderr và exit 2 để Claude làm tiếp. Nhớ kiểm tra stop_hook_active để tránh vòng lặp.
    Kết quả mong đợi: Claude không kết thúc lượt khi test còn đỏ. Khi stop_hook_active là true, hook thoát 0 ngay.

Tóm tắt ghi nhớ

Key takeaways
  • Bốn file settings: user ~/.claude/settings.json, shared project .claude/settings.json, project local .claude/settings.local.json, managed. Ưu tiên: Managed > command line > local > project > user. Mảng như permissions.allow được gộp.
  • Permission rules đánh giá theo thứ tự deny → ask → allow. Quy tắc khớp đầu tiên thắng, độ cụ thể không quan trọng. Allow không khoét được ngoại lệ trong deny.
  • Hooks = kiểm soát tất định. Cấu trúc: sự kiện → matcher → handler (command, http, mcp_tool, prompt, agent). Input JSON qua stdin.
  • Exit 0 thành công (JSON trên stdout được áp dụng), exit 2 chặn (stderr gửi cho Claude), exit khác là lỗi không chặn. Exit 1 không chặn.
  • Hook allow không vượt qua deny/ask rule. Hook exit 2 chặn được cả lệnh mà allow rule cho phép. Hook lỗi hoặc timeout mặc định fail-open, trừ khi đặt onFailure: "block".
  • MCP: claude mcp add --transport http|stdio|sse. Scope local (mặc định, ~/.claude.json), project (.mcp.json, commit), user. Dùng ${VAR} cho token. Output MCP mặc định tối đa 25.000 token.
  • Bảo mật: least privilege, deny file bí mật, cảnh giác prompt injection từ web/MCP/repo lạ, sandbox/dev container, managed settings cho tổ chức.

Thứ tự ưu tiên – quy tắc chọn giá trị khi cùng khóa đặt ở nhiều file.
Managed settings
Cấu hình do tổ chức quản lý – triển khai qua managed-settings.json, MDM hoặc server-managed; không bị ghi đè.
Permission rule
Quy tắc quyền – allow / ask / deny, cú pháp Tool(specifier).
Permission mode
Chế độ quyền – default, acceptEdits, plan, auto, dontAsk, bypassPermissions.
Workspace trust
Tin cậy thư mục làm việc – bước xác nhận trước khi allow rules, env… từ repo có hiệu lực.
Hook
Móc sự kiện – code của người dùng chạy tự động ở một sự kiện vòng đời Claude Code.
Hook event
Sự kiện hook – thời điểm kích hoạt: PreToolUse, PostToolUse, Stop, SessionStart…
Matcher
Bộ lọc khớp – chuỗi lọc nhóm hook theo tên tool hoặc nguồn sự kiện, hỗ trợ | và regex.
Hook handler
Trình xử lý hook – phần thực thi: command, http, mcp_tool, prompt, agent.
Exit code
Mã thoát – 0 = thành công, 2 = chặn, khác = lỗi không chặn.
additionalContext
Ngữ cảnh bổ sung – text hook chèn vào ngữ cảnh của Claude dưới dạng system reminder.
Fail-open / fail-closed
Mặc định mở / mặc định đóng – khi cơ chế kiểm tra lỗi thì hành động được tiếp tục hay bị chặn.
MCP scope (local / project / user)
Phạm vi cài MCP – nơi lưu cấu hình server: ~/.claude.json hoặc .mcp.json.
.mcp.json
File cấu hình MCP của project – đặt ở gốc project, commit để chia sẻ cho nhóm.
Transport (stdio / HTTP / SSE)
Tầng truyền tải – cách Claude Code nói chuyện với MCP server; SSE đã deprecated.
Tool search
Tìm kiếm tool – nạp định nghĩa MCP tool theo nhu cầu để tiết kiệm context window.
Prompt injection
Chèn lệnh độc hại vào prompt – văn bản độc hại cố thao túng chỉ dẫn của agent.
Sandbox
Môi trường cách ly – giới hạn filesystem và mạng của lệnh Bash ở mức hệ điều hành.
Least privilege
Đặc quyền tối thiểu – chỉ cấp đúng quyền cần cho công việc.

Câu hỏi luyện tập

Nhóm của Lan commit .claude/settings.json với "model": "claude-sonnet-5". Lan muốn dùng model khác chỉ cho riêng mình trong project này mà không ảnh hưởng đồng đội. Cô nên đặt khóa model ở đâu?
  1. Sửa trực tiếp .claude/settings.json rồi commit.
  2. Trong .claude/settings.local.json của project.
  3. Trong ~/.claude/settings.json.
  4. Trong .mcp.json.
Đáp án B. Project local cao hơn shared project trong precedence và không bị commit, nên chỉ phiên của Lan thay đổi. A sai: commit sẽ đổi model cho cả nhóm. C sai: user settings nằm dưới shared project, nên giá trị của nhóm vẫn thắng trong project này. D sai: .mcp.json chỉ chứa cấu hình MCP server.
Một file settings có "allow": ["Bash(aws s3 ls)"] và "deny": ["Bash(aws *)"]. Những phát biểu nào đúng? (Chọn 2)
  1. Lệnh aws s3 ls bị chặn vì deny được xét trước allow.
  2. Lệnh aws s3 ls được chạy vì allow rule cụ thể hơn.
  3. Claude Code báo lỗi cú pháp vì hai rule mâu thuẫn.
  4. Muốn cho phép aws s3 ls thì phải thu hẹp hoặc bỏ deny rule Bash(aws *); không thể thêm allow để tạo ngoại lệ.
  5. Deny rule chỉ có hiệu lực nếu đặt trong managed settings.
Đáp án A, D. Rules được đánh giá deny → ask → allow, độ cụ thể không làm thay đổi thứ tự. Tài liệu nói rõ allow rule không khoét được ngoại lệ trong deny rule. B sai: độ cụ thể không quan trọng. C sai: hai rule hoàn toàn hợp lệ, chỉ là deny thắng. E sai: deny rule có hiệu lực ở mọi scope, và deny ở bất kỳ scope nào cũng thắng allow ở scope khác.
Minh viết PreToolUse hook để chặn rm -rf: 
if echo "$CMD" | grep -q 'rm -rf'; then
  echo "Không được xóa đệ quy" >&2
  exit 1
fi
Khi thử, lệnh vẫn chạy. Vì sao?
  1. PreToolUse không chặn được tool call, phải dùng PostToolUse.
  2. Thông điệp phải in ra stdout chứ không phải stderr.
  3. Exit code 1 là lỗi không chặn; muốn chặn phải dùng exit 2 (hoặc JSON permissionDecision: "deny").
  4. Hook chỉ chạy khi permission mode là bypassPermissions.
Đáp án C. Theo Hooks reference, chỉ exit 2 là lỗi chặn. Mọi exit code khác 0 và 2 là lỗi không chặn, hành động vẫn tiếp tục, và tài liệu ghi rõ "Exit 1 is not a block". A sai: PreToolUse chính là sự kiện chặn được. PostToolUse chạy sau khi tool đã chạy. B sai: với exit 2, lý do được đọc từ stderr. D sai: hook chạy ở mọi mode.
Đội muốn mọi file Claude sửa bằng Edit/Write đều được chạy Prettier, không phụ thuộc việc Claude có nhớ hay không. Cách nào phù hợp nhất?
  1. Thêm dòng "Luôn chạy Prettier sau khi sửa" vào CLAUDE.md.
  2. Thêm Bash(npx prettier *) vào permissions.allow.
  3. Hook PreToolUse với matcher Bash.
  4. Hook PostToolUse với matcher Edit|Write chạy npx prettier --write trên tool_input.file_path.
Đáp án D. Đây đúng là ví dụ trong tài liệu hooks. PostToolUse chạy sau khi tool thành công, matcher lọc đúng các tool sửa file, và hành động luôn xảy ra (tất định). A sai: CLAUDE.md chỉ là hướng dẫn, model có thể quên. B sai: allow chỉ cho phép chạy mà không hỏi, không bắt buộc Claude chạy. C sai: chạy trước tool và chỉ khi gọi Bash, không phải sau khi sửa file.
Bạn đọc file .mcp.json trong một repo: 
{
  "mcpServers": {
    "tracker": {
      "type": "http",
      "url": "https://tracker.example.com/mcp",
      "headers": { "Authorization": "Bearer ${ANTHROPIC_API_KEY}" }
    }
  }
}
Khi Claude Code kết nối, header Authorization sẽ chứa gì?
  1. Bearer kèm chuỗi rỗng, vì biến credential như ANTHROPIC_API_KEY trong url/headers của remote server được mở rộng thành rỗng.
  2. API key Anthropic thật của bạn.
  3. Chuỗi nguyên văn ${ANTHROPIC_API_KEY}, vì .mcp.json không hỗ trợ mở rộng biến.
  4. Claude Code từ chối nạp file vì thiếu trường command.
Đáp án A. Tài liệu MCP nêu rõ: trong url và headers của remote server, các biến credential như ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN mở rộng thành rỗng. Cơ chế này ngăn một project gửi credential của bạn tới server do nó chỉ định. Muốn truyền thì copy sang biến có tên riêng. B sai vì cơ chế bảo vệ trên. C sai: .mcp.json hỗ trợ ${VAR} và ${VAR:-default}. Chuỗi nguyên văn chỉ giữ lại khi biến không được đặt và không có default. D sai: server type: "http" dùng url, không cần command.
Cả nhóm 8 người cần dùng chung một MCP server nội bộ, và cấu hình phải nằm trong git. Lệnh nào đúng?
  1. claude mcp add --transport http internal https://mcp.corp.example/mcp
  2. claude mcp add --transport http --scope user internal https://mcp.corp.example/mcp
  3. claude mcp add --transport http --scope project internal https://mcp.corp.example/mcp
  4. claude mcp serve --scope project internal
Đáp án C. Scope project ghi vào .mcp.json ở gốc project, có thể commit để chia sẻ. A sai: không ghi scope thì mặc định là local, lưu trong ~/.claude.json, chỉ máy bạn có. B sai: scope user cũng lưu trong ~/.claude.json, chỉ dành cho cá nhân. D sai: claude mcp serve biến Claude Code thành MCP server, không dùng để thêm server.
Những phát biểu nào đúng về quan hệ giữa PreToolUse hook và permission rules? (Chọn 2)
  1. Hook trả permissionDecision: "allow" sẽ vượt qua một deny rule khớp.
  2. Một ask rule khớp vẫn hỏi người dùng, kể cả khi hook đã trả "allow".
  3. Hook chỉ chạy sau khi permission rules đã cho phép call.
  4. Hook lỗi hoặc timeout luôn chặn tool call (fail-closed).
  5. Hook exit 2 chặn được cả tool call mà một allow rule cho phép.
Đáp án B, E. Theo Configure permissions, quyết định của hook không vượt qua deny và ask rule. Còn hook exit 2 dừng call trước khi rules được xét, nên chặn được cả call mà allow rule cho phép. A sai: deny vẫn thắng. C sai: hook chặn chạy trước khi rules được xét. D sai: mặc định là fail-open, chỉ chặn khi đặt onFailure: "block".
Bạn clone một repo mã nguồn mở lạ để sửa bug bằng Claude Code. Repo có .claude/settings.json khai báo hooks và có .mcp.json. Việc nào an toàn nhất trước khi để Claude làm việc?
  1. Chạy ngay với --permission-mode bypassPermissions cho nhanh.
  2. Chạy claude -p để không bị hỏi trust.
  3. Bấm trust thư mục và duyệt mọi server trong .mcp.json, vì Anthropic đã kiểm toán bảo mật các MCP server.
  4. Đọc .claude/settings.json (hooks, permissions) và .mcp.json trước khi trust; với repo không tin cậy, chạy trong dev container hoặc VM.
Đáp án D. Hooks chạy với quyền của bạn, và MCP server có thể là nguồn prompt injection. Tài liệu Security khuyên xem kỹ cấu hình, dùng VM hoặc dev container cho nội dung không tin cậy. A sai: bỏ mọi lời hỏi trên một repo lạ là rủi ro cao nhất. B sai: phiên -p không hiện trust prompt, và server trong .mcp.json được nạp không hỏi, nên còn nguy hiểm hơn. C sai: Anthropic không kiểm toán bảo mật MCP server.
Một hook trả về JSON sau: 
{
  "hookSpecificOutput": {
    "hookEventName": "PostToolUse",
    "additionalContext": "This file is generated. Edit src/schema.ts and run `bun generate` instead."
  }
}
Tác dụng là gì?
  1. Chèn đoạn text vào ngữ cảnh của Claude (dạng system reminder) để Claude biết cần sửa file nguồn thay vì file sinh ra.
  2. Hoàn tác (undo) lần sửa file vừa rồi.
  3. Dừng toàn bộ phiên Claude Code.
  4. Hiển thị cảnh báo cho người dùng nhưng Claude không thấy.
Đáp án A. additionalContext trong hookSpecificOutput chèn text vào ngữ cảnh của Claude như một system reminder. Đây là ví dụ lấy nguyên từ Hooks reference. B sai: PostToolUse chạy khi tool đã xong, hook không tự undo. C sai: dừng phiên cần continue: false. D sai: cảnh báo cho người dùng là systemMessage.
Công ty muốn đảm bảo nhân viên không thể dùng hook tự viết trong repo hay máy cá nhân, mà chỉ dùng hook do bộ phận bảo mật triển khai. Cấu hình nào phù hợp?
  1. Đặt disableAllHooks: true trong .claude/settings.json của từng repo.
  2. Đặt allowManagedHooksOnly trong managed settings và triển khai hook qua managed settings.
  3. Thêm deny rule Bash trong user settings của mỗi người.
  4. Yêu cầu nhân viên ghi cam kết trong CLAUDE.md.
Đáp án B. allowManagedHooksOnly trong managed settings chặn hook từ user, project, local và plugin. Managed settings đứng đầu precedence, người dùng không ghi đè được. A sai: người dùng có thể sửa file trong repo, và disableAllHooks ở tầng thấp không tắt được hook managed (cũng không ngăn hook ở user settings). C sai: deny Bash làm mất công cụ cần thiết và không liên quan tới hooks. D sai: CLAUDE.md không có tính cưỡng chế.
