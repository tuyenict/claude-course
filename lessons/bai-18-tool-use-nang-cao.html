Sau bài này bạn sẽ

  • Tự viết được agentic loop nhiều lượt: chạy tool, gửi tool_result, lặp lại cho tới khi stop_reason khác tool_use.
  • Khai báo nhiều tool trong một request, xử lý parallel tool use và trả kết quả đúng định dạng để Claude tiếp tục gọi song song.
  • Chọn đúng giá trị tool_choice (auto, any, tool, none), biết model nào không hỗ trợ ép gọi tool và cách dùng disable_parallel_tool_use.
  • Báo lỗi tool cho Claude bằng is_error với thông điệp hướng dẫn, và giới hạn số lần thử lại.
  • Bật fine-grained tool streaming bằng eager_input_streaming và xử lý JSON chưa hoàn chỉnh.
  • Viết tool description và thiết kế tool theo hướng dẫn "Writing effective tools for agents" của Anthropic.

Bài 17 dừng ở một lượt gọi tool: Claude trả về khối tool_use, ứng dụng chạy tool rồi gửi lại tool_result. Ứng dụng thật thường phức tạp hơn. 🔁Agentic loop: tool use nhiều lượt

Khi gặp câu hỏi cần nhiều bước, Claude ít khi xong việc trong một lần gọi tool. Ví dụ: "Thời tiết ở thành phố có văn phòng chính của khách hàng ACME thế nào?". Claude phải tra địa chỉ văn phòng trước, rồi mới hỏi được thời tiết. Mỗi bước là một vòng request/response. Vòng lặp lặp lại các bước đó gọi là agentic loop.

5 bước xử lý một response có tool_use

Trang Handle tool calls mô tả quy trình cho client tools như sau:

  1. Bước 1 – Với mỗi khối tool_use, chạy tool có tên trong name với tham số trong input.
  2. Bước 2 – Tạo request mới: giữ toàn bộ message trước đó, thêm nguyên vẹn content của response vừa nhận vào một message assistant.
  3. Bước 3 – Thêm một message user chứa một khối tool_result cho mỗi khối tool_use, kể cả tool bị lỗi.
  4. Bước 4 – Gửi request với cùng mảng tools như request đầu. Claude dùng kết quả tool để tiếp tục.
  5. Bước 5 – Nếu response tiếp theo vẫn có stop_reason là tool_use, lặp lại. Với giá trị khác (vd end_turn, max_tokens), xử lý theo bảng stop reason.
Ví dụ đời thường

Claude giống một trưởng nhóm ngồi trong phòng kín, chỉ liên lạc qua giấy. Mỗi lần cần số liệu, anh ấy đưa ra một tờ phiếu yêu cầu (tool_use). Bạn là người chạy việc: mang phiếu đi lấy số liệu và đem về kết quả (tool_result). Trưởng nhóm có thể đưa ra tờ phiếu thứ hai, thứ ba. Khi anh ấy đưa ra bản báo cáo cuối cùng thay vì phiếu yêu cầu, vòng lặp kết thúc.

Code mẫu: agentic loop viết tay (Python)

# agent_loop.py – vòng lặp tool use nhiều lượt, viết tay
import json
import anthropic

client = anthropic.Anthropic()  # đọc ANTHROPIC_API_KEY từ biến môi trường, không hard-code key

tools = [
    {
        "name": "crm_get_customer_office",
        "description": ("Trả về thành phố đặt văn phòng chính của một khách hàng trong CRM. "
                        "Dùng khi người dùng hỏi về địa điểm của một khách hàng theo tên công ty. "
                        "Không trả về thông tin liên hệ cá nhân."),
        "input_schema": {
            "type": "object",
            "properties": {"company": {"type": "string", "description": "Tên công ty, vd ACME"}},
            "required": ["company"],
        },
    },
    {
        "name": "weather_get_current",
        "description": ("Lấy thời tiết hiện tại của một thành phố. Trả về nhiệt độ (độ C) và mô tả ngắn. "
                        "Dùng khi cần thời tiết hiện tại, không dùng cho dự báo nhiều ngày."),
        "input_schema": {
            "type": "object",
            "properties": {"city": {"type": "string", "description": "Tên thành phố, vd Hanoi"}},
            "required": ["city"],
        },
    },
]

def run_tool(name, tool_input):
    # Ứng dụng thật sẽ gọi CRM / API thời tiết; ở đây giả lập
    if name == "crm_get_customer_office":
        return json.dumps({"company": tool_input["company"], "city": "Da Nang"})
    if name == "weather_get_current":
        return json.dumps({"city": tool_input["city"], "temp_c": 27, "summary": "nắng nhẹ"})
    raise ValueError(f"Tool không tồn tại: {name}")

messages = [{"role": "user", "content": "Thời tiết ở thành phố có văn phòng chính của ACME thế nào?"}]
MAX_TURNS = 10  # chặn vòng lặp vô hạn

for turn in range(MAX_TURNS):
    response = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=1024,
        tools=tools,              # Bước 4: luôn gửi cùng mảng tools
        messages=messages,
    )
    # Bước 2: thêm NGUYÊN VẸN content của assistant (gồm cả text và tool_use)
    messages.append({"role": "assistant", "content": response.content})

    if response.stop_reason != "tool_use":
        break                     # Bước 5: end_turn, max_tokens... → thoát vòng lặp

    tool_results = []
    for block in response.content:
        if block.type != "tool_use":
            continue
        try:
            result = run_tool(block.name, block.input)          # Bước 1
            tool_results.append({"type": "tool_result", "tool_use_id": block.id, "content": result})
        except Exception as e:
            tool_results.append({"type": "tool_result", "tool_use_id": block.id,
                                 "content": f"Lỗi: {e}", "is_error": True})
    # Bước 3: MỘT user message chứa mọi tool_result
    messages.append({"role": "user", "content": tool_results})

print(response.content[-1].text if response.content and response.content[-1].type == "text" else response.stop_reason)

Với câu hỏi trên, cuộc hội thoại diễn ra qua hai vòng tool rồi mới tới câu trả lời:

userThời tiết ở thành phố có văn phòng chính của ACME thế nào?
assistantMình sẽ tra văn phòng của ACME trước. [tool_use: crm_get_customer_office {"company": "ACME"}] · stop_reason: tool_use

assistant[tool_use: weather_get_current {"city": "Da Nang"}] · stop_reason: tool_use

assistantVăn phòng chính của ACME ở Đà Nẵng. Hiện tại ở đó khoảng 27°C, trời nắng nhẹ. · stop_reason: end_turn
Lỗi thường gặp
  • Chỉ lưu phần text của assistant và bỏ khối tool_use. Khi đó tool_result ở message sau không có khối tool_use tương ứng. Hãy append nguyên response.content.
  • Chèn message khác giữa message có tool_use và message chứa tool_result. Tài liệu yêu cầu tool_result phải nằm ngay sau tool_use tương ứng. Nếu sai sẽ gặp lỗi kiểu "tool_use ids were found without tool_result blocks immediately after".
  • Đặt text trước tool_result trong user message: lỗi 400. Các khối tool_result phải đứng đầu mảng content, text (nếu có) đặt sau.
  • Không giới hạn số vòng lặp. Một tool lỗi liên tục có thể khiến Claude thử lại mãi. Luôn đặt MAX_TURNS.
Mẹo thực chiến (Pro Tip)

Cần chèn bước con người phê duyệt (human-in-the-loop), log riêng, hoặc chỉ chạy tool khi đủ điều kiện ⇒ viết vòng lặp tay như trên. Chỉ cần chạy tool và nhận câu trả lời cuối ⇒ dùng Tool runner của SDK (phần 8). Trang Tool runner cũng đưa ra khuyến nghị này.

API dựng system prompt từ tool definitions

Khi request có tools, API tự dựng một system prompt đặc biệt. Prompt này gồm hướng dẫn định dạng, toàn bộ tool definitions ở dạng JSON Schema, system prompt của bạn và cấu hình tool. Vì vậy mọi tool definition đều tốn input token ở mỗi request. Khai báo quá nhiều tool vừa tốn tiền vừa làm Claude khó chọn hơn.

Claude chọn tool như thế nào?

Với tool_choice mặc định (auto), Claude đọc câu hỏi, đọc name + description của từng tool rồi quyết định: trả lời thẳng, gọi một tool, hay gọi nhiều tool. Trước khi gọi tool, Claude thường viết một câu ngắn giải thích việc sắp làm, ví dụ:

{
  "role": "assistant",
  "content": [
    { "type": "text", "text": "I'll help you check the current weather and time in San Francisco." },

Tài liệu lưu ý: câu dẫn này có thể được diễn đạt theo nhiều cách khác nhau. Code của bạn nên xử lý nó như mọi đoạn text khác do Claude sinh ra, không phụ thuộc vào câu chữ hay định dạng cụ thể.

⚡Parallel tool use: gọi nhiều tool trong một lượt

Mặc định Claude có thể gọi nhiều tool trong một response. Theo tài liệu, Claude 4 và các model mới hơn tự gọi song song khi request có lợi từ nhiều tool. Ví dụ câu "Thời tiết ở SF và NYC thế nào, và bây giờ ở đó mấy giờ?" có thể sinh ra 4 khối tool_use (2 get_weather + 2 get_time) trong cùng một assistant message, với stop_reason: "tool_use".

Ai quyết định chạy song song hay tuần tự?

Bạn quyết định. API không quy định thứ tự thực thi. Bạn có thể chạy đồng thời (asyncio.gather, Promise.all), chạy lần lượt theo thứ tự xuất hiện, hoặc kết hợp cả hai. Tài liệu gợi ý:

  • Thao tác độc lập, chỉ đọc (read-only) → thường chạy song song an toàn, giảm độ trễ.
  • Tool có tác dụng phụ, dùng trạng thái chung, hoặc cần đúng thứ tự → nên chạy tuần tự.

Định dạng kết quả để Claude tiếp tục gọi song song

Lỗi phổ biến nhất khiến Claude "ngừng" gọi song song là định dạng lịch sử hội thoại sai. Tài liệu viết: định dạng sai sẽ "dạy" Claude tránh gọi song song.

Nếu bạn chạy tuần tự và một lời gọi trước đó lỗi nên quyết định không chạy lời gọi sau, vẫn phải trả tool_result cho lời gọi bị bỏ qua, kèm is_error: true và giải thích ngắn:

{
  "type": "tool_result",
  "tool_use_id": "toolu_02",
  "is_error": true,
  "content": "Not executed: the preceding write_file call failed."
}

Code mẫu: chạy song song bằng asyncio

# parallel_tools.py – chạy các tool_use độc lập đồng thời
import asyncio
import anthropic

client = anthropic.AsyncAnthropic()  # key lấy từ ANTHROPIC_API_KEY

async def run_tool_async(block):
    try:
        if block.name == "get_weather":
            await asyncio.sleep(0.2)                  # giả lập gọi API
            content = f"{block.input['location']}: 20°C"
        elif block.name == "get_time":
            content = f"{block.input['timezone']}: 14:30"
        else:
            raise ValueError(f"Unknown tool {block.name}")
        return {"type": "tool_result", "tool_use_id": block.id, "content": content}
    except Exception as e:
        return {"type": "tool_result", "tool_use_id": block.id,
                "content": str(e), "is_error": True}

async def handle(response, messages):
    calls = [b for b in response.content if b.type == "tool_use"]
    results = await asyncio.gather(*(run_tool_async(b) for b in calls))
    messages.append({"role": "assistant", "content": response.content})
    messages.append({"role": "user", "content": list(results)})  # 1 message, đủ N kết quả

Tăng khả năng gọi song song bằng prompt

Với Claude 4 trở lên, tài liệu đề xuất thêm vào system prompt câu sau (giữ nguyên tiếng Anh như tài liệu):

For maximum efficiency, whenever you need to perform multiple independent operations,
invoke all relevant tools simultaneously rather than sequentially.

Nếu chưa đủ, dùng phiên bản mạnh hơn bọc trong thẻ <use_parallel_tool_calls> (ví dụ: "when reading 3 files, run 3 tool calls in parallel…"). Bạn cũng có thể nói rõ trong user message, ví dụ "Check the weather in Paris and London simultaneously.". Để giảm việc Claude gom các lời gọi phụ thuộc nhau vào cùng một lượt, thêm câu "Only batch tool calls that are independent of each other.".

Đo mức độ gọi song song

Tài liệu gợi ý đo số tool trung bình trên mỗi message có tool_use: lấy tổng số khối tool_use chia cho số message có tool_use. Nếu parallel tool use hoạt động, giá trị này nên lớn hơn 1.0. Lưu ý thêm: Claude Fable 5.1 có thể gọi song song ít hơn các model trước trong vòng lặp agent dài. Trang Prompting Claude Fable 5.1 có câu lệnh hướng dẫn gom lời gọi cho trường hợp này.

Mẹo thực chiến (Pro Tip)

Log cho thấy Claude gần như luôn gọi từng tool một dù các thao tác độc lập ⇒ kiểm tra trước hết xem bạn có đang trả mỗi tool_result trong một user message riêng không. Đây là nguyên nhân số 1 theo mục Troubleshooting. Sau đó mới tăng cường system prompt.

    messages=[{"role": "user", "content": "What's the weather like in San Francisco?"}],
)
# response.content[0] là tool_use, không có text dẫn trước, không có khối thinking

Muốn Claude vừa giải thích vừa gọi tool?

Khi tool_choice là any hoặc tool, API buộc response bắt đầu bằng lời gọi tool. Claude sẽ không viết câu giải thích trước tool_use, kể cả khi bạn yêu cầu. Tài liệu cho biết điều này không làm giảm chất lượng. Nếu bạn vẫn muốn có lời giải thích, dùng auto và nói rõ trong user message, ví dụ: What's the weather like in London? Use the get_weather tool in your response.

disable_parallel_tool_use

Parallel tool use bật mặc định. Để tắt, đặt disable_parallel_tool_use: true bên trong object tool_choice. Đây không phải tham số cấp cao nhất. Tác dụng phụ thuộc vào type:

1️⃣auto + disable

  • Claude gọi tối đa một tool mỗi response.
  • Vẫn có thể trả lời bằng text, không gọi tool nào.
  • {"type": "auto", "disable_parallel_tool_use": true}

🎯any/tool + disable

  • Claude gọi đúng một tool.
  • Chỉ dùng được trên model hỗ trợ ép gọi tool (không gồm Opus 5.5, Sonnet 5.5, Fable 5.2/5.1, Mythos 5.2/5.1).
  • {"type": "any", "disable_parallel_tool_use": true}
Lưu ý về prompt caching

Khi dùng prompt caching, đổi giá trị tool_choice giữa các request sẽ làm mất cache của các khối message. Tool definitions và system prompt vẫn được cache, nhưng phần nội dung message phải xử lý lại. Vì vậy nên giữ tool_choice ổn định trong một phiên hội thoại.

Mẹo thực chiến (Pro Tip)

Cần chắc chắn output đi qua tool record_summary với JSON đúng schema trên Claude Opus 5.5 ⇒ không dùng tool_choice: tool (lỗi 400). Hãy dùng auto + strict: true + chỉ dẫn rõ trong prompt, hoặc dùng structured outputs. Trên model hỗ trợ ép gọi, tổ hợp tool_choice: {"type": "any"} + strict: true đảm bảo vừa có lời gọi tool, vừa đúng schema.

🚨Xử lý lỗi tool với is_error

Mỗi khối tool_result có các trường: type: "tool_result", tool_use_id (id của khối tool_use được trả lời), content (tùy chọn: chuỗi, hoặc danh sách khối text, image, document, search_result) và is_error (tùy chọn). Khi tool thất bại hoặc lời gọi không hợp lệ, đặt is_error: true. Claude có thể gọi lại tool với một khối tool_use mới, hoặc giải thích cho người dùng.

Mẹo thực chiến (Pro Tip)

Đừng trả lỗi chung chung kiểu "failed". Hãy viết thông điệp lỗi có hướng dẫn: chuyện gì xảy ra và Claude nên thử gì tiếp (vd "Rate limit exceeded. Retry after 60 seconds.", "Không tìm thấy khách hàng 'ACME Corp'. Hãy thử tìm bằng tên ngắn hơn, vd 'ACME'."). Bài viết "Writing effective tools" cũng khuyên tránh trả mã lỗi khó hiểu hay stack trace.

Lỗi thường gặp
  • Bỏ qua tool lỗi, không gửi tool_result cho nó. Bước 3 yêu cầu mỗi tool_use phải có một tool_result, kể cả khi lỗi.
  • Trả nguyên stack trace hoặc thông tin nội bộ (đường dẫn server, chuỗi kết nối DB) vào content. Cách này vừa tốn token vừa lộ thông tin hệ thống. Theo nguyên tắc của IPA「安全なウェブサイトの作り方」, chỉ nên trả thông điệp đủ để xử lý; chi tiết thì ghi vào log phía server.
  • Không giới hạn số lần thử lại. Tài liệu nhắc rằng Claude có thể gọi lại tool sau lỗi, nên vòng lặp cần giới hạn retry.
Bảo mật: tool_result là dữ liệu không tin cậy

Kết quả tool thường chứa nội dung bạn không kiểm soát: trang web, email đến, file người dùng tải lên, API bên thứ ba. Kẻ tấn công có thể nhúng chỉ thị vào đó để điều khiển Claude (indirect prompt injection). Tài liệu khuyên giữ nội dung không tin cậy bên trong khối tool_result, không đưa vào system hay text của user. Kết hợp với nguyên tắc least privilege (quyền tối thiểu): tool có tác dụng phụ (xóa, chuyển tiền, gửi email) nên cần xác nhận của con người.

📡Fine-grained tool streaming

Khi stream một response có tool use, mặc định API buffer và kiểm tra từng giá trị tham số rồi mới stream về. Với tham số lớn (một tài liệu dài, một khối code), bạn phải chờ Claude sinh xong cả tham số mới thấy ký tự đầu tiên. Fine-grained tool streaming bỏ bước buffer đó. Input của tool đến client ngay khi Claude sinh ra, qua cùng các sự kiện streaming như tool use thông thường. Tính năng này ở trạng thái stable, có trên mọi model và đủ điều kiện ZDR (trừ Covered Models) theo tài liệu.

eager_input_streamingtrường đặt true trên từng tool cần stream chi tiết, kèm stream: true
input: {}placeholder trong content_block_start; input thật đến qua input_json_delta
INVALID_JSONkhóa gợi ý để bọc input không parse được, trả về với is_error: true

Cách bật

  • Đặt "eager_input_streaming": true trên mỗi tool do bạn định nghĩa cần stream chi tiết, và bật streaming cho request.
  • Bỏ trống trường này ⇒ streaming buffer như cũ.
  • Header beta cũ fine-grained-tool-streaming-2025-05-14 bật tính năng cho các tool không đặt trường. Trường theo từng tool đã thay thế header này. Đặt false rõ ràng thì tool đó vẫn buffer dù request có gửi header.
  • Header không được dùng chung với toolset computer use hoặc browser use: API từ chối request. Hãy bỏ header và dùng eager_input_streaming.

Quy tắc ghép input (accumulation contract)

  1. content_block_start với type: "tool_use" → khởi tạo chuỗi rỗng. Trường input: {} ở đây chỉ là placeholder.
  2. content_block_delta với type: "input_json_delta" → nối event.delta.partial_json vào chuỗi.
  3. content_block_stop → parse chuỗi đã ghép, bọc trong try/except. Đồng thời kiểm tra stop_reason: nếu là max_tokens, tham số có thể bị cắt giữa chừng.
# fine_grained.py – bật eager_input_streaming và ghép input an toàn
import json
import anthropic

client = anthropic.Anthropic()
tool_inputs: dict[int, str] = {}   # index khối → chuỗi JSON đã ghép

with client.messages.stream(
    model="claude-opus-5-5",
    max_tokens=1024,
    tools=[{
        "name": "get_weather",
        "description": "Get current weather for a city",
        "eager_input_streaming": True,        # bật fine-grained cho tool này
        "input_schema": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]},
    }],
    messages=[{"role": "user", "content": "Weather in Paris?"}],
) as stream:
    for event in stream:
        match event.type:
            case "content_block_start" if event.content_block.type == "tool_use":
                tool_inputs[event.index] = ""
            case "content_block_delta" if event.delta.type == "input_json_delta":
                tool_inputs[event.index] += event.delta.partial_json
            case "content_block_stop" if event.index in tool_inputs:
                raw = tool_inputs[event.index]
                try:
                    print("Tool input:", json.loads(raw))
                except json.JSONDecodeError:
                    print("Invalid tool input:", raw)   # không chạy tool, báo lại cho Claude

Trả JSON không hợp lệ về cho Claude

Nếu input ghép được không parse được, bạn không thể chạy tool. Hãy báo lại cho Claude bằng một tool_result có is_error: true. Bọc chuỗi gốc trong object có một khóa INVALID_JSON để Claude hiểu rõ chuyện gì xảy ra, đồng thời giữ lại input gốc để debug:

{
  "type": "tool_result",
  "tool_use_id": "toolu_01A09q90qw90lq917835lq9",
  "is_error": true,
  "content": "{\"INVALID_JSON\": \"<the unparseable input you received>\"}"
}
Lưu ý

Dựng wrapper bằng thư viện JSON (vd json.dumps({"INVALID_JSON": raw})), không nối chuỗi thủ công. Như vậy dấu nháy và ký tự đặc biệt trong input lỗi được escape đúng. Đây cũng là nguyên tắc chung của IPA「セキュア・プログラミング講座」: không tự ghép chuỗi khi tạo dữ liệu có cấu trúc.

Mẹo thực chiến (Pro Tip)

Ứng dụng soạn thảo cần hiển thị nội dung file mà Claude đang viết qua tool make_file theo thời gian thực ⇒ bật eager_input_streaming: true cho riêng tool đó. Tool nhỏ, cần JSON đã kiểm tra ⇒ giữ streaming buffer mặc định.

🤖Tool runner (SDK): để SDK lo vòng lặp

Tool runner là helper của SDK (đang ở trạng thái beta), tự động hóa vòng lặp ở phần 1: chạy tool khi Claude gọi, xử lý chu trình request/response, quản lý trạng thái hội thoại, và cung cấp kiểm tra kiểu (type safety). Tool runner có trong SDK Python, TypeScript, C#, Go, Java, PHP và Ruby.

# tool_runner_demo.py – Python SDK, @beta_tool suy ra JSON schema từ type hint + docstring
import json
from anthropic import Anthropic, beta_tool

client = Anthropic()

@beta_tool
def get_weather(location: str, unit: str = "fahrenheit") -> str:
    """Get the current weather in a given location.

    Args:
        location: The city and state, e.g. San Francisco, CA
        unit: Temperature unit, either 'celsius' or 'fahrenheit'
    """
    return json.dumps({"temperature": "20°C", "condition": "Sunny"})

@beta_tool
def calculate_sum(a: int, b: int) -> str:
    """Add two numbers together.

    Args:
        a: First number
        b: Second number
    """
    return str(a + b)

runner = client.beta.messages.tool_runner(
    model="claude-opus-5-5",
    max_tokens=1024,
    tools=[get_weather, calculate_sum],
    max_iterations=10,              # chặn vòng lặp quá dài
    messages=[{"role": "user", "content": "What's the weather like in Paris? Also, what's 15 + 27?"}],
)
final_message = runner.until_done()  # hoặc: for message in runner: print(message)
print(final_message.content)
  • Lặp: runner là iterable, trả về từng message của Claude; dừng khi Claude trả message không có tool use, hoặc khi chạm max_iterations (nếu đặt). Có thể break bất kỳ lúc nào.
  • Lỗi: khi tool ném exception, runner bắt lỗi và gửi cho Claude một tool_result với is_error: true. Nội dung là thông điệp của exception (Python: kiểu + thông điệp), không gồm toàn bộ stack trace.
  • Async: với client async, dùng @beta_async_tool và async def.
  • Kết quả tool: trả về chuỗi (thành một khối text) hoặc các khối text/image/document. Dữ liệu có cấu trúc thì encode thành chuỗi trước (vd json.dumps).

🧪Thực hành

Chuẩn bị: Python 3.10+, pip install anthropic, đặt biến môi trường ANTHROPIC_API_KEY (không ghi key vào code hay commit lên Git).

  1. Bài tập 1 – Agentic loop hai bước. Chạy agent_loop.py ở phần 1. In ra stop_reason và tên tool của từng vòng.
    Kết quả mong đợi: ít nhất 2 vòng có stop_reason: tool_use (crm_get_customer_office rồi weather_get_current), vòng cuối là end_turn với câu trả lời nhắc tới Đà Nẵng và 27°C. Thử xóa dòng messages.append({"role": "assistant", ...}) để thấy API báo lỗi vì tool_result không có tool_use tương ứng.
  2. Bài tập 2 – Parallel tool use và cách đo. Khai báo hai tool get_weather và get_time, hỏi "What's the weather in SF and NYC, and what time is it there?". Chạy các tool_use bằng asyncio.gather và trả kết quả trong một user message. Tính "số tool trung bình trên mỗi message có tool_use".
    Kết quả mong đợi: response đầu chứa nhiều khối tool_use; giá trị trung bình > 1.0. Sau đó thử thêm tool_choice={"type": "auto", "disable_parallel_tool_use": True} và kiểm tra: mỗi response chỉ còn tối đa 1 tool_use, số vòng tăng lên.
  3. Bài tập 3 – tool_choice và model. Gửi request với tool_choice={"type": "tool", "name": "get_weather"} lần lượt tới claude-haiku-5-5 và claude-opus-5-5.
    Kết quả mong đợi: Haiku 5.5 trả về content[0] là tool_use, không có text dẫn trước. Opus 5.5 trả lỗi 400 (forced tool use not supported). Viết lại request cho Opus 5.5 bằng auto + strict: true + câu "Use the get_weather tool in your response.".
  4. Bài tập 4 – is_error và fine-grained streaming. Sửa run_tool để weather_get_current ném lỗi trong lần gọi đầu, thành công ở lần gọi thứ hai. Trả lỗi với thông điệp có hướng dẫn và is_error: true. Sau đó bật eager_input_streaming: True cho tool make_file và in partial_json khi yêu cầu Claude viết một bài thơ dài vào poem.txt.
    Kết quả mong đợi: Claude tự gọi lại tool sau lỗi (vòng lặp vẫn kết thúc nhờ MAX_TURNS). Ở phần streaming, các fragment JSON hiện ra dần trên màn hình trước khi tool input hoàn tất. Nếu parse lỗi, bạn tạo được wrapper {"INVALID_JSON": ...} bằng json.dumps.

Tóm tắt ghi nhớ

Key takeaways
  • Agentic loop: append nguyên response.content (assistant), trả mỗi tool_use một tool_result trong một user message, gửi cùng tools, lặp tới khi stop_reason ≠ tool_use, luôn đặt giới hạn số vòng.
  • tool_result phải nằm ngay sau tool_use và đứng đầu mảng content; text đặt sau.
  • Parallel tool use bật mặc định. Bạn chọn chạy song song hay tuần tự. Mọi tool_result phải nằm trong một user message, nếu không Claude sẽ "học" cách ngừng gọi song song.
  • tool_choice: auto (mặc định khi có tools), any, tool, none (mặc định khi không có tools). any/tool không có text dẫn trước, bỏ qua thinking, lỗi khi bật manual extended thinking, và trả 400 trên Opus 5.5, Sonnet 5.5, Fable 5.2/5.1, Mythos 5.2/5.1.
  • disable_parallel_tool_use nằm trong tool_choice: với auto thì tối đa 1 tool; với any/tool thì đúng 1 tool.
  • is_error: true cho lỗi thực thi, lời gọi không hợp lệ, lời gọi bị bỏ qua. Viết lỗi có hướng dẫn. Server tool lỗi thì không gửi is_error.
  • Fine-grained tool streaming: eager_input_streaming: true trên từng tool + stream. JSON có thể chưa hoàn chỉnh, nên parse trong try/except và trả {"INVALID_JSON": ...} kèm is_error.
  • Description chi tiết (≥ 3–4 câu) là yếu tố quan trọng nhất. Ngoài ra: gom tool, đặt namespace, trả thông tin giá trị, tiết kiệm token, đánh giá bằng eval.
  • Tool runner (beta) tự lo vòng lặp và tự chuyển exception thành is_error. Cần phê duyệt hoặc kiểm soát thì viết vòng lặp tay.

Thuật ngữ (Glossary)

Agentic loop
Vòng lặp agent – lặp gọi API → chạy tool → gửi tool_result cho tới khi stop_reason khác tool_use.
Multiple tools
Nhiều công cụ – khai báo nhiều tool definition trong mảng tools của một request.
Parallel tool use
Gọi công cụ song song – một assistant message chứa nhiều khối tool_use.
tool_choice
Chế độ chọn công cụ – tham số auto / any / tool / none kiểm soát việc gọi tool.
Forced tool use
Ép gọi công cụ – dùng tool_choice any hoặc tool; không hỗ trợ trên một số model mới.
disable_parallel_tool_use
Tắt gọi song song – trường nằm trong tool_choice; auto thì tối đa 1 tool, any/tool thì đúng 1 tool.
tool_result
Khối kết quả công cụ – gồm tool_use_id, content, is_error; đặt trong user message.
is_error
Cờ báo lỗi công cụ – true khi tool thất bại, lời gọi không hợp lệ hoặc bị bỏ qua.
stop_reason: tool_use
Lý do dừng: gọi công cụ – Claude đang chờ kết quả tool từ ứng dụng.
Fine-grained tool streaming
Stream đầu vào tool chi tiết – stream input của tool không qua buffer/kiểm tra JSON phía server.
eager_input_streaming
Bật stream input sớm – trường trên từng tool để bật fine-grained tool streaming.
input_json_delta
Mảnh JSON đầu vào – sự kiện streaming mang chuỗi partial_json cần nối lại.
input_examples
Ví dụ đầu vào – mảng ví dụ input hợp lệ theo schema, giúp Claude dùng tool phức tạp.
Strict tool use
Tool use nghiêm ngặt – strict: true đảm bảo input của tool khớp đúng schema.
Namespacing
Đặt không gian tên – thêm tiền tố dịch vụ vào tên tool (vd github_list_prs).
Tool runner
Bộ chạy công cụ của SDK – helper (beta) tự xử lý agentic loop, lỗi và kiểu dữ liệu.
Indirect prompt injection
Chèn lệnh gián tiếp – chỉ thị độc hại ẩn trong dữ liệu tool trả về (web, email, file…).
response_format (concise/detailed)
Định dạng phản hồi – enum để agent chọn mức chi tiết của kết quả tool, tiết kiệm token.

Câu hỏi luyện tập

Một nhóm xây chatbot hỗ trợ khách hàng. Claude trả về response có stop_reason: "tool_use" với một khối text và một khối tool_use. Lập trình viên chạy tool xong. Bước tiếp theo đúng là gì?
  1. Gửi request mới chỉ gồm một user message chứa tool_result, bỏ lịch sử cũ để tiết kiệm token.
  2. Thêm phần text của assistant vào lịch sử, bỏ khối tool_use, rồi thêm user message chứa tool_result.
  3. Thêm nguyên vẹn content của response vào message assistant, rồi thêm user message chứa tool_result tương ứng, gửi kèm cùng mảng tools.
  4. Thêm message role: "tool" chứa kết quả, giống các API khác.
Đáp án C. Theo Handle tool calls: giữ các message trước, thêm nguyên vẹn content làm message assistant, thêm user message chứa một tool_result cho mỗi tool_use, gửi cùng tools. A sai: bỏ lịch sử thì tool_result không có tool_use tương ứng. B sai: thiếu khối tool_use nên tool_use_id không khớp được. D sai: Claude API không có role tool; tool_result nằm trong message user.
Ứng dụng báo lỗi 400 khi gửi user message sau đây. Nguyên nhân là gì? 
{"role": "user", "content": [
  {"type": "text", "text": "Here are the results:"},
  {"type": "tool_result", "tool_use_id": "toolu_01", "content": "15 degrees"}
]}
  1. Khối text đứng trước tool_result; các khối tool_result phải đứng đầu mảng content.
  2. content của tool_result phải là mảng khối, không được là chuỗi.
  3. Thiếu trường is_error: false bắt buộc.
  4. User message chứa tool_result không được có bất kỳ khối text nào.
Đáp án A. Tài liệu: trong user message chứa tool results, tool_result phải đứng TRƯỚC; text đặt SAU mọi tool result. B sai: content có thể là chuỗi hoặc danh sách khối. C sai: is_error là tùy chọn. D sai: text được phép nếu đặt sau các tool_result (khi lượt assistant chỉ gọi client tools).
Nhóm phát triển thấy Claude gần như không bao giờ gọi song song dù các thao tác hoàn toàn độc lập. Hai cách nào được tài liệu khuyến nghị để khắc phục? (Chọn 2)
  1. Đặt disable_parallel_tool_use: false ở cấp cao nhất của request.
  2. Trả toàn bộ tool_result của một lượt trong một user message, thay vì mỗi kết quả một message.
  3. Chuyển sang tool_choice: {"type": "none"}.
  4. Thêm vào system prompt chỉ dẫn gọi mọi tool liên quan đồng thời khi thao tác độc lập (vd khối <use_parallel_tool_calls>).
  5. Giảm max_tokens để Claude buộc phải gom lời gọi.
Đáp án B, D. Mục Troubleshooting: nguyên nhân phổ biến nhất là định dạng kết quả sai (mỗi kết quả một message); cách thứ hai là tăng cường prompt. A sai: disable_parallel_tool_use không phải tham số cấp cao nhất, và parallel vốn đã bật mặc định. C sai: none cấm gọi tool. E sai: không có cơ chế nào như vậy; max_tokens thấp chỉ làm response bị cắt.
Một kỹ sư dùng claude-opus-5-5 và muốn chắc chắn Claude luôn gọi tool extract_invoice với input đúng schema. Họ đặt tool_choice: {"type": "tool", "name": "extract_invoice"} và nhận lỗi 400. Cách làm phù hợp nhất là gì?
  1. Đổi sang tool_choice: {"type": "any"}.
  2. Bật manual extended thinking (thinking: {type: "enabled"}) rồi giữ nguyên tool_choice.
  3. Thêm header beta fine-grained-tool-streaming-2025-05-14.
  4. Dùng tool_choice: auto kèm strict: true trên tool và chỉ dẫn rõ trong prompt, hoặc dùng structured outputs.
Đáp án D. Theo Define tools, Claude Opus 5.5 (cùng Sonnet 5.5, Fable 5.2/5.1, Mythos 5.2/5.1) trả 400 với any và tool; cách thay thế là auto + strict tool use, hoặc structured outputs. A sai: any cũng bị từ chối trên các model này. B sai: manual extended thinking cũng không hỗ trợ any/tool, và không được chấp nhận trên các model mới. C sai: header đó liên quan tới streaming, không liên quan tới ép gọi tool.
Trên một model hỗ trợ ép gọi tool, request đặt tool_choice: {"type": "auto", "disable_parallel_tool_use": true}. Hành vi nào đúng?
  1. Claude phải gọi đúng một tool.
  2. Claude gọi tối đa một tool trong mỗi response, và vẫn có thể trả lời bằng text mà không gọi tool.
  3. Claude không được gọi tool nào.
  4. Claude gọi song song nhưng ứng dụng phải chạy tuần tự.
Đáp án B. Với auto, disable_parallel_tool_use: true nghĩa là tối đa một tool và Claude vẫn có thể trả lời thuần text. A sai: "đúng một tool" là hành vi khi type là any/tool. C sai: đó là none. D sai: trường này giới hạn số tool_use Claude sinh ra, không liên quan tới cách ứng dụng thực thi.
Agent gọi API đặt phòng họp nhưng hệ thống bên ngoài trả lỗi do vượt rate limit. Cách trả kết quả nào giúp Claude tự xử lý tốt nhất?
  1. tool_result với is_error: true và content "Rate limit exceeded. Retry after 60 seconds."
  2. tool_result với content "failed", không đặt is_error.
  3. Bỏ qua tool_use đó, chỉ gửi user message "Hãy thử lại".
  4. tool_result với is_error: true và toàn bộ stack trace kèm chuỗi kết nối nội bộ để Claude debug.
Đáp án A. Tài liệu khuyên viết thông điệp lỗi có hướng dẫn (chuyện gì xảy ra, nên thử gì tiếp) kèm is_error: true. B sai: "failed" quá chung chung và thiếu cờ lỗi. C sai: mỗi tool_use bắt buộc phải có tool_result; thiếu sẽ gây lỗi. D sai: stack trace tốn token, và lộ thông tin nội bộ là rủi ro bảo mật.
Đọc đoạn code ghép input khi bật fine-grained tool streaming. Đoạn nào cần sửa để tuân thủ khuyến nghị của tài liệu? 
case "content_block_start" if event.content_block.type == "tool_use":
    buf[event.index] = ""
case "content_block_delta" if event.delta.type == "input_json_delta":
    buf[event.index] += event.delta.partial_json
case "content_block_stop" if event.index in buf:
    args = json.loads(buf[event.index])
    run_tool(args)
  1. Phải khởi tạo buf bằng event.content_block.input thay cho chuỗi rỗng.
  2. Phải parse JSON sau mỗi input_json_delta thay vì đợi tới content_block_stop.
  3. json.loads phải được bọc trong try/except; nếu lỗi thì không chạy tool mà trả tool_result có is_error: true (vd wrapper INVALID_JSON).
  4. Phải đổi partial_json thành delta.text.
Đáp án C. Fine-grained streaming không kiểm tra JSON phía server, nên chuỗi ghép được có thể không hợp lệ hoặc bị cắt do max_tokens. Tài liệu yêu cầu "guard the parse" và trả lỗi về cho Claude. A sai: input: {} chỉ là placeholder dạng object; phần cần nối là chuỗi. B sai: fragment lẻ thường chưa phải JSON hoàn chỉnh; tài liệu parse ở content_block_stop. D sai: delta của tool input là input_json_delta với trường partial_json.
Những phát biểu nào đúng về fine-grained tool streaming? (Chọn 2)
  1. Bật bằng "eager_input_streaming": true trên từng tool do người dùng định nghĩa, kèm streaming cho request.
  2. Đảm bảo input luôn là JSON hợp lệ vì server đã kiểm tra trước.
  3. Header beta fine-grained-tool-streaming-2025-05-14 không được dùng chung với toolset computer use hoặc browser use.
  4. Chỉ hoạt động khi tool_choice là any.
  5. Là tính năng beta, chỉ có trên Claude API, không có trên các nền tảng cloud.
Đáp án A, C. A: đúng theo mục "How to use". C: tài liệu nói API từ chối request có cả header và toolset computer/browser use. B sai: chính vì bỏ buffer và kiểm tra nên có thể nhận JSON không hợp lệ. D sai: tài liệu không có ràng buộc này. E sai: trang tài liệu ghi trạng thái stable trên mọi nền tảng được hỗ trợ.
Assistant trả về hai lời gọi write_file (id toolu_01) và run_tests (id toolu_02). Ứng dụng chạy tuần tự; write_file lỗi nên không chạy run_tests. User message tiếp theo nên là gì?
  1. [{"type":"tool_result","tool_use_id":"toolu_01","is_error":true,"content":"Disk full"}] — bỏ qua toolu_02 vì không chạy.
  2. Hai user message riêng, mỗi message một tool_result.
  3. [{"type":"text","text":"write_file lỗi"}, {"type":"tool_result","tool_use_id":"toolu_01",...}]
  4. Một user message chứa hai tool_result: toolu_01 với is_error: true (lý do lỗi) và toolu_02 với is_error: true, content "Not executed: the preceding write_file call failed."
Đáp án D. Trang Parallel tool use: lời gọi bạn chọn không chạy vẫn cần một tool_result với is_error: true và giải thích ngắn, và mọi kết quả nằm trong một user message. A sai: thiếu tool_result cho toolu_02. B sai: tách message làm giảm parallel tool use, và trái quy tắc tool_result phải nằm ngay sau tool_use. C sai: text đứng trước tool_result gây lỗi 400, và vẫn thiếu toolu_02.
Một startup có agent dùng tool list_contacts trả toàn bộ 20.000 liên hệ (kèm UUID, MIME type ảnh đại diện) mỗi lần gọi. Agent chậm và hay nhầm người. Theo "Writing effective tools for agents", cải tiến nào phù hợp nhất?
  1. Giữ nguyên tool, chỉ tăng max_tokens của request.
  2. Thay bằng tool search_contacts có lọc/phân trang, trả các trường giá trị cao (tên, email) và có thể thêm enum response_format (concise/detailed).
  3. Tách thành 20 tool, mỗi tool trả 1.000 liên hệ.
  4. Ép gọi list_contacts bằng tool_choice: tool ở mọi lượt.
Đáp án B. Bài viết lấy chính ví dụ này: search_contacts tốt hơn list_contacts; nên ưu tiên trường có ngữ nghĩa hơn UUID/MIME type; tiết kiệm token bằng lọc, phân trang, response_format. A sai: max_tokens giới hạn output của Claude, không giảm ngữ cảnh do tool trả về. C sai: nhiều tool trùng chức năng làm tăng nhầm lẫn. D sai: ép gọi không giải quyết được việc response quá lớn, và nhiều model mới không hỗ trợ ép gọi.
