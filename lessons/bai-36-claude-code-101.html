Sau bài này bạn sẽ

  • Phân biệt được một AI coding agent như Claude Code với trợ lý chat thông thường.
  • Cài đặt Claude Code trên macOS / Linux / WSL / Windows, đăng nhập và chạy phiên làm việc đầu tiên.
  • Giải thích được agentic loop ba pha: thu thập ngữ cảnh → hành động → kiểm chứng, và vai trò của các built-in tools (Read, Edit, Bash…).
  • Chọn đúng permission mode (default, acceptEdits, plan, auto, dontAsk, bypassPermissions) cho từng tình huống.
  • Dùng Plan mode và quy trình explore → plan → code → commit; làm việc với Claude Code trong VS Code / JetBrains.

💻Claude Code là gì?

Theo tài liệu của Anthropic, Claude Code là một agentic coding tool: nó đọc codebase của bạn, sửa file, chạy lệnh và tích hợp với các công cụ phát triển. Claude Code có mặt ở terminal, IDE, ứng dụng desktop và trình duyệt.

Điểm khác biệt cốt lõi so với một trợ lý chat (như khi bạn dán code vào Claude.ai và hỏi): Claude Code tự đi tìm ngữ cảnh và tự hành động. Bạn không cần chỉ định file nào cần đọc, lệnh nào cần chạy. Khi bạn nói “sửa lỗi xác thực”, Claude Code tìm các file liên quan, đọc nhiều file để hiểu, sửa đồng bộ nhiều chỗ, chạy test để kiểm chứng rồi commit nếu bạn yêu cầu. Tài liệu nhấn mạnh: điều này khác với các trợ lý code nội tuyến (inline) vốn chỉ nhìn thấy file hiện tại.

💬Trợ lý chat

  • Bạn tự dán code, log, thông báo lỗi vào khung chat.
  • Claude chỉ trả lời bằng văn bản; bạn tự copy code về và chạy thử.
  • Chỉ thấy những gì bạn đưa vào.
  • Phù hợp: hỏi khái niệm, viết đoạn code ngắn, giải thích.

🤖Claude Code (coding agent)

  • Tự đọc file trong thư mục dự án và thư mục con.
  • Có tools để sửa file, chạy lệnh shell, chạy test, dùng git.
  • Thấy cả trạng thái git (nhánh, thay đổi chưa commit, lịch sử commit gần đây).
  • Phù hợp: sửa bug nhiều file, viết test, refactor, tạo commit/PR.

Ví dụ đời thường

Trợ lý chat giống một chuyên gia tư vấn qua điện thoại: bạn mô tả, họ khuyên, bạn tự làm. Claude Code giống một đồng nghiệp ngồi cạnh bạn, được mở máy của bạn: tự mở file, chạy thử, sửa và báo lại. 🔄Claude Code hoạt động thế nào: agentic loop

Khi nhận một tác vụ, Claude làm việc qua ba pha: gather context (thu thập ngữ cảnh), take action (hành động) và verify results (kiểm chứng kết quả). Các pha này đan xen nhau và lặp lại cho tới khi xong việc.

Agentic loop được vận hành bởi hai thành phần: models để suy luận và tools để hành động. Claude Code là lớp bao quanh model, cung cấp tools và quản lý ngữ cảnh mà model nhìn thấy. Tài liệu gọi lớp bao quanh này là agentic harness.

Vòng lặp tự điều chỉnh theo yêu cầu: một câu hỏi về codebase có thể chỉ cần pha thu thập ngữ cảnh; sửa bug thì đi qua cả ba pha nhiều lần; refactor có thể cần kiểm chứng rất kỹ. Claude quyết định bước tiếp theo dựa trên những gì vừa học được ở bước trước, nối hàng chục hành động liên tiếp và tự sửa hướng đi.

Ví dụ: “fix the failing tests”

  1. Bash – chạy bộ test để xem test nào đang hỏng.
  2. Đọc output lỗi – kết quả tool quay về làm ngữ cảnh mới.
  3. Search – tìm các file mã nguồn liên quan.
  4. Read – đọc các file đó để hiểu code.
  5. Edit – sửa file để khắc phục lỗi.
  6. Bash – chạy lại test để kiểm chứng.

Mỗi lần dùng tool đem về thông tin mới, quyết định bước kế tiếp. Đây chính là agentic loop trong thực tế.

Models

Claude Code dùng các model Claude để hiểu code và suy luận. Có nhiều model với đánh đổi khác nhau: theo tài liệu, Sonnet xử lý tốt phần lớn tác vụ lập trình, Opus suy luận mạnh hơn cho các quyết định kiến trúc phức tạp. Đổi model bằng /model trong phiên hoặc khởi động với claude --model <name>.

Bạn cũng là một phần của vòng lặp

  • Nhấn Esc để dừng ngay: tool call đang chạy bị hủy, Claude chờ chỉ dẫn mới.
  • Gõ lời chỉnh sửa rồi nhấn Enter mà không dừng: tin nhắn được xếp hàng (queued); Claude đọc nó ngay khi các tool call hiện tại kết thúc, trong cùng lượt, và điều chỉnh trước bước tiếp theo.
userFix the login bug
assistant[Claude điều tra, thử một hướng sửa…]
userThat’s not quite right. The issue is in the session handling.
assistant[Claude đổi hướng, đọc module session…]

Lần đầu chưa đúng thì không cần làm lại từ đầu – bạn lặp (iterate). Tài liệu khuyên: “Delegate, don’t dictate” – hãy giao việc như giao cho một đồng nghiệp giỏi: cho ngữ cảnh và hướng đi, rồi tin Claude tự tìm chi tiết.

Mẹo thực chiến (Pro Tip)

Prompt mơ hồ như “fix the bug” ⇒ Claude phải đoán. Prompt cụ thể như “fix the login bug where users see a blank screen after entering wrong credentials” kèm vị trí (“the relevant code is in src/payments/”) ⇒ ít vòng lặp thừa, kết quả chính xác hơn. Việc phức tạp thì chia thành các bước đánh số.

Mở rộng khả năng gốc

Built-in tools là nền móng. Bạn có thể mở rộng bằng skills (quy trình đóng gói, tải khi cần), kết nối dịch vụ ngoài bằng MCP, tự động hóa bằng hooks và giao việc cho subagents. Các phần mở rộng này nằm ở lớp trên agentic loop – sẽ học chi tiết ở các bài 37–39.

Claude truy cập được những gì?

  • Project: file trong thư mục hiện tại và thư mục con, cùng file ở nơi khác nếu bạn cho phép.
  • Terminal: mọi lệnh bạn chạy được – build tool, git, package manager, tiện ích hệ thống, script.
  • Git state: nhánh hiện tại, thay đổi chưa commit, lịch sử commit gần đây.
  • CLAUDE.md: file markdown chứa hướng dẫn riêng của dự án, đọc ở đầu mỗi phiên (nếu repo có AGENTS.md, Claude có thể đọc file đó thay thế).
  • Auto memory: những điều Claude tự lưu khi làm việc; 200 dòng đầu hoặc 25KB đầu của MEMORY.md (cái nào tới trước) được nạp đầu mỗi phiên.
Lỗi thường gặp: quên rằng “Claude chạy được mọi lệnh bạn chạy được”

Vì Claude dùng chính quyền của tài khoản bạn, một lệnh Bash có thể xóa file, đẩy code, gọi API production. Nội dung Claude đọc được (README lạ, trang web qua WebFetch, output của MCP server) có thể chứa prompt injection – lệnh trá hình nhằm lừa agent làm việc ngoài ý bạn. Hãy áp dụng nguyên tắc least privilege (quyền tối thiểu): chỉ cho phép những gì tác vụ cần, và đọc kỹ trước khi chấp thuận lệnh lạ.

🔒Permission modes: cho Claude tự làm đến đâu?

Claude Code có hai cơ chế an toàn: checkpoints cho phép hoàn tác thay đổi file, và permissions kiểm soát những gì Claude được làm mà không cần hỏi. Permission mode của phiên quyết định hành động nào chạy ngay, hành động nào phải chờ bạn duyệt.

ModeChạy mà không hỏiPhù hợp nhất cho
default (alias manual)Đọc file trong thư mục làm việc và các hành động không cần duyệt (vd khởi động subagent)Việc nhạy cảm, code chưa quen
acceptEditsĐọc, sửa file và các lệnh filesystem phổ biến (mkdir, touch, mv, cp, rm, rmdir, sed) trong thư mục làm việcLặp nhanh trên code bạn đang review
planĐọc, cộng các lệnh được classifier duyệt khi auto mode khả dụngKhám phá codebase trước khi thay đổi
autoMọi thứ, có classifier kiểm tra an toàn chạy nềnTác vụ dài, giảm “mệt mỏi vì hỏi duyệt”
dontAskĐọc file trong thư mục làm việc và tool đã được duyệt trước. Mọi thứ cần hỏi đều bị từ chốiCI và script đã khóa chặt
bypassPermissionsMọi thứChỉ container và VM cô lập

Theo trang Permission modes, kiểm tra ngày 2026-11-20.

Quy tắc quan trọng

Deny rules chặn ở mọi mode, kể cả bypassPermissions. Ngược lại, allow rules không có tác dụng trong bypassPermissions (vì mọi thứ đã được phép).

Cách chuyển mode

# Chọn mode ngay khi khởi động
claude --permission-mode plan
claude --permission-mode acceptEdits
claude --permission-mode dontAsk        # CI: thứ gì cần hỏi thì từ chối
claude --permission-mode auto

# Đặt mode mặc định trong settings (vd .claude/settings.json)
{
  "permissions": {
    "defaultMode": "default"
  }
}
  • Thứ tự ưu tiên khi khởi động: cờ --permission-mode (hoặc --dangerously-skip-permissions) > permissions.defaultMode trong settings > mặc định có sẵn.
  • Giá trị "auto" hoặc "bypassPermissions" đặt trong .claude/settings.json hay .claude/settings.local.json của dự án bị bỏ qua – một repo không thể tự cấp quyền cao cho chính nó.
  • Bạn cũng có thể cho phép sẵn từng lệnh tin cậy (vd npm test, git status) trong .claude/settings.json để Claude khỏi hỏi mỗi lần.
  • VS Code: bấm vào chỉ báo mode (nhãn Manual, Edit automatically, Plan, Auto, Bypass permissions). Desktop: bộ chọn dưới ô prompt. Web: dropdown trên claude.ai/code.

Auto mode

Trong auto, một model classifier riêng xem xét hành động trước khi chạy, chặn những gì vượt quá yêu cầu của bạn, nhắm vào hạ tầng không nhận diện được, hoặc có vẻ bị điều khiển bởi nội dung thù địch (vd prompt injection). Một số điểm theo tài liệu (kiểm tra ngày 2026-11-20):

  • Từ Claude Code v2.1.283 trở đi, auto là mode khởi đầu có sẵn cho phiên terminal tương tác và VS Code.
  • Có yêu cầu về model; Sonnet 4.5, Opus 4.5, Haiku 4.5 và các model claude-3 không được hỗ trợ. Trên Team/Enterprise, admin có thể tắt bằng permissions.disableAutoMode trong managed settings.
  • Cơ chế dự phòng: nếu classifier chặn một hành động 3 lần liên tiếp hoặc tổng cộng 20 lần, auto mode tạm dừng và Claude Code quay lại hỏi bạn.

Cảnh báo về auto và bypassPermissions
  • Tài liệu ghi rõ: auto mode giảm số lần hỏi nhưng không đảm bảo an toàn – đừng dùng nó thay cho việc review các thao tác nhạy cảm.
  • bypassPermissions chỉ dùng trong môi trường cô lập như container, VM, dev container không có internet. Không thể chuyển sang mode này từ một phiên không khởi động với nó. Trên Linux/macOS, Claude Code từ chối chạy mode này dưới quyền root hoặc sudo trừ khi nhận ra sandbox. Admin có thể chặn bằng permissions.disableBypassPermissionsMode.

Protected paths và critical paths

Một số đường dẫn được bảo vệ đặc biệt vì sửa nhầm có thể phá cấu hình hoặc chèn mã độc vào môi trường:

  • Thư mục được bảo vệ: .git, .vscode, .idea, .husky, .devcontainer, .claude (có ngoại lệ như .claude/worktrees/).
  • File được bảo vệ: .gitconfig, .bashrc, .zshrc, .profile, .npmrc, .mcp.json, .claude.json.
  • Ghi vào protected path: default/acceptEdits ⇒ hỏi; auto ⇒ chuyển cho classifier; dontAsk ⇒ từ chối; bypassPermissions ⇒ cho phép. Allow rules trong settings không duyệt trước việc ghi vào protected path.
  • Critical paths: Claude Code chặn rm/rmdir xóa thư mục gốc, thư mục cấp cao nhất, thư mục home, thư mục làm việc và các thư mục cha – không allow rule hay hook nào duyệt được, ở mọi mode. Tài liệu lưu ý kiểm tra này có thể sót, nên hãy dùng thêm sandbox.
Mẹo thực chiến (Pro Tip) – chọn mode theo tình huống
  • Lần đầu mở một codebase lạ / hệ thống nhạy cảm ⇒ plan hoặc default.
  • Đang lặp nhanh trên code bạn sẽ tự review diff ⇒ acceptEdits.
  • Tác vụ dài, muốn ít bị hỏi nhưng vẫn có lớp kiểm tra ⇒ auto.
  • Pipeline CI không có người duyệt ⇒ dontAsk + allow rules cho đúng các tool cần thiết.
  • Muốn bỏ hẳn mọi kiểm tra ⇒ chỉ bypassPermissions trong container/VM cô lập.

🗺️Plan mode và quy trình explore → plan → code → commit

Trong Plan mode, Claude đọc file và khám phá nhưng không sửa mã nguồn; việc sửa bị chặn cho tới khi bạn duyệt plan. Đây là cách an toàn để Claude hiểu vấn đề và đề xuất hướng làm trước khi động vào code.

  • Vào plan mode: nhấn Shift+Tab, hoặc thêm tiền tố /plan cho một prompt (vd /plan fix the auth bug), hoặc khởi động với claude --permission-mode plan.
  • Thoát: nhấn Shift+Tab lần nữa (đang ở màn hình duyệt thì nhấn Esc trước).
  • Khi Claude trình plan, bạn chọn: Yes, and use auto mode, Yes, manually approve edits hoặc No, keep planning. Nhấn Ctrl+G để sửa plan trong editor của bạn.
  • Lệnh shell trong lúc lập plan: nếu auto mode khả dụng và useAutoModeDuringPlan bật (mặc định), classifier xem xét lệnh; nếu không, lệnh ngoài tập chỉ-đọc sẽ hỏi bạn duyệt.
  • Trong VS Code, plan mở ra thành một tài liệu Markdown đầy đủ để bạn thêm bình luận nội tuyến trước khi Claude bắt đầu.

Mẹo thực chiến (Pro Tip)

Thay đổi lớn hoặc chưa rõ phải sửa ở đâu ⇒ bắt đầu bằng Plan mode để Claude khám phá trước (“let Claude explore first”), sửa plan bằng Ctrl+G, rồi mới cho sửa code. Trước khi commit, hãy review diff – khóa học còn gợi ý dùng một reviewer có ngữ cảnh mới (fresh context) để soát lại.

🧩Tích hợp IDE: VS Code và JetBrains

VS Code (và Cursor)

Extension cung cấp inline diff, @-mention, duyệt plan và lịch sử hội thoại ngay trong editor. Cài từ Extensions view (Cmd+Shift+X / Ctrl+Shift+X), tìm “Claude Code”; sau đó mở Command Palette, gõ “Claude Code”, chọn Open in New Tab.

  • Yêu cầu: VS Code 1.94.0 trở lên; một gói Claude trả phí hoặc tài khoản Claude Console (không cần API key; đăng nhập khi mở panel lần đầu).
  • Inline diff: ở mode Manual, Claude hiện diff hai bên cho từng thay đổi và xin phép; bạn có thể chấp nhận, từ chối, hoặc sửa nội dung đề xuất trước khi chấp nhận (Claude được báo là bạn đã sửa).
  • @-mention: @auth khớp mờ với auth.js, AuthService.ts; thêm dấu / để chỉ thư mục (@src/components/); Option+K / Alt+K chèn tham chiếu kiểu @file.ts#5-10; @terminal:name đưa output terminal vào prompt.
  • Claude tự thấy vùng chọn và file đang mở (tắt được bằng claudeCode.attachSelection, claudeCode.attachOpenFile).
  • Lịch sử: phiên dùng chung với CLI – chạy claude --resume trong terminal để tiếp tục.
  • Checkpoints: rê chuột lên một tin nhắn để fork hội thoại hoặc rewind code.

⏪Sessions, context window và checkpoints

Claude Code lưu hội thoại cục bộ: mỗi tin nhắn, tool use và kết quả được ghi vào file JSONL dạng văn bản thuần dưới ~/.claude/projects/. Nhờ vậy có thể rewind, resume và fork phiên.

  • Các phiên độc lập: mỗi phiên mới bắt đầu với context window trống, không có lịch sử phiên trước. Thứ cần nhớ lâu dài thì để trong CLAUDE.md hoặc auto memory.
  • Resume vs fork: claude --continue / claude --resume mở lại phiên với cùng session ID và nối thêm tin nhắn; --fork-session hoặc /branch sao chép lịch sử sang session ID mới, giữ nguyên bản gốc.
  • Phiên gắn với thư mục: muốn chạy song song nhiều phiên trên các nhánh khác nhau ⇒ dùng git worktrees.
  • Context window chứa lịch sử hội thoại, nội dung file, output lệnh, CLAUDE.md, auto memory, skill đã nạp và system instructions. Khi gần đầy, Claude Code tự compact (tóm tắt) – hướng dẫn chi tiết đầu hội thoại có thể mất. Chạy /context để xem cái gì chiếm chỗ; /compact focus on … để chỉ định trọng tâm khi tóm tắt.

Checkpoints: hoàn tác thay đổi file

Trước khi sửa file, Claude chụp lại nội dung hiện tại. Nếu có sự cố, nhấn Esc hai lần để quay về trạng thái trước, hoặc bảo Claude hoàn tác. Checkpoints tách biệt với git và vẫn còn khi bạn resume hội thoại.

Lỗi thường gặp: nghĩ rằng checkpoint hoàn tác được mọi thứ

Checkpoints chỉ bao phủ thay đổi file (và bỏ qua file symlink / hard link khi khôi phục). Hành động tác động hệ thống bên ngoài – database, API, deployment – không thể checkpoint. Những việc đó bạn phải kiểm soát bằng permission mode và permission rules.

Mẹo thực chiến (Pro Tip)

Quy tắc cần áp dụng xuyên suốt (coding standard, lệnh test…) ⇒ ghi vào CLAUDE.md (tạo nhanh bằng /init) thay vì nhắc trong hội thoại, vì sau khi compact hoặc mở phiên mới, lời nhắc cũ có thể mất. Gặp vấn đề cài đặt/cấu hình ⇒ chạy /doctor.

🧪Thực hành

  1. Bài tập 1 – Cài đặt và kiểm tra. Cài Claude Code bằng Native Install phù hợp hệ điều hành của bạn (macOS/Linux/WSL: install.sh; Windows PowerShell: install.ps1). Mở terminal mới, chạy claude --version, sau đó vào một dự án và chạy claude, đăng nhập, gõ /doctor.
    Kết quả mong đợi: claude --version in số phiên bản kèm “(Claude Code)”; prompt Claude Code hiện phiên bản, model hiện tại và thư mục làm việc; /doctor không báo lỗi nghiêm trọng.
  2. Bài tập 2 – Quan sát agentic loop ở plan mode. Khởi động claude --permission-mode plan trong một dự án có test. Gõ: “what does this project do? where is the main entry point? how are tests run?”. Sau đó gõ: “there are failing tests – find out why and propose a fix”.
    Kết quả mong đợi: bạn thấy Claude dùng Read/tìm kiếm và (nếu được duyệt) chạy lệnh test, không sửa file nào; cuối cùng Claude trình một plan với các lựa chọn “Yes, and use auto mode / Yes, manually approve edits / No, keep planning”. Thử Ctrl+G để sửa plan trước khi duyệt.
  3. Bài tập 3 – So sánh default và acceptEdits. Trong một nhánh git mới, ở mode default yêu cầu “add input validation to the user registration form”; ghi lại số lần Claude xin phép. Hoàn tác bằng Esc hai lần (checkpoint), nhấn Shift+Tab sang acceptEdits và yêu cầu lại.
    Kết quả mong đợi: ở default mỗi lần sửa file và chạy lệnh đều hỏi; ở acceptEdits việc sửa file và lệnh filesystem cơ bản chạy ngay, còn lệnh khác (vd chạy test) vẫn hỏi. Bạn rút ra mode nào hợp với việc gì.
  4. Bài tập 4 – Chế độ không tương tác cho CI. Viết một script shell chạy review tự động: 
    # review-changes.sh – chạy trong CI; API key lấy từ secret của CI, KHÔNG ghi vào file
# (biến môi trường ANTHROPIC_API_KEY do hệ thống CI cấp)
git diff main --name-only \
  | claude -p "review these changed files for security issues; list findings only" \
      --permission-mode dontAsk
    Kết quả mong đợi: Claude in danh sách vấn đề rồi thoát; mọi hành động cần hỏi duyệt đều bị từ chối thay vì treo pipeline. Giải thích vì sao không dùng bypassPermissions ở đây (nguyên tắc least privilege).

Tóm tắt ghi nhớ

Key takeaways
  • Claude Code là agentic coding tool: tự đọc codebase, sửa file, chạy lệnh, dùng git; có ở terminal, VS Code/Cursor, JetBrains, desktop, web, CI/CD, Slack – dùng chung một engine.
  • Cài Native Install (tự cập nhật): curl -fsSL https://claude.ai/install.sh | bash hoặc irm https://claude.ai/install.ps1 | iex; Homebrew/WinGet không tự cập nhật. Kiểm tra bằng claude --version.
  • Agentic loop: gather context → take action → verify results, chạy bởi models (suy luận) + tools (hành động); Claude Code là agentic harness bao quanh model.
  • 5 nhóm built-in tools: file operations, search, execution, web, code intelligence. Read/Glob/Grep không cần quyền; Edit/Write/Bash/WebFetch cần quyền.
  • 6 permission modes: default, acceptEdits, plan, auto, dontAsk, bypassPermissions. Shift+Tab xoay vòng; deny rules chặn ở mọi mode.
  • Plan mode: khám phá + lập plan, không sửa source tới khi duyệt; quy trình explore → plan → code → commit.
  • Checkpoints (Esc hai lần) chỉ hoàn tác thay đổi file – không hoàn tác được database, API, deployment.
  • Lệnh thiết yếu: claude, claude -p, claude -c, claude -r, /clear, /help, /init, /doctor, /context, /compact.

Câu hỏi luyện tập

Một lập trình viên quen dán code vào Claude.ai để hỏi. Khi chuyển sang Claude Code và yêu cầu “fix the authentication bug”, điều gì khác biệt cốt lõi nhất?
  1. Claude Code dùng một model riêng không có trên Claude.ai nên trả lời chính xác hơn.
  2. Claude Code tự tìm và đọc các file liên quan, sửa đồng bộ nhiều file, chạy test để kiểm chứng – bạn không phải tự đưa ngữ cảnh vào.
  3. Claude Code chỉ nhìn thấy file đang mở trong editor, giống trợ lý code nội tuyến.
  4. Claude Code tự động commit và push mọi thay đổi mà không cần hỏi.
Đáp án B. Claude Code là agentic coding tool: nó có tools để tự thu thập ngữ cảnh, hành động và kiểm chứng. C sai: tài liệu nhấn mạnh điều ngược lại – Claude Code thấy cả dự án, khác với trợ lý nội tuyến chỉ thấy file hiện tại. D sai: commit chỉ khi bạn yêu cầu, và việc chạy lệnh còn phụ thuộc permission mode.
Theo tài liệu “How Claude Code works”, những phát biểu nào đúng về agentic loop? (Chọn 2)
  1. Gồm ba pha gather context, take action, verify results, đan xen và lặp lại.
  2. Mọi tác vụ, kể cả một câu hỏi đơn giản về codebase, luôn phải đi đủ cả ba pha.

Một kỹ sư dùng Claude Code trong VS Code. Những phát biểu nào đúng? (Chọn 2)

Bạn được giao refactor module thanh toán trong một codebase chưa từng đọc. Bạn muốn Claude hiểu code và đề xuất hướng làm, nhưng tuyệt đối chưa sửa file nào cho tới khi bạn đồng ý. Cách nào phù hợp nhất?

Đọc lệnh sau trong một script: 
tail -200 app.log | claude -p "summarize anomalies"
Phát biểu nào đúng?
  1. Lệnh mở phiên tương tác và chờ bạn gõ tiếp.
  2. Cờ -p nghĩa là tiếp tục (continue) hội thoại gần nhất.
  3. 200 dòng log được pipe vào Claude; -p chạy truy vấn một lần, in kết quả rồi thoát – phù hợp cho script/CI.
  4. Lệnh sai vì Claude Code không nhận dữ liệu từ pipe.
Đáp án C. claude -p "query": “Run one-off query, then exit”; tài liệu Overview có đúng ví dụ tail -200 app.log | claude -p … vì Claude Code tuân theo triết lý Unix. A sai: phiên tương tác là claude hoặc claude "task". B sai: tiếp tục hội thoại gần nhất là claude -c. D sai: pipe được hỗ trợ.

Sau một phiên dài, Claude bắt đầu “quên” quy ước đặt tên bạn đã dặn từ đầu hội thoại. Cách xử lý được tài liệu khuyến nghị là gì?
  1. Nhắc lại quy ước trong mỗi tin nhắn.
  2. Ghi quy ước bền vững vào CLAUDE.md (có thể tạo bằng /init), và dùng /context để xem cái gì đang chiếm context.

  4. Mở phiên mới bằng /clear – phiên mới tự mang theo toàn bộ hội thoại cũ.
Đáp án B. Khi context đầy, Claude Code tự compact và hướng dẫn chi tiết đầu hội thoại có thể mất; tài liệu khuyên đặt quy tắc bền vững trong CLAUDE.md (đọc đầu mỗi phiên) và chạy /context.
