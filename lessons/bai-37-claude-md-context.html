🧠Hai cơ chế ghi nhớ: CLAUDE.md và auto memory

Mỗi phiên Claude Code bắt đầu với một context window hoàn toàn mới. Claude không "nhớ" phiên hôm qua. Để mang kiến thức qua nhiều phiên, Claude Code có hai cơ chế bổ sung cho nhau: CLAUDE.md do bạn viết, và auto memory do Claude tự ghi.

Quy tắc nạp cần nhớ

  1. Đi ngược lên cây thư mục – Claude Code nạp CLAUDE.md và CLAUDE.local.md ở thư mục làm việc hiện tại và mọi thư mục phía trên. Chạy trong foo/bar/ thì nạp cả foo/bar/CLAUDE.md và foo/CLAUDE.md.
  2. Nối lại, không ghi đè – mọi file tìm được được nối vào context. Thứ tự từ gốc hệ thống file xuống thư mục làm việc, nên chỉ dẫn gần nơi bạn khởi động nhất được đọc sau cùng. Trong cùng thư mục, CLAUDE.local.md được nối sau CLAUDE.md.
  3. Thư mục con nạp theo yêu cầu – CLAUDE.md trong thư mục con không nạp lúc khởi động mà nạp khi Claude đọc, ghi hoặc sửa một file trong thư mục con đó (kể cả cat/head một file qua Bash).
  4. Mâu thuẫn thì "chọn bừa" – vì không có ghi đè, nếu hai file nói ngược nhau, tài liệu cảnh báo Claude có thể chọn một trong hai một cách tùy ý. Hãy rà soát định kỳ để loại bỏ chỉ dẫn mâu thuẫn.
  5. --add-dir – theo mặc định CLAUDE.md của thư mục bổ sung không được nạp; đặt CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 để nạp.
Ví dụ đời thường – sổ tay nhân viên mới

Hãy hình dung một nhân viên mới nhận ba tài liệu: nội quy công ty (managed policy), sổ tay phòng ban (project CLAUDE.md) và tờ ghi chú riêng của chính mình (CLAUDE.local.md). Anh ta đọc hết theo thứ tự, không xé trang nào. Nếu nội quy và sổ tay nói ngược nhau, anh ta sẽ bối rối và có thể làm theo một bên bất kỳ — đó là lý do phải giữ các tài liệu nhất quán.

Kiểm tra file nào đã được nạp

Chạy /context all trong phiên và xem danh sách Memory files. Lệnh /memory liệt kê các file CLAUDE.md, CLAUDE.local.md theo user và project scope (kể cả file chưa tồn tại — chọn vào sẽ tạo mới), cho phép bật/tắt auto memory và mở thư mục auto memory. CLAUDE.md ở thư mục con không xuất hiện trong Memory files vì nó chỉ nạp khi cần; khi nạp, terminal hiện một dòng Loaded kèm đường dẫn.

✍️Viết CLAUDE.md hiệu quả

Mỗi dòng trong CLAUDE.md chiếm một chút "sự chú ý" của Claude trong mọi tác vụ, dù có liên quan hay không. Vì vậy file tốt nhất là file ngắn và chỉ chứa điều Claude không tự tìm ra từ code.

Bắt đầu bằng /init

Chạy /init để Claude phân tích codebase và sinh CLAUDE.md khởi đầu với lệnh build, cách chạy test, quy ước dự án. Nếu đã có CLAUDE.md, /init đề xuất cải tiến thay vì ghi đè. /init cũng đọc file chỉ dẫn của công cụ khác (.cursor/rules/, .cursorrules, .github/copilot-instructions.md) để đưa phần phù hợp vào. Đặt biến môi trường CLAUDE_CODE_NEW_INIT=1 để dùng luồng tương tác nhiều bước: hỏi bạn muốn tạo CLAUDE.md, skill hay hook, khám phá codebase bằng subagent, hỏi bổ sung rồi trình đề xuất để bạn duyệt trước khi ghi file.

Theo trang Best practices, sau /init phần lớn công việc là xóa bớt dòng. /doctor đề xuất cắt những gì Claude tự suy ra được từ code; /doctor prompt-audit (cần v2.1.283 trở lên) tìm chỉ dẫn viết cho model cũ, trỏ tới file không còn tồn tại, hoặc mâu thuẫn nhau.

Phép thử hai câu hỏi

Trước khi ghi một điều gì vào CLAUDE.md, tài liệu đề nghị tự hỏi: (1) Claude có thể tìm ra điều này bằng cách đọc code không? (2) Nó có thực sự đi tìm không? Nếu cả hai đều "có" ⇒ bỏ ra.

Comment HTML dạng block (<!-- maintainer notes -->) trong CLAUDE.md bị loại bỏ trước khi chèn vào context — dùng để để lại ghi chú cho người mà không tốn token. Comment nằm trong code block thì được giữ nguyên.

Import file khác bằng @path

CLAUDE.md có thể import file khác bằng cú pháp @path/to/import. File được import sẽ được mở rộng và nạp cùng CLAUDE.md tham chiếu nó.

  • Chấp nhận cả đường dẫn tương đối và tuyệt đối; đường dẫn tương đối tính từ file chứa import, không phải từ thư mục làm việc.
  • Import đệ quy tối đa bốn hop.
  • Đường dẫn có dấu cách: đặt dấu \ trước mỗi dấu cách (@Design\ Docs/api-conventions.md). Đường dẫn bọc trong dấu nháy không được import.
  • Import bị bỏ qua trong code span và fenced code block — viết `@README` để nhắc tên file mà không import.
  • Import giúp tổ chức nhưng không giảm chi phí context, vì file import nạp cùng lúc với CLAUDE.md.

Lỗi thường gặp – import bên ngoài và bảo mật

Import trong file project trỏ ra ngoài thư mục làm việc được coi là external import. Lần đầu gặp, Claude Code hiện hộp thoại liệt kê các file để bạn duyệt; nếu từ chối, import bị tắt và hộp thoại không hiện lại. Cơ chế này bảo vệ bạn khỏi file do người khác commit vào dự án dùng chung — một dạng prompt injection qua chỉ dẫn. Khi clone repo lạ, hãy đọc CLAUDE.md, .claude/rules/ và danh sách import trước khi chấp nhận (đúng tinh thần "kiểm tra dữ liệu đầu vào từ nguồn không tin cậy" trong 「セキュア・プログラミング講座」 của IPA).

Claude bỏ qua những gì suy ra được từ codebase (kiến trúc, đường dẫn file, cách sửa lỗi) và những gì CLAUDE.md đã nói.

Lưu ở đâu, nạp thế nào

~/.claude/projects/<project>/memory/
├── MEMORY.md           # chỉ mục, mỗi memory một dòng, nạp vào mọi phiên
├── user_role.md        # một memory
├── feedback_testing.md # một memory
└── ...                 # các file chủ đề khác Claude tạo
  • <project> suy ra từ git repository ⇒ mọi worktree và thư mục con trong cùng repo dùng chung một thư mục auto memory. Ngoài git repo thì dùng thư mục gốc dự án.
  • Chỉ 200 dòng đầu hoặc 25KB đầu của MEMORY.md (cái nào đến trước) được nạp đầu mỗi phiên. Các file chủ đề (user_role.md…) không nạp lúc khởi động; Claude đọc chúng khi cần bằng công cụ file thông thường.
  • Auto memory là cục bộ trên máy, không đồng bộ giữa các máy hay môi trường cloud. File memory không bị xóa theo cleanupPeriodDays.
  • Auto memory của phiên chính không nạp vào subagent (trừ fork). Subagent có thể có auto memory riêng qua trường memory.
  • Khi thấy "Saved 2 memories" hay "Recalled 2 memories" trên giao diện, Claude đang ghi/đọc thư mục memory.

Bật, tắt, đổi vị trí

  • Auto memory bật mặc định trong phiên cục bộ. Bật/tắt bằng /memory (lưu autoMemoryEnabled vào ~/.claude/settings.json).
  • Tắt cho một dự án: "autoMemoryEnabled": false trong settings của dự án. Tắt bằng biến môi trường: CLAUDE_CODE_DISABLE_AUTO_MEMORY=1.
  • Đổi thư mục: "autoMemoryDirectory": "~/my-custom-memory-dir" (phải là đường dẫn tuyệt đối hoặc bắt đầu bằng ~/).
userremember that the API tests require a local Redis instance

assistant(Claude sửa CLAUDE.md của dự án – chỉ dẫn dùng chung, commit cùng repo)

Tài liệu phân biệt rõ: khi bạn bảo "remember…", Claude lưu vào auto memory. Muốn ghi vào CLAUDE.md, hãy nói thẳng "add this to CLAUDE.md" hoặc tự sửa qua /memory.

Lỗi thường gặp – để lộ thông tin nhạy cảm vào memory

Auto memory và CLAUDE.md là file markdown thuần. Đừng nhờ Claude "nhớ" API key, mật khẩu hay token; đừng ghi chúng vào CLAUDE.md (file được commit lên repo). Hãy định kỳ mở /memory → thư mục auto memory để rà soát, sửa hoặc xóa — tất cả đều là văn bản bạn đọc được.

🪟Quản lý context window

Context window của Claude Code chứa mọi thứ Claude biết về phiên: chỉ dẫn của bạn, các file nó đọc, câu trả lời của chính nó, và cả nội dung không bao giờ hiện trên terminal. Hiểu cái gì chiếm chỗ và khi nào nó vào là chìa khóa để phiên làm việc vừa chính xác vừa rẻ.

Context đầy dần như thế nào

  • Trước khi bạn gõ gì: system prompt, CLAUDE.md, auto memory (MEMORY.md), tên các MCP tool và mô tả skill đã nạp. Có thể thêm output style hoặc nội dung từ --append-system-prompt.
  • Khi Claude làm việc: mỗi lần đọc file cộng thêm token; path-scoped rule tự nạp cùng file khớp; output của hook (ví dụ PostToolUse chạy Prettier) cũng vào context.
  • Khi giao cho subagent: subagent đọc file trong context window riêng, chỉ gửi về bản tóm tắt và một ít metadata.
  • Khi compaction: hội thoại được thay bằng một bản tóm tắt có cấu trúc; phần lớn nội dung khởi động được nạp lại.

Trang Explore the context window có một phiên ví dụ: trước /compact dùng 22,225 token; sau /compact còn 17,095 token (phần khởi động, bản tóm tắt 1,725 token, bốn file đã đọc và nội dung skill đã gọi). Đây là số minh họa; muốn xem số thật của phiên bạn, chạy /context — lệnh hiển thị mức dùng theo từng nhóm kèm gợi ý tối ưu.

Auto-compaction

Claude Code tự compact khi bạn tiến gần giới hạn, nên context đầy không làm phiên kết thúc. Theo trang Model configuration (kiểm tra 2026-11-20):

  • Model có context window 1M gốc (các model Fable, Sonnet 5 trở lên, Haiku 5.5, Opus 4.7 trở lên) compact ở khoảng 967K token theo mặc định.
  • Sonnet 4.6 và Opus 4.6 khi không bật extended context compact ở mốc 200K; đặt CLAUDE_CODE_DISABLE_1M_CONTEXT=1 cũng đưa các model 1M gốc về mốc 200K.
  • Đổi ngưỡng: /autocompact <giá trị>, cờ --autocompact, khóa autoCompactWindow trong settings, hoặc biến CLAUDE_CODE_AUTO_COMPACT_WINDOW (ưu tiên cao nhất). Lệnh và cờ nhận giá trị từ 100K token trở lên.

Nếu một chỉ dẫn biến mất sau compaction, nó thường (1) chỉ được nói trong hội thoại, (2) nằm trong CLAUDE.md lồng chưa nạp lại, hoặc (3) là path-scoped rule chưa khớp file nào từ đó. Tương tự, câu "don't push until I've reviewed" nói trong hội thoại có thể mất khi compact — điều quan trọng phải nằm trong deny rule.

Chi phí: vì sao vẫn nên /clear khi context còn rộng

Trang Best practices xếp lời khuyên "context window là ràng buộc chính, hãy quản lý quyết liệt" vào mục What you can stop doing, vì hầu hết model hiện tại có context 1M token và compaction tự chạy. Tuy vậy /clear giữa các tác vụ vẫn đáng làm: mỗi request gửi cả hội thoại, nên một phiên đã gom ba tác vụ không liên quan sẽ đọc lại cả ba ở mỗi lượt của tác vụ thứ tư. Phần này được giảm giá khi prompt cache còn "ấm" và tính giá đầy đủ khi cache hết hạn. Theo tài liệu, prompt cache kéo dài khoảng một giờ với gói subscription và năm phút với API key, cloud provider hoặc usage credits. Dùng /usage để xem token đi đâu.

Mẹo thực chiến (Pro Tip)

Cần khám phá một codebase lớn mà không muốn hàng chục file đọc nằm lại trong context chính ⇒ giao cho subagent: use a subagent to investigate how our auth system handles token refresh. Subagent đọc trong context riêng và chỉ gửi về bản tóm tắt. Lưu ý tài liệu: subagent tốn thêm token và không cho câu trả lời thông minh hơn; lợi ích là chạy song song, giữ output ồn ào ngoài phiên chính và có người review "mắt mới".

🗺️Plan mode, effort và thinking

Plan mode cho phép bạn duyệt thay đổi trước khi nó chạm tới đĩa: Claude đọc file, chạy lệnh để khám phá và viết kế hoạch, nhưng không sửa source cho tới khi bạn phê duyệt.

Vào và ra plan mode

  • Nhấn Shift+Tab trong phiên cho tới khi thanh trạng thái hiện ⏸ plan mode on; hoặc thêm /plan trước một prompt.
  • Khởi động sẵn trong plan mode: claude --permission-mode plan.
  • Đặt làm mặc định: "permissions": { "defaultMode": "plan" } trong .claude/settings.json (dự án) hoặc ~/.claude/settings.json (mọi phiên terminal).
  • Thoát: nhấn Shift+Tab lần nữa khi không có prompt phê duyệt. Tại prompt phê duyệt, nhấn Esc trước — vì nhấn Shift+Tab ở đó là phê duyệt plan.
  • Nhấn Ctrl+G để mở plan trong trình soạn thảo mặc định và sửa trước khi Claude thực hiện.

Thứ tự vòng Shift+Tab trong CLI: từ auto, lần nhấn đầu chuyển sang default; sau đó vòng default → acceptEdits → plan rồi quay lại (các mode tùy chọn như bypassPermissions, auto chen vào sau plan nếu được bật). Permission mode được học kỹ ở bài 36.

Effort level – núm chỉnh chính cho "độ suy nghĩ"

Theo Best practices, effort là điều khiển chính cho việc Claude suy nghĩ bao lâu, và nó thay thế hầu hết những gì người ta từng làm bằng cách viết prompt. Claude Fable 5.2, Opus 5.5, Sonnet 5.5 và Haiku 5.5 mặc định medium (kiểm tra 2026-11-20). Các mức trên những model này: low, medium, high, xhigh, max.

⬇️/effort low

  • Trao đổi qua lại nhanh, bạn xem từng kết quả.
  • Brainstorm, phác thảo đầu, rename vài file.

⏺️medium (mặc định)

  • Đủ cho việc phát triển tính năng hằng ngày có phạm vi rõ.

⬆️/effort high · xhigh

  • Bug trong code bạn không viết, test chập chờn (flaky), thay đổi schema phải tìm mọi chỗ đọc.

🚀max

  • Bài toán khó để Claude tự làm không cần bạn (săn lỗ hổng bảo mật). Việc thường thì dễ "nghĩ quá".
  • Đặt effort: /effort (thanh trượt), /effort high, cờ --effort high, biến CLAUDE_CODE_EFFORT_LEVEL, khóa effortLevel trong settings, hoặc effort: trong frontmatter skill/subagent.
  • ultrathink: đặt từ này ở bất kỳ đâu trong prompt để yêu cầu suy luận sâu hơn cho lượt đó mà không đổi effort của phiên. Các cụm "think", "think hard", "think harder" không còn là từ khóa — chỉ là văn bản thường.
  • Bật/tắt extended thinking cho phiên: Option+T (macOS) / Alt+T (Windows, Linux); mặc định toàn cục qua /config (alwaysThinkingEnabled). Ctrl+O bật verbose để xem phần suy luận. Trên Opus 5.5, Sonnet 5.5, Haiku 5.5 và các model Fable không thể tắt thinking — hãy hạ effort.
  • Alias opusplan: dùng opus trong plan mode rồi chuyển sang sonnet để thực thi.
Mẹo thực chiến (Pro Tip)

Phiên đang làm việc thường, chỉ một câu hỏi giữa chừng cần nghĩ kỹ (ví dụ phân tích race condition) ⇒ thêm ultrathink vào riêng prompt đó, thay vì đổi /effort cho cả phiên. Còn muốn Claude làm "đầy đủ hơn" (xử lý trạng thái rỗng/lỗi, điều hướng bàn phím) ⇒ nói be ambitious — đó là thông tin về phạm vi, thứ chỉ bạn biết.

Trong script, Best practices khuyên thêm vài cờ: --bare (bỏ qua hook, skill, plugin, MCP server và các file CLAUDE.md; xác thực bằng ANTHROPIC_API_KEY lấy từ biến môi trường, không hard-code), --allowedTools để cấp trước đúng các tool cần, --permission-mode dontAsk để từ chối mọi thứ khác, và --max-turns để giới hạn số lượt.

# Di chuyển từng file sang logger mới – quyền tối thiểu (least privilege)
for file in $(cat files.txt); do
  claude --bare -p "Migrate $file to the new logger API and commit. Reply OK or FAIL." \
    --allowedTools "Read,Edit,Bash(git add *),Bash(git commit *)" \
    --permission-mode dontAsk \
    --max-turns 20
done

Cho Claude một phép kiểm tra

Claude dừng khi công việc trông có vẻ xong. Nếu nó có thứ để chạy trả về pass/fail (file test, exit code của build, linter, script so output với fixture, ảnh chụp trình duyệt), nó tự đóng vòng lặp: sửa → chạy kiểm tra → đọc lỗi → sửa tiếp. Tài liệu nói thẳng: nếu repo đã có một phép kiểm tra, dòng hữu ích nhất trong CLAUDE.md là lệnh chạy nó. Và luôn đòi bằng chứng: lệnh đã chạy và output, không chỉ câu "All tests pass".

{
  "hooks": {
    "Stop": [
      { "hooks": [

      ] }

  "permissions": {

Exit code 2 là thứ chặn việc dừng; stderr được gửi lại cho Claude làm lý do. Deny rule giữ hiệu lực ở mọi permission mode, kể cả auto và bypassPermissions. Chi tiết hook học ở bài 39.

Bảo mật khi để Claude chạy một mình

Trước khi để một phiên chạy không giám sát, Best practices đề nghị trả lời năm câu: Nó biết "xong" trông thế nào chưa? Nó tự kiểm tra được không? Nó được phép chạm vào đâu (permission rule, dontAsk, sandbox, worktree)? Cái gì dừng nó (--max-turns, --max-budget-usd)? Kết quả đi đâu và ai duyệt? Nội dung Claude đọc được (issue, trang web, file trong repo lạ) có thể chứa prompt injection; vì vậy quyền phải tối thiểu và con người duyệt bước không thể hoàn tác (merge, deploy).

Giữ lại: lệnh cài đặt, lệnh chạy một file test, lệnh typecheck/lint, 1–2 quy ước khác mặc định, 1 "gotcha". Thêm một comment HTML <!-- người bảo trì: cập nhật khi đổi CI -->.
    Kết quả mong đợi: CLAUDE.md dưới 30 dòng; /context all liệt kê nó dưới Memory files; khi hỏi "how do I run a single test here?", Claude trả lời đúng lệnh trong file mà không cần tìm kiếm.
  2. Bài tập 2 – Tách rule theo đường dẫn và kiểm tra lazy loading. Tạo .claude/rules/api.md: 
    ---

  - "src/api/**/*.ts"
---
- Validate request bodies with the zod schemas in src/api/schemas/
- Every new endpoint needs an entry in openapi.yaml
    Mở phiên mới, chạy /context all (rule chưa có), rồi yêu cầu Claude đọc một file trong src/api/.
    Kết quả mong đợi: rule chỉ xuất hiện sau khi Claude chạm file khớp. Chạy /compact, rồi hỏi lại Claude về quy tắc: bạn sẽ thấy nó chỉ nạp lại khi Claude chạm file src/api/ lần nữa — đúng như bảng "What survives compaction".
  3. Bài tập 3 – Plan mode + effort cho một bug thật. Khởi động claude --permission-mode plan. Viết prompt cụ thể theo mẫu: triệu chứng, thư mục nghi ngờ, "write a failing test that reproduces it, then fix it". Thêm ultrathink nếu lỗi khó.   4. Bài tập 4 – Quản lý context giữa nhiều tác vụ. Làm xong một tác vụ, chạy /clear auth-fix trước khi chuyển sang tác vụ khác. Ở tác vụ thứ hai, giữa chừng hỏi một câu phụ bằng /btw. Cuối buổi, đóng terminal; hôm sau chạy claude --resume auth-fix.
    Kết quả mong đợi: /context ở tác vụ hai không chứa lịch sử tác vụ một; câu hỏi /btw không xuất hiện trong lịch sử; phiên auth-fix mở lại đúng chỗ.

Tóm tắt ghi nhớ

Key takeaways
  • Hai cơ chế ghi nhớ: CLAUDE.md (bạn viết, nạp toàn bộ mỗi phiên) và auto memory (Claude viết, nạp 200 dòng / 25KB đầu của MEMORY.md). Cả hai là context, không phải luật cứng.
  • Thứ tự nạp: managed policy → user (~/.claude/CLAUDE.md) → project (./CLAUDE.md hoặc ./.claude/CLAUDE.md) → local (CLAUDE.local.md). Các file được nối, không ghi đè; thư mục con nạp khi cần.
  • CLAUDE.md tốt: dưới 200 dòng, cụ thể, kiểm chứng được; chỉ chứa điều Claude không tự tìm ra. Bắt đầu bằng /init, rồi xóa bớt.
  • @path import tối đa 4 hop, không giảm context. .claude/rules/ có paths chỉ nạp khi chạm file khớp. Quy trình nhiều bước ⇒ skill.
  • Quy tắc không ngoại lệ ⇒ hook / deny rule / managed settings (deterministic), không phải thêm IMPORTANT vào CLAUDE.md.
  • Context: /context để xem, /clear giữa tác vụ không liên quan, /compact <focus> trước tác vụ dài, /rewind để quay lại, /btw cho câu hỏi phụ. Sau compaction, CLAUDE.md gốc và auto memory được nạp lại; chỉ dẫn chỉ nói trong hội thoại có thể mất.
  • Plan mode (Shift+Tab, /plan, --permission-mode plan): đọc và lập kế hoạch, không sửa source cho đến khi duyệt. Effort là núm chỉnh độ suy nghĩ; ultrathink cho một lượt; "think hard" không còn là từ khóa.
  • Workflow: prompt cụ thể, cho Claude phép kiểm tra pass/fail, đòi bằng chứng; sửa hai lần chưa được ⇒ /clear và viết prompt mới.

  1. Lệnh typecheck chạy trước mỗi lần Claude gọi tool.
  2. Đây chỉ là gợi ý; Claude có thể bỏ qua giống một dòng trong CLAUDE.md.
  3. Hook chạy khi phiên khởi động để nạp lỗi typecheck vào context.
  4. Khi Claude định kết thúc lượt, typecheck chạy; nếu lỗi, exit code 2 chặn việc dừng và stderr được gửi lại cho Claude để sửa tiếp.
Đáp án D. Stop hook chạy khi Claude cố kết thúc lượt; exit code 2 chặn và nội dung stderr (đã chuyển hướng bằng 1>&2) trở thành lý do gửi Claude. A sai: đó là PreToolUse. B sai: hook là cơ chế deterministic do Claude Code cưỡng chế, khác CLAUDE.md. C sai: đó sẽ là SessionStart hook.
Chi vừa sửa xong một bug xác thực trong phiên Claude Code và giờ chuyển sang viết tài liệu cho module báo cáo, không liên quan gì. Cô muốn câu trả lời tập trung và tiết kiệm token. Nên làm gì?
  1. Tiếp tục trong cùng phiên; context 1M token nên không cần quan tâm.
  2. Chạy /clear (có thể đặt tên, ví dụ /clear auth-fix) rồi bắt đầu tác vụ mới.
  3. Chạy /rewind về đầu phiên và chọn khôi phục code.
  4. Tắt auto memory để Claude không nhớ bug cũ.
Đáp án B. /clear giữa các tác vụ không liên quan giúp context tập trung và rẻ hơn, vì mỗi request gửi lại cả hội thoại; đặt tên giúp quay lại sau. A sai: tài liệu vẫn khuyên /clear giữa tác vụ — lịch sử cũ tốn token ở mọi lượt và làm loãng sự chú ý. C sai: khôi phục code sẽ hoàn tác bản sửa bug. D sai: auto memory không phải nguyên nhân và chỉ lưu ghi chú ngắn.
