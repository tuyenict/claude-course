Sau bài này bạn sẽ

  • Giải thích được Agent Skills là gì, khác gì một prompt thông thường và vì sao chúng giúp Claude trở thành "chuyên gia" theo từng lĩnh vực.
  • Mô tả cơ chế progressive disclosure ba cấp: metadata → nội dung SKILL.md → tài nguyên đi kèm.
  • Viết được một file SKILL.md hợp lệ với YAML frontmatter (name, description) đúng các ràng buộc.
  • Dùng Skills trên ba bề mặt: Claude API (container.skills + code execution tool), Claude Code (.claude/skills/) và claude.ai.
  • Áp dụng các skill authoring best practices: viết ngắn gọn, đặt mức tự do phù hợp, mô tả ở ngôi thứ ba, tham chiếu một cấp, xây eval trước.
  • Nhận diện rủi ro bảo mật của Skills và chọn Skill thay vì CLAUDE.md / hooks / subagents / MCP khi phù hợp.

🎒Agent Skills là gì và vì sao cần?

Theo tài liệu Anthropic, Agent Skills là các năng lực dạng mô-đun mở rộng chức năng của Claude. Mỗi Skill đóng gói hướng dẫn, metadata và tài nguyên tùy chọn (script, template) mà Claude tự động dùng khi chúng liên quan tới yêu cầu.

Skill là tài nguyên filesystem-based, tái sử dụng được, mang lại cho Claude chuyên môn theo lĩnh vực: quy trình làm việc (workflow), ngữ cảnh và các thực hành tốt — biến một agent đa năng thành một chuyên gia. Khác với prompt (chỉ dẫn ở mức hội thoại cho tác vụ một lần), Skill được nạp theo nhu cầu, nên bạn không phải lặp lại cùng một hướng dẫn qua nhiều cuộc hội thoại.

🪜Progressive disclosure: nạp kiến thức theo ba cấp

Skills tận dụng môi trường virtual machine (VM) của Claude: Claude có quyền truy cập hệ thống tệp, nên Skill tồn tại dưới dạng thư mục chứa hướng dẫn, code thực thi và tài liệu tham khảo. Kiến trúc này cho phép progressive disclosure: Claude nạp thông tin theo từng giai đoạn khi cần, thay vì tiêu tốn context window ngay từ đầu.

~100token / Skill cho metadata (Level 1), luôn nạp lúc khởi động
< 5ktoken cho phần thân SKILL.md (Level 2), nạp khi Skill được kích hoạt
0token cho file đi kèm (Level 3+) cho tới khi được đọc / chạy

Số liệu theo trang "Agent Skills overview" của Anthropic, kiểm tra ngày 2026-11-20.

CấpKhi nào nạpChi phí tokenNội dung
Level 1: MetadataLuôn luôn (lúc khởi động)~100 token / Skillname và description trong YAML frontmatter — được đưa vào system prompt
Level 2: InstructionsKhi Skill được kích hoạtDưới 5k tokenPhần thân SKILL.md: quy trình, thực hành tốt, hướng dẫn
Level 3+: ResourcesKhi cầnKhông tốn cho tới khi truy cậpFile đi kèm: file tham khảo vào context khi được đọc; script chạy qua bash và chỉ output vào context

Ví dụ: Claude nạp Skill pdf-processing như thế nào

  1. Khởi động – system prompt chứa dòng: pdf-processing - Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction.
  2. Người dùng yêu cầu – "Trích xuất văn bản từ file PDF này và tóm tắt."
  3. Claude gọi – bash: cat pdf-processing/SKILL.md → hướng dẫn được nạp vào context.
  4. Claude quyết định – tác vụ không cần điền form ⇒ không đọc FORMS.md.
  5. Hoàn thành tác vụ – dùng hướng dẫn trong SKILL.md.

Kiến trúc này mang lại gì?

  • Truy cập file theo nhu cầu: Skill có thể chứa hàng chục file tham khảo; nếu tác vụ chỉ cần schema bán hàng thì Claude chỉ nạp đúng file đó.
  • Chạy script hiệu quả: khi Claude chạy validate_form.py, mã nguồn script không vào context — chỉ output (vd "Validation passed") tốn token. Hiệu quả hơn nhiều so với để Claude tự sinh code tương đương.
  • Không giới hạn thực tế về nội dung đi kèm: file chưa được truy cập không tốn context, nên có thể đóng gói tài liệu API đầy đủ, bộ dữ liệu lớn, nhiều ví dụ.

Ba loại nội dung có thế mạnh riêng: instructions cho hướng dẫn linh hoạt, code cho độ tin cậy (thao tác tất định — deterministic), resources cho tra cứu sự thật.

Lưu ý

Vì metadata luôn được nạp, description là thứ Claude dùng để so khớp yêu cầu và quyết định có kích hoạt Skill hay không. Nhờ metadata gọn nhẹ, bạn có thể cài nhiều Skill mà không bị "phạt" context — cho tới khi được kích hoạt, mỗi Skill chỉ chiếm chỗ bằng tên và mô tả.

# Python SDK – dùng Skill PowerPoint dựng sẵn
import anthropic

client = anthropic.Anthropic()  # đọc ANTHROPIC_API_KEY từ biến môi trường, KHÔNG hard-code key

response = client.messages.create(
    model="claude-opus-5-5",      # model ID dùng trong ví dụ của tài liệu (kiểm tra 2026-11-20)
    max_tokens=4096,
    container={
        "skills": [{"type": "anthropic", "skill_id": "pptx", "version": "latest"}]
    },
    messages=[{"role": "user", "content": "Create a presentation about renewable energy"}],
    # Bắt buộc: Skills chạy trong container của code execution tool
    tools=[{"type": "code_execution_20250825", "name": "code_execution"}],
)

File do Skill tạo ra (vd .pptx) được trả về dưới dạng file_id trong các khối kết quả code execution; bạn tải về bằng Files API:

# Lấy file_id từ các khối bash_code_execution_tool_result rồi tải bằng Files API
def extract_file_ids(response):
    file_ids = []
    for item in response.content:
        if item.type == "bash_code_execution_tool_result":
            content_item = item.content
            if content_item.type == "bash_code_execution_result":
                for file in content_item.content:
                    file_ids.append(file.file_id)
    return file_ids

for file_id in extract_file_ids(response):
    meta = client.files.retrieve_metadata(file_id=file_id)
    content = client.files.download(file_id=file_id)
    content.write_to_file(meta.filename)   # lưu ra đĩa
    print(f"Downloaded: {meta.filename}")

Hội thoại nhiều lượt và pause_turn

  • Response chứa đối tượng container có id và expires_at. Để tái sử dụng container ở lượt sau, gửi "container": {"id": response1.container.id, "skills": [...]} kèm lịch sử hội thoại.
  • stop_reason: "pause_turn" nghĩa là một thao tác Skill chạy lâu đã bị tạm dừng. Hãy nối nội dung của assistant vào messages rồi gửi lại request với cùng container.id và Skills (vòng lặp có giới hạn số lần thử, ví dụ trong tài liệu là 10).
  • Nếu quên container.id, request chạy trong container mới và mất các file đã tạo trước đó trong lượt.
# Xử lý pause_turn: tiếp tục trong CÙNG container
messages = [{"role": "user", "content": "Phân tích file doanh thu và tạo báo cáo Excel"}]
skills = [{"type": "anthropic", "skill_id": "xlsx", "version": "latest"}]
tools = [{"type": "code_execution_20250825", "name": "code_execution"}]

response = client.messages.create(model="claude-opus-5-5", max_tokens=4096,
                                  container={"skills": skills}, messages=messages, tools=tools)
for _ in range(10):                         # giới hạn số lần tiếp tục
    if response.stop_reason != "pause_turn":
        break
    messages.append({"role": "assistant", "content": response.content})
    response = client.messages.create(model="claude-opus-5-5", max_tokens=4096,
                                      container={"id": response.container.id, "skills": skills},
                                      messages=messages, tools=tools)

import anthropic
from anthropic.lib import files_from_dir

client = anthropic.Anthropic()

# Tạo Skill từ thư mục (phải có SKILL.md ở gốc)
skill = client.skills.create(files=files_from_dir("financial_skill"))

# Phiên bản mới = BẢN ĐẦY ĐỦ (không phải delta), giữ nguyên name trong SKILL.md
new_version = client.skills.versions.create(skill_id=skill.id, files=files_from_dir("financial_skill"))

# Chỉ liệt kê custom Skill
for s in client.skills.list(source="custom"):
    print(s.id, s.display_name)

# Xóa Skill (xóa luôn mọi phiên bản)
client.skills.delete(skill_id=skill.id)

# .claude/skills/deploy/SKILL.md – ví dụ từ tài liệu Claude Code
---
name: deploy
description: Deploy the application to production
disable-model-invocation: true
allowed-tools: Bash(git status *) Bash(npm run build *)
argument-hint: [environment]
---

Deploy $ARGUMENTS to production:
1. Run the test suite
2. Build the application
3. Push to the deployment target

Giải thích: disable-model-invocation: true ⇒ chỉ chạy khi người dùng gõ /deploy (thao tác có tác dụng phụ không nên để Claude tự kích hoạt); allowed-tools chỉ duyệt trước đúng các lệnh cần thiết (nguyên tắc least privilege); /deploy staging ⇒ $ARGUMENTS = staging.

  • Thay thế chuỗi: $ARGUMENTS (toàn bộ đối số), $ARGUMENTS[N] / $N (đối số thứ N, đếm từ 0), ${CLAUDE_SKILL_DIR} (thư mục chứa SKILL.md — dùng để gọi script đi kèm bất kể Skill cài ở cấp nào).
  • Quan hệ với slash command: file trong .claude/commands/ vẫn chạy. Chuyển .claude/commands/deploy.md thành .claude/skills/deploy/SKILL.md vẫn giữ /deploy — nên chuyển khi lệnh cần file hỗ trợ.
  • Live reload: thêm/sửa/xóa Skill có hiệu lực ngay trong phiên; nếu Skill mới không hiện, chạy /reload-skills.
  • Ngân sách mô tả: phần description + when_to_use của mỗi Skill bị cắt ở 1.536 ký tự trong danh sách Skill; ngân sách cả danh sách bằng 1% context window của model ⇒ đặt từ khóa kích hoạt lên đầu.

Chọn Skill hay tính năng khác?

🎒Skill

  • Chuyên môn / quy trình tái sử dụng, nạp theo nhu cầu.
  • Có thể kèm script, template, tài liệu tham khảo.

🧠CLAUDE.md

  • Ngữ cảnh lâu dài (memory) của dự án.
  • Phù hợp quy ước luôn cần biết ở mọi phiên.

🪝Hooks

  • Chạy mỗi lần sự kiện xảy ra, bất kể Claude có làm theo Skill hay không.
  • Dùng cho quy tắc bắt buộc tuyệt đối.

🤖Subagents · MCP

  • Subagent: ủy thác tác vụ cho agent chuyên trách với context riêng.
  • MCP: kết nối tool và dữ liệu từ hệ thống bên ngoài.
Mẹo thực chiến (Pro Tip)

Skill được Claude theo ở lượt đầu nhưng bỏ qua một quy tắc phải luôn đúng ở các lượt sau ⇒ chuyển quy tắc đó thành hook (có thể khai báo ngay trong trường hooks của Skill). Với hướng dẫn cần phán đoán, viết sao cho áp dụng cho cả tác vụ ("Chạy test sau mỗi lần sửa" thay vì "Chạy test"). Sau khi hội thoại bị compact, gọi lại Skill để khôi phục nội dung — và đặt chỉ dẫn quan trọng nhất ở đầu SKILL.md.

Mẹo thực chiến (Pro Tip)

Skill không kích hoạt dù bạn nghĩ là nên ⇒ kiểm tra description có chứa từ khóa người dùng hay nói, hỏi "What skills are available?" để xem Skill có trong danh sách, gọi thẳng /skill-name, và chạy claude --debug. Skill kích hoạt quá thường xuyên ⇒ viết mô tả cụ thể hơn hoặc đặt disable-model-invocation: true.

✍️Skill authoring best practices

Skill tốt là Skill ngắn gọn, có cấu trúc tốt và được kiểm thử bằng sử dụng thực tế. Phần này dịch và tóm lược các quyết định quan trọng từ trang "Skill authoring best practices" của Anthropic.

1. Ngắn gọn là chìa khóa

Context window là "tài sản chung": Skill của bạn dùng chung với system prompt, lịch sử hội thoại, metadata của Skill khác và yêu cầu hiện tại. Giả định mặc định: Claude đã rất thông minh — chỉ thêm ngữ cảnh Claude chưa có. Hãy tự hỏi: "Claude có thật sự cần lời giải thích này?", "Đoạn này có xứng với số token nó tốn?"

✅Ngắn gọn (~50 token)

  • "Use pdfplumber for text extraction:" + 4 dòng code.
  • Giả định Claude đã biết PDF là gì và thư viện hoạt động thế nào.

❌Dài dòng (~150 token)

  • Giải thích PDF là định dạng gì, có nhiều thư viện, vì sao chọn pdfplumber, cách cài pip…
  • Tốn token mà không thêm thông tin mới.

2. Đặt mức tự do phù hợp (degrees of freedom)

MediumPseudocode / script có tham sốCó mẫu ưu tiên nhưng chấp nhận biến thểSinh báo cáo theo template

Ví dụ đời thường (từ tài liệu Anthropic)

Hãy coi Claude như robot khám phá đường đi. Cây cầu hẹp hai bên là vực: chỉ có một lối an toàn ⇒ rào chắn cụ thể, chỉ dẫn chính xác (low freedom). Cánh đồng rộng không chướng ngại: nhiều đường đều tới đích ⇒ chỉ hướng chung và tin Claude tự tìm đường (high freedom).

3. Đặt tên và viết description

  • Tên: nên dùng dạng gerund (động từ + -ing): processing-pdfs, analyzing-spreadsheets, writing-documentation. Chấp nhận cụm danh từ (pdf-processing) hoặc dạng hành động (process-pdfs). Tránh tên mơ hồ (helper, utils), quá chung (documents, data), chứa từ dành riêng (claude-tools).
  • Description luôn viết ở ngôi thứ ba, vì nó được chèn vào system prompt — đổi ngôi có thể gây lỗi phát hiện Skill. Tốt: "Processes Excel files and generates reports". Tránh: "I can help you…", "You can use this to…".
  • Cụ thể, có từ khóa và ngữ cảnh kích hoạt: Claude dùng description để chọn đúng Skill trong số có thể hơn 100 Skill.
✅ tốtdescription: Generate descriptive commit messages by analyzing git diffs. Use when the user asks for help writing commit messages or reviewing staged changes.
❌ mơ hồdescription: Helps with documents
❌ sai ngôidescription: I can help you process Excel files

4. Progressive disclosure trong thực hành

< 500dòng: giới hạn khuyến nghị cho phần thân SKILL.md
1 cấpđộ sâu tham chiếu từ SKILL.md tới file khác
> 100dòng: file tham khảo dài hơn mức này nên có mục lục ở đầu
  • Pattern 1 – Hướng dẫn tổng quan kèm tham chiếu: SKILL.md có quick start, trỏ sang FORMS.md, REFERENCE.md, EXAMPLES.md.
  • Pattern 2 – Tổ chức theo lĩnh vực: reference/finance.md, sales.md, product.md… Hỏi về sales thì chỉ đọc file sales.
  • Pattern 3 – Chi tiết có điều kiện: nội dung cơ bản trong SKILL.md, phần nâng cao (vd tracked changes) ở file riêng.
  • Tránh tham chiếu lồng sâu: khi gặp file được tham chiếu từ file khác, Claude có thể chỉ xem trước (vd head -100) và bỏ sót thông tin.

5. Workflow, checklist và vòng phản hồi

Chia thao tác phức tạp thành bước tuần tự rõ ràng; với workflow rất phức tạp, cung cấp checklist để Claude chép vào câu trả lời và đánh dấu dần. Mẫu phổ biến của feedback loop: chạy validator → sửa lỗi → lặp lại. Với tác vụ hàng loạt hoặc có tính phá hủy, dùng mẫu plan → validate → execute: Claude tạo file kế hoạch có cấu trúc (vd changes.json), script kiểm tra kế hoạch rồi mới thực thi.

## PDF form filling workflow (trích từ best practices)
Copy this checklist and check off items as you complete them:
- [ ] Step 1: Analyze the form (run analyze_form.py)
- [ ] Step 2: Create field mapping (edit fields.json)
- [ ] Step 3: Validate mapping (run validate_fields.py)
- [ ] Step 4: Fill the form (run fill_form.py)
- [ ] Step 5: Verify output (run verify_output.py)
If verification fails, return to Step 2.

6. Xây eval trước, lặp với Claude A / Claude B

  1. Identify gaps – chạy Claude trên tác vụ đại diện khi chưa có Skill, ghi lại các thất bại cụ thể.
  2. Create evaluations – xây ba kịch bản kiểm tra đúng các lỗ hổng đó.
  3. Establish baseline – đo hiệu năng khi chưa có Skill.
  4. Write minimal instructions – chỉ viết vừa đủ để lấp lỗ hổng và qua eval.
  5. Iterate – chạy eval, so với baseline, tinh chỉnh. Kiểm thử với mọi model định dùng (Haiku, Sonnet, Opus): cái chạy tốt với Opus có thể cần chi tiết hơn cho Haiku.

Hiện chưa có cách tích hợp sẵn để chạy các eval này trên API — bạn tự xây hệ thống đánh giá. Trong Claude Code, plugin skill-creator hỗ trợ viết test case, chạy cô lập bằng subagent, chấm điểm và so sánh có/không có Skill.

7. Anti-pattern và Skill có code

  • Không dùng đường dẫn kiểu Windows (scripts\helper.py) — luôn dùng dấu /.
  • Không đưa quá nhiều lựa chọn ("dùng pypdf, hoặc pdfplumber, hoặc PyMuPDF…") — đưa một mặc định kèm lối thoát cho trường hợp đặc biệt.
  • Tránh thông tin nhạy cảm theo thời gian ("trước tháng 8/2025 thì…") — dùng mục "Old patterns".
  • Thuật ngữ nhất quán: luôn "field", không trộn "field / box / element".
  • Solve, don't defer: script tự xử lý lỗi thay vì để Claude đoán; tránh "voodoo constants" — giải thích vì sao REQUEST_TIMEOUT = 30.
  • Nói rõ ý định: "Run analyze_form.py" (chạy) khác "See analyze_form.py for the algorithm" (đọc tham khảo).
  • MCP tool: luôn dùng tên đầy đủ ServerName:tool_name (vd GitHub:create_issue) để tránh lỗi "tool not found" khi có nhiều MCP server.

🛡️Bảo mật khi dùng Skills

Skill cấp cho Claude năng lực mới qua hướng dẫn và code — điều đó cũng có nghĩa một Skill độc hại có thể điều khiển Claude gọi tool hoặc chạy code theo cách không khớp mục đích đã nêu. Tài liệu Anthropic khuyến nghị chỉ dùng Skill từ nguồn tin cậy: do chính bạn tạo hoặc lấy từ Anthropic.

🔎

Audit thoroughly

Kiểm tra kỹ toàn bộ

Rà mọi file: SKILL.md, script, hình ảnh, tài nguyên. Tìm lệnh gọi mạng bất thường, truy cập file lạ, thao tác không khớp mục đích.

🌍

External sources are risky

Nguồn bên ngoài rủi ro

Skill tải dữ liệu từ URL ngoài có thể nhận nội dung chứa lệnh độc hại (prompt injection); dependency có thể bị thay đổi theo thời gian.

🧨

Tool misuse · Data exposure

Lạm dụng tool · Lộ dữ liệu

Skill độc hại có thể dùng file, bash, code execution gây hại hoặc gửi dữ liệu nhạy cảm ra hệ thống ngoài.

💿

Treat like installing software

Coi như cài phần mềm

Đặc biệt cẩn trọng khi tích hợp vào production có dữ liệu nhạy cảm hoặc thao tác quan trọng.

Lỗi thường gặp

Tải một Skill "tiện ích" từ repo lạ rồi cài thẳng vào ~/.claude/skills/ kèm allowed-tools: Bash(*). Trong Claude Code, Skill có toàn quyền mạng như mọi chương trình trên máy bạn ⇒ nguy cơ rò rỉ dữ liệu. Hãy đọc từng file, giới hạn allowed-tools ở mức tối thiểu (least privilege) và không cấp quyền rộng hơn cần thiết.

Với quy mô tổ chức, Anthropic có trang "Skills for enterprise" về quản trị, thẩm định và triển khai; tổ chức Claude Enterprise có thể bật Skill content scanning cho custom Skill upload trên claude.ai và Claude Cowork (không áp dụng cho Skill upload qua Skills API hay Claude Console).

  2. Bài tập 2 – Skill nhiều file theo progressive disclosure. Mở rộng thành thư mục analyzing-sales/ gồm SKILL.md (dưới 500 dòng, có mục "Available datasets"), reference/sales.md, reference/finance.md và scripts/validate.py. Trong SKILL.md ghi rõ: "Run python ${CLAUDE_SKILL_DIR}/scripts/validate.py".   3. Bài tập 3 – Gọi Skill dựng sẵn qua API. Kết quả mong đợi: danh sách mục đạt/chưa đạt và bản sửa cho từng mục chưa đạt.

Tóm tắt ghi nhớ

Key takeaways
  • Agent Skill = thư mục có SKILL.md (YAML frontmatter + hướng dẫn) và file tùy chọn (tài liệu, script, template); Claude tự dùng khi yêu cầu khớp description.
  • Progressive disclosure: Level 1 metadata (~100 token/Skill, luôn nạp) → Level 2 thân SKILL.md (< 5k token, khi kích hoạt) → Level 3 tài nguyên (0 token tới khi đọc; script chỉ tốn output).
  • name: ≤ 64 ký tự, chữ thường/số/gạch ngang, không XML, không chứa anthropic/claude. description: không rỗng, ≤ 1.024 ký tự, không XML, nói "làm gì + khi nào".
  • API: container.skills (type, skill_id, version) + bắt buộc code execution tool; tối đa 20 Skill/request; container không mạng, không cài package; custom Skill phạm vi workspace.
  • Claude Code: ~/.claude/skills/ (cá nhân), .claude/skills/ (dự án), plugin; gọi /skill-name; allowed-tools, disable-model-invocation.
  • Custom Skill không đồng bộ giữa claude.ai, API và Claude Code.
  • Best practices: ngắn gọn; mức tự do theo độ "mong manh" của tác vụ; tên gerund; description ngôi thứ ba; thân < 500 dòng; tham chiếu 1 cấp; eval trước; lặp Claude A/B; test mọi model.
  • Bảo mật: chỉ dùng Skill tin cậy, audit mọi file, cẩn trọng nguồn ngoài (prompt injection), least privilege.

Thuật ngữ (Glossary)

Agent Skills
Kỹ năng cho agent – gói năng lực mô-đun (hướng dẫn, metadata, tài nguyên) mở rộng chức năng của Claude, được nạp theo nhu cầu.
SKILL.md
File định nghĩa Skill – file bắt buộc, gồm YAML frontmatter và phần thân hướng dẫn.
YAML frontmatter
Phần đầu YAML – khối giữa hai dòng --- ở đầu file chứa name, description.
Progressive disclosure
Tiết lộ dần dần – nạp thông tin theo tầng, chỉ khi cần, để tiết kiệm context window.
Metadata (Level 1)
Siêu dữ liệu – name + description, luôn nằm trong system prompt.
Bundled files / Resources
File đi kèm / tài nguyên – tài liệu tham khảo, script, template trong thư mục Skill (Level 3).
Pre-built Agent Skills
Skill dựng sẵn – pptx, xlsx, docx, pdf do Anthropic cung cấp.
Custom Skills
Skill tùy chỉnh – Skill do bạn/tổ chức tự viết.
Skills API
API quản lý Skill – các endpoint /v1/skills để tạo, liệt kê, tạo phiên bản, xóa custom Skill.
Code execution tool
Công cụ thực thi mã – server tool cung cấp container nơi Skills chạy; bắt buộc khi dùng Skills qua API.
Container
Vùng chứa thực thi – môi trường sandbox có id, expires_at; tái sử dụng qua container.id.
pause_turn
Tạm dừng lượt – stop_reason báo thao tác dài bị tạm dừng; gửi lại với cùng container để tiếp tục.
Degrees of freedom
Mức độ tự do – mức chi tiết của chỉ dẫn (high / medium / low) tùy độ mong manh của tác vụ.
Feedback loop
Vòng phản hồi – chạy validator → sửa → lặp lại cho tới khi đạt.
allowed-tools
Tool được phép – trường frontmatter Claude Code phê duyệt trước một số tool khi Skill chạy.
disable-model-invocation
Tắt tự kích hoạt – true thì chỉ người dùng gọi Skill bằng /skill-name.
Surface
Bề mặt sản phẩm – nơi dùng Claude: Claude API, Claude Code, claude.ai… Custom Skill không đồng bộ giữa các surface.
Least privilege
Đặc quyền tối thiểu – chỉ cấp đúng quyền/tool cần cho tác vụ.

Câu hỏi luyện tập

Nhóm tài chính của một công ty cài 40 custom Skill cho Claude. Một kỹ sư lo rằng 40 Skill sẽ "ngốn" hết context window ngay từ đầu mỗi cuộc hội thoại. Nhận định nào đúng?
  1. Đúng, toàn bộ nội dung SKILL.md của cả 40 Skill được nạp vào system prompt lúc khởi động.
  2. Không, lúc khởi động chỉ name và description của mỗi Skill (~100 token/Skill) được nạp; thân SKILL.md chỉ vào context khi Skill được kích hoạt.
  3. Không, vì Skill hoàn toàn không tốn token kể cả khi được kích hoạt.
  4. Đúng, nên phải gộp 40 Skill thành một file SKILL.md duy nhất.
Đáp án B. Đây là progressive disclosure: Level 1 (metadata, ~100 token/Skill) luôn nạp; Level 2 (< 5k token) chỉ khi kích hoạt; Level 3 khi cần. A sai vì thân SKILL.md không nạp sẵn. Đoạn code gọi Messages API dưới đây trả lỗi vì không thể dùng Skill. Cần sửa gì?

Skill của bạn hướng dẫn migration database phải chạy đúng trình tự, sai một bước là hỏng dữ liệu. Theo khái niệm "degrees of freedom", nên viết Skill thế nào?
  1. High freedom: liệt kê vài nguyên tắc chung, để Claude tự chọn cách làm.
  2. Medium freedom: đưa pseudocode để Claude tự viết script.
  3. Low freedom: cung cấp script cụ thể, ít tham số, kèm "Run exactly this script… Do not modify the command".
  4. Không dùng Skill; viết hướng dẫn vào mỗi prompt.

Một bạn đồng nghiệp gửi link Skill "auto-reporting" trên GitHub cá nhân, bên trong có script gọi tới một URL lạ. Bạn định dùng trong Claude Code trên máy có quyền truy cập dữ liệu khách hàng. Hành động phù hợp nhất?
