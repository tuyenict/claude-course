🧭Bức tranh tổng thể: mở rộng Claude Code theo nhiều tầng

Claude Code "nguyên bản" đã đọc code, sửa file và chạy lệnh rất tốt. Nhưng mỗi nhóm có quy trình riêng: checklist release, cách review, quy ước commit, công cụ nội bộ. Thay vì gõ lại cùng một prompt dài mỗi ngày, bạn đóng gói kiến thức đó thành các thành phần tái sử dụng được.

Tài liệu Claude Code mô tả một bộ công cụ mở rộng gồm nhiều lớp. Bài này tập trung vào bốn lớp "hướng dẫn và ủy quyền": slash commands, skills, subagents, plugins — cộng thêm output styles. Hai lớp còn lại (hooks và MCP) được học kỹ ở Bài 39.

⌘Custom slash commands và $ARGUMENTS

Slash command là lệnh bắt đầu bằng / ở đầu tin nhắn. Claude Code có sẵn nhiều built-in commands và cho phép bạn tự tạo lệnh riêng.

Built-in commands hay dùng

Gõ / để xem danh sách; chỉ phần đầu tin nhắn mới được nhận là lệnh, phần chữ phía sau trở thành tham số. Một số lệnh liên quan trực tiếp tới bài này:

LệnhTác dụng (theo trang Commands)
/skillsLiệt kê skills hiện có, lọc theo tên/mô tả/nguồn; có thể sắp xếp theo số token.
/reload-skillsQuét lại thư mục skill và command để dùng skill vừa thêm/sửa mà không cần khởi động lại.
/agentsNhắc bạn nhờ Claude tạo/quản lý subagent hoặc sửa trực tiếp .claude/agents/, ~/.claude/agents/ (bản v2.1.197 trở về trước mở giao diện wizard).
/pluginMở trình quản lý plugin (tab Discover, Installed, Marketplaces, Errors) hoặc chạy lệnh con như install, enable, disable.
/reload-pluginsNạp lại plugin đang bật để áp dụng thay đổi mà không khởi động lại.
/output-style [style]Liệt kê hoặc chuyển output style, vd /output-style concise.
/compact, /context, /clearQuản lý context window (đã học ở bài trước) — rất liên quan khi dùng nhiều skill/subagent.

Tự tạo command: file Markdown trong .claude/commands/

Đây là định dạng có từ đầu: mỗi file Markdown là một lệnh, tên file trở thành tên lệnh. Thư mục con tạo namespace:

  • .claude/commands/deploy.md → /deploy
  • .claude/commands/frontend/component.md → /frontend:component
Cập nhật quan trọng: commands đã được gộp vào skills

Theo tài liệu hiện hành, custom commands đã được hợp nhất vào skills. File trong .claude/commands/ vẫn hoạt động, và Claude cũng có thể tự gọi chúng. Nếu một skill và một command trùng tên, skill được ưu tiên. Với việc mới, Anthropic khuyên dùng skill vì skill hỗ trợ thêm file đi kèm (supporting files). Muốn nâng cấp: chuyển .claude/commands/deploy.md thành .claude/skills/deploy/SKILL.md — bạn vẫn gõ /deploy như cũ.

Frontmatter của command

File command nhận cùng các trường frontmatter như skill (trừ name và paths). Ví dụ một lệnh sửa issue GitHub:

# .claude/commands/fix-issue.md
---
description: Fix a GitHub issue          # Claude dựa vào đây để biết khi nào dùng
argument-hint: [issue-number]            # gợi ý hiện khi gõ lệnh (autocomplete)
allowed-tools: Bash(gh *) Read Edit      # tool được dùng không cần hỏi quyền trong lượt này
disable-model-invocation: true           # chỉ người dùng gọi, Claude không tự chạy
---

Fix GitHub issue $ARGUMENTS following our coding standards.

Khi gõ /fix-issue 123, chuỗi $ARGUMENTS được thay bằng 123 trước khi gửi cho Claude.

Các biến thay thế tham số

BiếnÝ nghĩaVí dụ với /migrate SearchBar JavaScript TypeScript
$ARGUMENTSToàn bộ chuỗi tham số đúng như đã gõSearchBar JavaScript TypeScript
$ARGUMENTS[N] / $NTham số theo vị trí, đánh số từ 0$0 = SearchBar, $1 = JavaScript, $2 = TypeScript
$nameTham số có tên, khai báo trong trường arguments, ánh xạ theo thứ tựarguments: [component, from, to] → $component, $from, $to
${CLAUDE_SKILL_DIR}Thư mục chứa SKILL.md (dùng để gọi script đi kèm)python3 ${CLAUDE_SKILL_DIR}/scripts/x.py
${CLAUDE_SESSION_ID}, ${CLAUDE_PROJECT_DIR}ID phiên hiện tại; thư mục gốc dự ánGhi log theo phiên, đường dẫn tuyệt đối
  • Nếu nội dung không có placeholder nào nhận tham số, Claude Code tự nối thêm ARGUMENTS: <giá trị> vào cuối.
  • Giá trị nhiều từ cần đặt trong ngoặc kép: /my-skill "hello world" second → $0 = hello world, $1 = second.
  • Muốn viết ký hiệu đô la trước chữ số (vd giá tiền) thì escape: \$1.00.
Lỗi thường gặp

Nhiều hướng dẫn cũ trên mạng viết $1 là tham số đầu tiên. Theo tài liệu hiện hành, chỉ số bắt đầu từ 0: $0 là tham số đầu, $1 là tham số thứ hai. Viết sai sẽ khiến lệnh "lệch" một vị trí mà không báo lỗi.

Chèn ngữ cảnh động bằng !`lệnh`

Cú pháp !`<command>` chạy lệnh shell trước khi nội dung được gửi cho Claude; kết quả thay vào chỗ placeholder. Claude chỉ thấy dữ liệu, không thấy lệnh. Với lệnh nhiều dòng, dùng khối code mở bằng ```!.

# .claude/skills/summarize-changes/SKILL.md
---
name: summarize-changes
description: Summarizes uncommitted changes and flags anything risky. Use when the user asks what changed, wants a commit message, or asks to review their diff.
---

## Current changes

!`git diff HEAD`          # chạy trước, output diff được chèn vào đây

## Instructions

Summarize the changes above in two or three bullet points, then list any risks you notice.
  • Dấu ! phải đứng đầu dòng hoặc sau khoảng trắng; trong KEY=!`cmd` sẽ không có gì chạy.
  • Lệnh trả mã thoát khác 0 (trừ một số lệnh tìm kiếm trả 1) sẽ hủy toàn bộ lần gọi. Thêm || true nếu lỗi là bình thường.
  • Quản trị viên có thể tắt tính năng này bằng "disableSkillShellExecution": true trong settings.
Mẹo thực chiến (Pro Tip)

Lệnh review PR luôn cần diff mới nhất ⇒ dùng !`gh pr diff` trong skill thay vì bảo Claude "hãy tự chạy gh pr diff". Dữ liệu có sẵn ngay ở lượt đầu, tiết kiệm một vòng tool call và tránh Claude quên bước.

🎒Agent Skills: SKILL.md và progressive disclosure

Theo bài kỹ thuật của Anthropic, Agent Skills là "các thư mục có tổ chức gồm hướng dẫn, script và tài nguyên" mà agent có thể khám phá và nạp khi nhiệm vụ cần — giống như tài liệu onboarding cho nhân viên mới. Skills theo chuẩn mở Agent Skills (agentskills.io) và được hỗ trợ trên Claude.ai, Claude Code, Claude Agent SDK và Claude Developer Platform.

Cấu trúc một skill

Mỗi skill là một thư mục có file SKILL.md: phần frontmatter YAML nằm giữa hai dòng --- (bắt buộc bắt đầu ở dòng đầu tiên của file), theo sau là hướng dẫn Markdown. Có thể kèm file phụ:

my-skill/
├── SKILL.md          # tổng quan + điều hướng (bắt buộc)
├── reference.md      # chỉ đọc khi cần
├── examples.md       # chỉ đọc khi cần
└── scripts/
    └── helper.py     # được THỰC THI, không nạp nội dung vào context

Tài liệu khuyên giữ SKILL.md dưới 500 dòng, chuyển chi tiết sang file phụ mà SKILL.md tham chiếu tới.

Progressive disclosure – ba mức nạp thông tin

Ví dụ trong bài viết của Anthropic: PDF skill có SKILL.md tham chiếu tới reference.md và forms.md. Hướng dẫn điền form nằm trong forms.md, nên Claude chỉ đọc file đó khi thực sự phải điền form. Skill còn có script trích xuất trường form — Claude chạy script mà không cần nạp script hay file PDF vào context. Code mang tính tất định và rẻ hơn so với việc sinh cùng kết quả bằng token.

Ví dụ đời thường

Progressive disclosure giống mục lục của một cuốn cẩm nang: bạn luôn thấy tên chương (metadata), chỉ mở chương khi cần (SKILL.md), và chỉ lật đến phụ lục (file phụ) khi gặp tình huống đặc biệt.

Mẹo thực chiến (Pro Tip)

Skill có tác dụng phụ (deploy production, gửi email, xóa dữ liệu) ⇒ đặt disable-model-invocation: true để chỉ người mới kích hoạt được. Skill kiến thức nền (quy ước API nội bộ) mà người dùng không cần gõ ⇒ user-invocable: false.

Chạy skill trong subagent với context: fork

---
name: deep-research
description: Research a topic thoroughly
context: fork          # nội dung skill trở thành prompt của một subagent mới
agent: Explore         # loại subagent: Explore, Plan, general-purpose hoặc agent tự tạo
---

Research $ARGUMENTS thoroughly:
1. Find relevant files using Glob and Grep
2. Read and analyze the code
3. Summarize findings with specific file references

Subagent này không thấy lịch sử hội thoại nên hướng dẫn phải tự đủ nghĩa. Theo tài liệu, nó chạy nền (background) mặc định; đặt background: false để chờ kết quả ngay trong lượt.

Ngân sách mô tả skill

Claude Code nạp danh sách tên + mô tả của mọi skill vào context. Danh sách luôn chứa mọi tên, nhưng nếu quá nhiều skill, một số mô tả bị bỏ để vừa ngân sách ký tự — theo tài liệu, ngân sách bằng 1% context window của model (chỉnh bằng skillListingBudgetFraction hoặc biến môi trường SLASH_COMMAND_TOOL_CHAR_BUDGET). Mô tả của skill ít dùng nhất bị bỏ trước. Dùng /doctor hoặc /skill-doctor để xem skill nào tốn chỗ.

3mức progressive disclosure (metadata → SKILL.md → file phụ)
< 500dòng: độ dài khuyến nghị cho SKILL.md
1.536ký tự: giới hạn description + when_to_use trong danh sách
1%context window: ngân sách danh sách skill mặc định

Skill không kích hoạt? Checklist từ tài liệu

  1. Description có chứa từ khóa người dùng hay nói tự nhiên không?
  2. Hỏi Claude "What skills are available?" để xem skill có trong danh sách.
  3. Diễn đạt lại yêu cầu sát với description, hoặc gọi thẳng /skill-name.
  4. YAML frontmatter lỗi cú pháp ⇒ skill nạp với metadata rỗng: /skill-name vẫn chạy nhưng Claude không khớp được description. Chạy claude --debug hoặc claude plugin validate .claude/skills.
  5. Skill kích hoạt quá thường xuyên ⇒ viết description cụ thể hơn hoặc thêm disable-model-invocation: true.
Lưu ý về compaction

Nội dung skill được thêm vào hội thoại khi gọi và không được đọc lại ở các lượt sau. Sau khi compaction, Claude Code có thể chỉ giữ phần đầu skill ⇒ đặt chỉ dẫn quan trọng nhất ở đầu SKILL.md. Quy tắc phải được tuân thủ 100% thì chuyển thành hook.

👥Subagents: phụ tá có context window riêng

Subagent là trợ lý AI chuyên trách một loại việc. Mỗi subagent chạy trong context window riêng với system prompt riêng, quyền truy cập tool riêng và quyền hạn độc lập. Khi Claude gặp việc khớp với description của subagent, nó ủy quyền; subagent làm độc lập rồi trả kết quả về.

File subagent: frontmatter + system prompt

# .claude/agents/code-reviewer.md
---
name: code-reviewer                # bắt buộc, không chứa ":" và không bắt đầu bằng "-"
description: Reviews code for quality and best practices. Use proactively after code changes.
tools: Read, Glob, Grep            # allowlist; bỏ trống = kế thừa mọi tool
model: sonnet                      # sonnet | opus | haiku | fable | full model ID | inherit
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.

Phần thân Markdown trở thành system prompt của subagent. Chỉ name và description là bắt buộc. Một số trường khác:

TrườngÝ nghĩa
disallowedToolsDenylist, loại khỏi tập tool kế thừa hoặc tập đã liệt kê.
permissionModedefault, acceptEdits, auto, dontAsk, bypassPermissions, plan. Bị bỏ qua với subagent của plugin.
maxTurnsSố lượt agentic tối đa trước khi dừng.
skillsSkill được nạp sẵn toàn bộ nội dung vào context của subagent khi khởi động.
mcpServers, hooksMCP server và hook (PreToolUse, PostToolUse, Stop) riêng cho subagent. Bị bỏ qua với subagent của plugin.
memoryBộ nhớ lâu dài theo phạm vi user, project hoặc local.
isolation: worktreeChạy subagent trong một git worktree tạm thời.
background, effort, colorLuôn chạy nền; mức effort; màu hiển thị.

Thứ tự chọn model: tham số model của lần gọi → trường model trong file → biến CLAUDE_CODE_SUBAGENT_MODEL → model của hội thoại cha.

Built-in subagents

SubagentToolsMục đích

Cách gọi subagent

  • Tự động: Claude so yêu cầu với description. Cụm như "use proactively" trong description khuyến khích Claude ủy quyền chủ động.
  • Ngôn ngữ tự nhiên: "Use the code-reviewer subagent to check my recent changes."
  • @-mention: @"code-reviewer (agent)" look at the auth changes
  • Cả phiên là subagent: claude --agent code-reviewer hoặc "agent": "code-reviewer" trong .claude/settings.json.
  • Định nghĩa tạm bằng CLI: cờ --agents nhận JSON gồm description, prompt, tools, model; chỉ tồn tại trong phiên đó.

Foreground, background, resume và giới hạn

  • Foreground chặn hội thoại chính, prompt xin quyền chuyển thẳng cho bạn. Background chạy song song; nhấn Ctrl+B để đẩy tác vụ đang chạy xuống nền.
  • Mỗi lần gọi tạo instance mới, trừ khi resume: subagent được tiếp tục giữ toàn bộ lịch sử trước đó.
  • Lồng nhau: theo tài liệu hiện hành, subagent có thể tạo subagent, mặc định tối đa 3 tầng dưới hội thoại chính (CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH; đặt 1 để tắt lồng nhau).
  • Đồng thời: mặc định tối đa 20 subagent chạy cùng lúc (CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS).
  • Nếu tổng description của các subagent tự tạo vượt 15.000 token, Claude Code cảnh báo khi khởi động ⇒ giữ description ngắn, để chi tiết trong system prompt.

Các giới hạn trên theo tài liệu Subagents, kiểm tra ngày 2026-11-20; có thể thay đổi theo phiên bản.

Mẹo thực chiến (Pro Tip)

Cần quét toàn bộ codebase để tìm nơi dùng một API cũ, nhưng không muốn hàng nghìn dòng kết quả làm đầy context ⇒ giao cho subagent Explore (chỉ đọc) và chỉ nhận danh sách file + dòng. Cần review sau mỗi lần sửa code ⇒ subagent code-reviewer với description có "Use proactively after code changes".

Lỗi thường gặp

Viết delegation hoặc system prompt kiểu "sửa lỗi mình vừa nói ở trên". Subagent (không phải fork) không thấy lịch sử hội thoại, skill đã gọi hay file đã đọc. Hãy để Claude truyền đủ ngữ cảnh trong thông điệp ủy quyền, hoặc viết system prompt tự đủ nghĩa.

🔌Plugins: đóng gói và phân phối

Một plugin của Claude Code là một thư mục chứa skills, agents, hooks, MCP servers hoặc các thành phần khác, được Claude Code cài và nạp như một đơn vị. Phần lớn plugin đến từ một marketplace — một danh mục liệt kê plugin và nơi tải từng plugin.

Khi nào cần plugin?

Skills, subagents, hooks và MCP server đều chạy được độc lập mà không cần plugin. Theo tài liệu: giữ cấu hình độc lập khi nó chỉ phục vụ một dự án hoặc chỉ mình bạn; tạo plugin khi muốn chia sẻ cho đồng đội, cài vào nhiều dự án, hoặc phát hành theo phiên bản.

📁Cấu hình độc lập (.claude/)

  • Đặt trong .claude/skills/, .claude/agents/, settings…
  • Tên ngắn: /deploy, agent reviewer
  • Hợp với một dự án / một người
  • Không cần manifest

🔌Plugin

  • Thư mục riêng có .claude-plugin/plugin.json
  • Tên có tiền tố: /my-plugin:deploy, my-plugin:reviewer
  • Hợp để chia sẻ nhóm, nhiều dự án, có phiên bản
  • Cài một lệnh, nhận cập nhật từ marketplace

Cấu trúc thư mục plugin

my-first-plugin/
├── .claude-plugin/
│   └── plugin.json      # manifest – CHỈ file này nằm trong .claude-plugin/
├── skills/
│   └── hello/SKILL.md   # → /my-first-plugin:hello
├── commands/            # dạng cũ của skills (file Markdown phẳng)
├── agents/
│   └── reviewer.md      # → subagent my-first-plugin:reviewer
├── hooks/hooks.json     # khóa "hooks" cùng cấu trúc như trong settings
└── .mcp.json            # định nghĩa MCP server
// my-first-plugin/.claude-plugin/plugin.json
{
  "name": "my-first-plugin",          // bắt buộc; thành tiền tố của mọi skill/agent; không có dấu cách
  "description": "A greeting plugin to learn the basics",
  "version": "1.0.0",                  // tùy chọn; giữ người dùng ở phiên bản này đến khi bạn đổi
  "author": { "name": "Your Name" }
}
Lỗi thường gặp

Đặt skills/, agents/… bên trong .claude-plugin/. Theo tài liệu, chỉ plugin.json nằm trong đó; thành phần đặt ở đây không được nạp — triệu chứng là "plugin nạp được nhưng mất skill". Chuyển chúng ra thư mục gốc plugin rồi chạy /reload-plugins.

Quy trình tạo và thử plugin

# Kiểm tra manifest và frontmatter của mọi skill/agent/command
claude plugin validate ./my-first-plugin

# Nạp plugin cho MỘT phiên (không cài đặt); lặp cờ để nạp nhiều plugin
claude --plugin-dir ./my-first-plugin

# Trong phiên:
/my-first-plugin:hello      # gọi skill có namespace
/reload-plugins             # áp dụng thay đổi trên đĩa
/plugin                     # tab Installed / Errors để chẩn đoán

Chuyển cấu hình .claude/ sẵn có thành plugin

  1. Tạo khung – mkdir -p my-plugin/.claude-plugin và viết plugin.json.
  2. Sao chép – cp -r .claude/commands .claude/agents .claude/skills my-plugin/ (thư mục nào có thì chép).
  3. Chuyển hooks – chép object hooks trong settings sang my-plugin/hooks/hooks.json (cùng định dạng).
  4. Thử – claude --plugin-dir ./my-plugin; skill cũ /deploy giờ là /my-plugin:deploy.
  5. Dọn dẹp – xóa bản gốc trong .claude/. Lưu ý: hook không có tiền tố, nên nếu còn ở cả hai nơi thì sẽ chạy hai lần.

Marketplace, phạm vi cài đặt và chi phí context

  • Marketplace là repo/thư mục có .claude-plugin/marketplace.json. Claude Code tự thêm marketplace chính thức của Anthropic (claude-plugins-official) ở lần chạy terminal tương tác đầu tiên (trừ khi chính sách quản trị chặn). Cài theo tên, vd commit-commands@claude-plugins-official.
  • Ba scope cài đặt: User (mọi dự án trên máy), Project (mọi người trong repo, qua .claude/settings.json đã commit), Local (chỉ bạn, trong repo này).
  • Plugin đã bật là một phần của mọi phiên: tên + mô tả của mỗi skill/agent mà Claude tự gọi được luôn nằm trong context; MCP server của plugin chạy kèm; hook của plugin luôn kích hoạt. Tắt bằng /plugin hoặc claude plugin disable khi không dùng.
Mẹo thực chiến (Pro Tip)

Nhóm 10 người cần cùng bộ skill review + subagent bảo mật + hook format code ⇒ đóng gói thành plugin trong marketplace nội bộ, cài ở scope Project. Mỗi người chỉ chạy một lệnh install và tự nhận bản cập nhật, thay vì copy thư mục .claude/ thủ công.

Output style là bộ chỉ dẫn quy định vai trò, giọng điệu và định dạng cho mọi phản hồi trong một phiên. Claude Code có style Default và bốn style dựng sẵn khác; bạn cũng có thể tự viết.

Bảo mật: skill và plugin là code chạy với quyền của bạn

  • Chỉ cài từ nguồn tin cậy. Bài kỹ thuật của Anthropic cảnh báo skill có thể đưa vào lỗ hổng hoặc hướng Claude rò rỉ dữ liệu (exfiltrate). Với skill ít tin cậy, hãy kiểm tra toàn bộ file đi kèm — đặc biệt là script, dependency và mọi chỉ dẫn kết nối mạng ra ngoài.
  • Plugin chạy với quyền người dùng của bạn, dù thuộc tier nào (official, community, third-party). Tên marketplace chính thức chỉ được chấp nhận khi lấy từ github.com/anthropics/.
  • Prompt injection: nội dung mà skill/subagent đọc vào (diff PR, issue, trang web, output của !`cmd`) có thể chứa chỉ dẫn độc hại. Coi đó là dữ liệu, không phải mệnh lệnh; giới hạn tool để dù bị lừa, agent cũng không làm được việc nguy hiểm.
  • Least privilege (đặc quyền tối thiểu): subagent chỉ đọc thì khai báo tools: Read, Grep, Glob; allowed-tools của skill thu hẹp theo mẫu (Bash(gh *) thay vì Bash); skill có tác dụng phụ đặt disable-model-invocation: true.
  • Vì lý do bảo mật, subagent của plugin bỏ qua hooks, mcpServers, permissionMode. Quản trị viên có thể tắt !`cmd` bằng disableSkillShellExecution, chặn skill qua rule Skill(...) trong permissions, chặn subagent bằng Agent(name) trong permissions.deny.
  • Không hard-code API key/token trong SKILL.md hay file agent (chúng thường được commit). Dùng biến môi trường hoặc cơ chế secret của hệ thống.
user/review-pr 482

assistantMình đã review PR #482. Lưu ý: file utils.js chứa một comment cố ra lệnh cho AI reviewer push lên main — đây là dấu hiệu prompt injection, mình không làm theo. Skill này chỉ được cấp Bash(gh pr view *), Read nên cũng không có quyền push.
Mẹo thực chiến (Pro Tip)

Muốn một quy tắc "không bao giờ sửa file migration" được tuân thủ tuyệt đối ⇒ đừng chỉ ghi vào skill hay output style (đó là chỉ dẫn, không cưỡng chế). Dùng hook PreToolUse hoặc rule deny trong permissions.

🧪Thực hành

  1. Bài tập 1 – Skill có tham số và ngữ cảnh động. Tạo .claude/skills/commit-msg/SKILL.md: 
    ---
name: commit-msg
description: Draft a Conventional Commits message for the staged changes. Use when the user asks for a commit message.
argument-hint: [type]
allowed-tools: Bash(git diff *)
---

## Staged changes
!`git diff --cached`

## Task
Write ONE commit message of type "$0" (feat, fix, docs…) for the changes above.
Subject line ≤ 72 characters, then a short body explaining WHY.
    Kết quả mong đợi: sau khi git add vài file, gõ /commit-msg fix → Claude trả về message bắt đầu bằng fix: dựa đúng trên diff đã stage. Chạy /skills thấy commit-msg trong danh sách. Thử khi chưa stage gì: diff rỗng, Claude nên báo không có thay đổi.
  2. Bài tập 2 – Subagent chỉ đọc. Tạo .claude/agents/test-finder.md với tools: Read, Grep, Glob, model: haiku, description "Finds test files related to a given module. Use proactively before modifying code." và system prompt yêu cầu trả về danh sách file + lý do. Sau đó hỏi: "Mình sắp sửa module auth, test nào liên quan?".
    Kết quả mong đợi: Claude ủy quyền cho test-finder (tự động hoặc khi bạn nêu tên); kết quả trả về là danh sách ngắn gọn; subagent không thể sửa file vì không có Write/Edit.
  3. Bài tập 3 – Đóng gói plugin. Gom hai thành phần trên thành plugin team-kit: tạo team-kit/.claude-plugin/plugin.json (name, description, version), chép skills/ và agents/ ra thư mục gốc plugin. Chạy claude plugin validate ./team-kit rồi claude --plugin-dir ./team-kit.
    Kết quả mong đợi: validate in ✔ Validation passed; trong phiên gõ được /team-kit:commit-msg fix; /plugin → tab Installed liệt kê skill và agent. Cố tình chuyển skills/ vào trong .claude-plugin/ để quan sát skill biến mất, rồi sửa lại.
  4. Bài tập 4 – Output style. Thử /output-style explanatory rồi nhờ Claude thêm một endpoint; quan sát khối ★ Insight. Sau đó tạo .claude/output-styles/vi-reviewer.md với keep-coding-instructions: true và chỉ dẫn "luôn trả lời bằng tiếng Việt, kết thúc bằng danh sách rủi ro".
    Kết quả mong đợi: style mới hiện trong /config → Output style (cần khởi động lại Claude Code nếu tạo file giữa phiên); phản hồi tiếp theo theo định dạng mới.

Tóm tắt ghi nhớ

Key takeaways
  • Custom commands đã gộp vào skills: .claude/commands/x.md vẫn chạy như /x; trùng tên thì skill thắng; việc mới nên viết .claude/skills/x/SKILL.md.
  • $ARGUMENTS = toàn bộ tham số; $0, $1… đánh số từ 0; $name qua trường arguments; !`cmd` chèn output lệnh trước khi gửi cho Claude.
  • Skill dùng progressive disclosure: metadata luôn nạp → thân SKILL.md khi gọi → file phụ/script khi cần. Giữ SKILL.md < 500 dòng; description nêu rõ làm gì + khi nào dùng.
  • disable-model-invocation: true = chỉ người gọi (việc có tác dụng phụ); user-invocable: false = chỉ Claude gọi (kiến thức nền).
  • Subagent: file Markdown trong .claude/agents/ hoặc ~/.claude/agents/; bắt buộc name + description; context riêng, không thấy lịch sử; built-in: Explore, Plan, general-purpose.
  • Plugin = thư mục + .claude-plugin/plugin.json (chỉ manifest nằm trong đó); thành phần có tiền tố plugin-name:; phát triển bằng --plugin-dir, /reload-plugins, claude plugin validate.
  • Output style đổi giọng mọi phản hồi (Proactive, Concise, Explanatory, Learning); là chỉ dẫn, không cưỡng chế — việc bắt buộc dùng hook.
  • Skill/plugin chạy với quyền của bạn: chỉ cài nguồn tin cậy, audit script, least privilege, cảnh giác prompt injection.

Thuật ngữ (Glossary)

Slash command
Lệnh gạch chéo – lệnh bắt đầu bằng / ở đầu tin nhắn; có loại dựng sẵn (built-in) và tự tạo (custom).
Custom slash command
Lệnh tùy biến – file Markdown trong .claude/commands/; tên file thành tên lệnh. Nay là dạng cũ của skill.
Skill / Agent Skill
Kỹ năng – thư mục có SKILL.md (hướng dẫn, script, tài nguyên) mà Claude nạp khi phù hợp hoặc khi gọi /skill-name.
SKILL.md
File bắt buộc của skill: frontmatter YAML + hướng dẫn Markdown.
Frontmatter
Phần khai báo đầu file – khối YAML giữa hai dòng --- ở đầu file Markdown.
Progressive disclosure
Tiết lộ dần dần – chỉ nạp metadata trước, nạp nội dung chi tiết khi thật sự cần.
$ARGUMENTS
Biến thay bằng toàn bộ chuỗi tham số người dùng gõ sau tên lệnh/skill; $N lấy tham số thứ N (từ 0).
Dynamic context injection
Chèn ngữ cảnh động – cú pháp !`cmd` chạy lệnh shell và chèn output vào skill trước khi gửi cho Claude.
Subagent
Tác tử con – trợ lý chuyên trách chạy trong context window riêng, có system prompt, tool, model riêng.
Delegation
Ủy quyền – Claude giao việc cho subagent dựa trên description hoặc theo yêu cầu rõ ràng.
Built-in subagents
Subagent dựng sẵn – Explore (tìm kiếm chỉ đọc), Plan (nghiên cứu trong plan mode), general-purpose (việc nhiều bước).
Fork (context: fork)
Rẽ nhánh – chạy nội dung skill như prompt của một subagent mới tách khỏi hội thoại chính.
Plugin
Gói mở rộng – thư mục gom skills, agents, hooks, MCP servers, cài/nạp như một đơn vị.
Manifest (plugin.json)
Tệp khai báo – .claude-plugin/plugin.json đặt tên, phiên bản, mô tả cho plugin.
Marketplace
Danh mục plugin – repo/thư mục có .claude-plugin/marketplace.json liệt kê plugin và nơi tải.
Namespace
Không gian tên – tiền tố như my-plugin: hoặc frontend: giúp tránh trùng tên lệnh.
Install scope
Phạm vi cài đặt – User, Project hoặc Local; quyết định plugin bật cho ai.
Output style
Phong cách phản hồi – chỉ dẫn định hình vai trò, giọng, định dạng của mọi phản hồi trong phiên.
Least privilege
Đặc quyền tối thiểu – chỉ cấp đúng những tool/quyền cần thiết cho nhiệm vụ.
Prompt injection
Chèn lệnh độc hại vào prompt – nội dung bên ngoài cố ra lệnh cho Claude làm điều ngoài ý người dùng.

Câu hỏi luyện tập

Nhóm của Minh có file CLAUDE.md dài, trong đó hơn một nửa là checklist release chi tiết chỉ dùng mỗi tháng một lần. Họ muốn giảm context tiêu tốn mỗi phiên mà checklist vẫn sẵn sàng khi cần. Cách nào phù hợp nhất?
  1. Chuyển checklist sang một output style tùy biến.
  2. Tách checklist thành một skill trong .claude/skills/release/SKILL.md.
  3. Tạo subagent release và chép checklist vào phần description của nó.
  4. Giữ trong CLAUDE.md nhưng chạy /compact sau mỗi phiên.
Đáp án B. Thân skill chỉ nạp khi được dùng, nên checklist dài gần như không tốn context cho đến lúc gõ /release hoặc Claude thấy việc khớp. A sai: output style áp dụng cho mọi phản hồi, luôn được gửi kèm request. C sai: description phải ngắn (description của subagent nằm trong context để Claude quyết định ủy quyền); chi tiết thuộc về system prompt. D sai: /compact tóm tắt hội thoại, không ngăn CLAUDE.md được nạp ở phiên sau.
Cho file .claude/skills/migrate/SKILL.md có thân: Migrate the $0 component from $1 to $2. Người dùng gõ /migrate SearchBar JavaScript TypeScript. Claude nhận được câu nào?
  1. Migrate the migrate component from SearchBar to JavaScript.
  2. Migrate the component from SearchBar to JavaScript.
  3. Migrate the SearchBar JavaScript TypeScript component from $1 to $2.
  4. Migrate the SearchBar component from JavaScript to TypeScript.
Đáp án D. Theo tài liệu, $N đánh số từ 0: $0 = SearchBar, $1 = JavaScript, $2 = TypeScript. A sai: tên lệnh không phải tham số. B sai: đó là cách hiểu "đánh số từ 1" của hướng dẫn cũ (lệch một vị trí). C sai: đó là hành vi của $ARGUMENTS (toàn bộ chuỗi), không phải $0, và $1/$2 vẫn được thay thế.
Một skill deploy-prod chạy script đẩy code lên production. Đội vận hành lo ngại Claude có thể tự kích hoạt skill này khi người dùng chỉ nói "code ổn rồi đấy". Nên cấu hình thế nào?
  1. Thêm disable-model-invocation: true vào frontmatter.
  2. Thêm user-invocable: false vào frontmatter.
  3. Đặt context: fork để skill chạy trong subagent.
  4. Đổi tên thư mục skill thành _deploy-prod để Claude không thấy.
Đáp án A. disable-model-invocation: true khiến Claude không tự nạp skill (description cũng không nằm trong context); chỉ người dùng gõ /deploy-prod mới chạy. B sai: làm điều ngược lại — ẩn khỏi menu, chỉ Claude được gọi. C sai: fork chỉ thay đổi nơi skill chạy, Claude vẫn có thể tự kích hoạt. D sai: tài liệu không có quy ước nào như vậy; tên mặc định chỉ là tên thư mục.
Lan cần tìm mọi nơi gọi một hàm deprecated trong monorepo hàng nghìn file. Cô lo kết quả grep khổng lồ sẽ làm đầy context của phiên chính, khiến các bước sửa code sau bị ảnh hưởng. Giải pháp tốt nhất?
  1. Chuyển sang output style Concise để Claude trả lời ngắn hơn.
  2. Viết một skill chứa !`grep -rn oldFunc .` rồi gọi trong phiên chính.
  3. Giao việc tìm kiếm cho subagent Explore và chỉ nhận lại danh sách tóm tắt.
  4. Tăng skillListingBudgetFraction lên 0.05.
Đáp án C. Subagent chạy trong context window riêng; output dài ở lại đó, chỉ bản tóm tắt quay về. Explore là built-in chỉ đọc, chuyên tìm kiếm codebase. A sai: Concise rút gọn câu chữ phản hồi, nhưng kết quả tool vẫn nằm trong context. B sai: !`cmd` chèn toàn bộ output vào phiên chính — đúng điều Lan muốn tránh (trừ khi kết hợp context: fork). D sai: đó là ngân sách cho danh sách mô tả skill, không liên quan.
Những phát biểu nào đúng về custom slash commands trong Claude Code hiện hành? (Chọn 2)
  1. File .claude/commands/deploy.md vẫn hoạt động và tạo lệnh /deploy.
  2. Nếu skill và command trùng tên, command được ưu tiên vì có trước.
  3. Command không hỗ trợ frontmatter; chỉ skill mới có frontmatter.
  4. File .claude/commands/frontend/component.md tạo lệnh /frontend:component.
  5. Claude không bao giờ tự gọi command; chỉ người dùng gọi được.
Đáp án A, D. Commands đã gộp vào skills nhưng file cũ vẫn chạy; thư mục con tạo namespace. B sai: trùng tên thì skill thắng. C sai: command nhận cùng các trường frontmatter như skill (trừ name và paths). E sai: tài liệu nói Claude có thể tự gọi command; muốn chặn thì thêm disable-model-invocation: true.
Đọc file subagent sau và chọn nhận định đúng: 
---
name: db-reader
description: Execute read-only database queries
tools: Bash
model: haiku
---
You only run SELECT statements against the analytics DB.
  1. Subagent này kế thừa mọi tool của phiên chính vì có dòng tools.
  2. Câu "You only run SELECT statements" bảo đảm tuyệt đối subagent không thể chạy DELETE.
  3. Subagent chỉ có tool Bash, chạy bằng model haiku; muốn chặn chắc chắn câu lệnh ghi nên thêm hook PreToolUse kiểm tra lệnh.
  4. File thiếu trường bắt buộc permissionMode nên sẽ không nạp.
Đáp án C. tools là allowlist → chỉ Bash; model: haiku dùng alias hợp lệ. Tài liệu có đúng ví dụ db-reader kèm hook PreToolUse gọi script kiểm tra và thoát mã 2 để chặn lệnh ghi. A sai: chỉ khi bỏ trống tools mới kế thừa toàn bộ. B sai: system prompt là chỉ dẫn, không cưỡng chế; Bash vẫn chạy được mọi lệnh. D sai: chỉ name và description là bắt buộc.
Hùng tạo plugin như sau, chạy claude --plugin-dir ./kit thì plugin nạp được nhưng không thấy skill /kit:review. Nguyên nhân? 
kit/
└── .claude-plugin/
    ├── plugin.json
    └── skills/
        └── review/SKILL.md
  1. plugin.json thiếu trường version bắt buộc.
  2. Thư mục skills/ nằm trong .claude-plugin/; chỉ plugin.json được đặt ở đó, thành phần phải ở thư mục gốc plugin.
  3. Skill trong plugin phải đặt tên file là review.md thay vì SKILL.md.
  4. --plugin-dir chỉ nạp được file .zip, không nạp thư mục.
Đáp án B. Tài liệu cảnh báo rõ: chỉ plugin.json nằm trong .claude-plugin/, thành phần đặt ở đó không được nạp. Sửa: chuyển skills/ ra kit/skills/ rồi /reload-plugins. A sai: version là tùy chọn; chỉ name bắt buộc. C sai: mỗi skill là thư mục chứa SKILL.md (file phẳng thuộc commands/, dạng cũ). D sai: --plugin-dir nhận cả thư mục lẫn .zip.
Một công ty muốn 30 lập trình viên dùng chung bộ gồm 4 skill, 2 subagent và 1 hook format code, có đánh số phiên bản và mỗi người nhận cập nhật dễ dàng. Cách nào phù hợp nhất?
  1. Gửi file zip thư mục .claude/ qua email mỗi khi có thay đổi.
  2. Đặt tất cả vào ~/.claude/ trên máy của trưởng nhóm.
  3. Viết toàn bộ nội dung vào CLAUDE.md của từng repo.
  4. Đóng gói thành plugin, đưa vào một marketplace nội bộ để mọi người cài và nhận cập nhật.
Đáp án D. Tài liệu khuyên dùng plugin khi muốn chia sẻ cho đồng đội, cài nhiều dự án, phát hành có phiên bản; marketplace giúp cài một lệnh và nhận cập nhật. A sai: thủ công, dễ lệch phiên bản. B sai: ~/.claude/ là cấu hình cá nhân trên một máy, người khác không dùng được. C sai: CLAUDE.md không định nghĩa được subagent hay hook, và luôn chiếm context.
Chi là sinh viên thực tập, muốn Claude Code vừa hoàn thành task vừa để lại một số đoạn code có quyết định thiết kế cho cô tự viết để luyện tập. Nên dùng gì?
  1. Output style Learning.
  2. Output style Proactive.
  3. Subagent Plan.
  4. Skill với user-invocable: false.
Đáp án A. Learning thêm khối Insight và đánh dấu TODO(human) để người dùng tự viết những đoạn có quyết định thiết kế. B sai: Proactive làm ngay và tự giả định, không chừa việc cho người học. C sai: Plan là subagent chỉ đọc để nghiên cứu trong plan mode. D sai: user-invocable: false chỉ ẩn skill khỏi menu, không liên quan đến cách dạy.
Đội bảo mật xem xét việc cài một skill "auto-pr-review" từ một repo GitHub cá nhân không quen biết. Những biện pháp nào phù hợp với khuyến nghị của Anthropic? (Chọn 2)
  1. Cài ngay vì skill chỉ là file Markdown, không thể chạy code.
  2. Kiểm tra toàn bộ file đi kèm, đặc biệt script, dependency và chỉ dẫn kết nối mạng ra ngoài.
  3. Đặt allowed-tools: Bash để skill chạy trơn tru không bị hỏi quyền.
  4. Đổi tên marketplace thành claude-plugins-official để được coi là nguồn chính thức.
  5. Giới hạn allowed-tools theo mẫu hẹp (vd Bash(gh pr view *)) và coi nội dung PR đọc vào là dữ liệu có thể chứa prompt injection.
Đáp án B, E. Anthropic cảnh báo skill có thể đưa vào lỗ hổng hoặc hướng Claude rò rỉ dữ liệu; cần audit file đi kèm và áp dụng least privilege, cảnh giác prompt injection từ nội dung bên ngoài. A sai: skill có thể kèm script được thực thi và !`cmd` chạy lệnh shell. C sai: cấp Bash không giới hạn trái nguyên tắc least privilege. D sai: tên marketplace chính thức chỉ được chấp nhận khi nguồn từ github.com/anthropics/; đổi tên không làm nguồn đáng tin hơn.
