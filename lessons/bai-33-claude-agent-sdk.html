🧰Claude Agent SDK là gì?

Theo tài liệu Anthropic, một agent là ứng dụng tự lập kế hoạch các bước và gọi công cụ (đọc file, chạy lệnh, sửa code) để hoàn thành nhiệm vụ. 🔁Vòng lặp agent: thu thập → hành động → kiểm chứng

Bài blog của Anthropic mô tả mọi agent tốt đều xoay quanh một chu trình lặp: gather context → take action → verify work → repeat. Agent SDK hiện thực hóa chu trình này thành các "turn" có thể quan sát được.

1. Gather context – thu thập ngữ cảnh

  • Agentic search và hệ thống file: file là thông tin có thể được nạp vào ngữ cảnh. Claude tự quyết định nạp thế nào, bằng các lệnh như grep, tail. Vì vậy cấu trúc thư mục của agent cũng là một dạng context engineering (ví dụ agent email có thư mục "Conversations" để tìm).
  • Semantic search: chia đoạn, nhúng vector, tìm theo khái niệm – thường nhanh hơn nhưng kém chính xác, khó bảo trì, kém minh bạch. Anthropic khuyên bắt đầu bằng agentic search, chỉ thêm semantic search khi cần tốc độ hoặc đa dạng.
  • Subagents: bật sẵn trong SDK; giúp chạy song song và giữ ngữ cảnh sạch (mỗi subagent có cửa sổ ngữ cảnh riêng, chỉ trả về phần liên quan).
  • Compaction: khi gần chạm giới hạn ngữ cảnh, SDK tự tóm tắt các message cũ để agent chạy lâu không "hết chỗ" – xây trên lệnh /compact của Claude Code.

2. Take action – hành động

  • Tools: khối xây dựng chính. Tool nổi bật trong ngữ cảnh của Claude nên thiết kế tool ảnh hưởng cả hiệu quả ngữ cảnh lẫn hành động Claude chọn. Tool nên đại diện cho hành động chính của agent (vd fetchInbox, searchEmails).
  • Bash & scripts: cách đa năng để làm việc linh hoạt (vd tải PDF đính kèm, chuyển sang text, tìm trong đó).
  • Code generation: code chính xác, ghép được, tái sử dụng được. Tính năng tạo file của Claude.ai dựa vào việc Claude viết Python để tạo Excel, PowerPoint, Word.
  • MCP: tích hợp chuẩn hóa, lo phần xác thực và gọi API (Slack, GitHub, Google Drive, Asana…) – không phải tự viết tích hợp hay quản lý OAuth.

Vòng lặp nhìn từ SDK: turn và message

Tài liệu How the agent loop works mô tả 5 bước của mọi session:

  1. Nhận prompt – Claude nhận prompt cùng system prompt, tool definitions, lịch sử hội thoại. SDK phát SystemMessage subtype "init" chứa metadata session.
  2. Đánh giá & phản hồi – Claude trả text, yêu cầu một/nhiều tool call, hoặc cả hai. SDK phát một AssistantMessage cho mỗi content block.
  3. Thực thi tool – SDK chạy từng tool, thu kết quả, đưa lại cho Claude. Hooks có thể chặn/sửa tool call trước khi chạy.
  4. Lặp lại – bước 2–3 lặp cho tới khi Claude trả lời không còn tool call.
  5. Trả kết quả – SDK phát AssistantMessage cuối (chỉ text), rồi ResultMessage chứa text cuối, token usage, chi phí, session ID.

Ví dụ trong tài liệu: prompt "Fix the failing tests in auth.ts" mất 4 turn – turn 1 chạy npm test, turn 2 đọc auth.ts và auth.test.ts, turn 3 sửa bằng Edit rồi chạy lại test, turn cuối trả lời bằng text. Một câu hỏi nhanh như "what files are here?" có thể chỉ mất 2–3 turn.

Agent tìm và sửa bug (Python)

import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, ResultMessage


async def main():
    # Vòng lặp agent: stream message khi Claude làm việc
    async for message in query(
        prompt="Review utils.py for bugs that would cause crashes. Fix any issues you find.",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Edit", "Glob"],  # tự duyệt các tool này
            permission_mode="acceptEdits",          # tự duyệt sửa file
        ),
    ):
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if hasattr(block, "text"):
                    print(block.text)               # suy luận của Claude
                elif hasattr(block, "name"):
                    print(f"Tool: {block.name}")    # tool đang được gọi
        elif isinstance(message, ResultMessage):
            print(f"Done: {message.subtype}")    # kết quả cuối


asyncio.run(main())

Cùng agent đó bằng TypeScript

import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Review utils.py for bugs that would cause crashes. Fix any issues you find.",
  options: {
    allowedTools: ["Read", "Edit", "Glob"],  // tự duyệt các tool này
    permissionMode: "acceptEdits"            // tự duyệt sửa file
  }
})) {
  // TS: nội dung nằm ở message.message.content (không phải message.content)
  if (message.type === "assistant" && message.message?.content) {
    for (const block of message.message.content) {
      if ("text" in block) console.log(block.text);
      else if ("name" in block) console.log(`Tool: ${block.name}`);
    }
  } else if (message.type === "result") {
    console.log(`Done: ${message.subtype}`);
  }
}

Ba phần chính của code: query – điểm vào tạo vòng lặp agent, trả về async iterator; prompt – việc cần làm (Claude tự chọn tool); options – cấu hình (allowedTools, permissionMode, systemPrompt, mcpServers…). Chạy bằng npx tsx agent.ts, uv run agent.py hoặc python agent.py; kết thúc bằng dòng Done: success.

Lỗi thường gặp

Đọc message.result mà không kiểm tra subtype trước – trường result chỉ có ở biến thể success. Ngoài ra, với query() single-shot, khi kết thúc bằng kết quả lỗi SDK vẫn phát ResultMessage rồi raise/throw (vd "Reached maximum number of turns") – hãy bọc vòng lặp trong try. Tạo custom tool

Một tool gồm 4 phần: name, description (Claude đọc để quyết định khi nào gọi), input schema (TypeScript dùng Zod; Python dùng dict kiểu {"latitude": float} hoặc JSON Schema đầy đủ) và handler async trả về object có content (bắt buộc), tùy chọn structuredContent và isError. Sau đó bọc tool vào server bằng create_sdk_mcp_server / createSdkMcpServer – server chạy ngay trong tiến trình ứng dụng của bạn.

# Python – custom tool tra tồn kho (dữ liệu giả lập)
import asyncio
from typing import Annotated, Any
from claude_agent_sdk import (tool, create_sdk_mcp_server, ToolAnnotations,
                              query, ClaudeAgentOptions, ResultMessage)

STOCK = {"SKU-001": 42, "SKU-002": 0}

@tool(
    "get_stock",
    "Get the current stock quantity for a product SKU",
    {"sku": Annotated[str, "Product SKU, e.g. SKU-001"]},
    annotations=ToolAnnotations(readOnlyHint=True),  # không ghi gì ⇒ được chạy song song
)
async def get_stock(args: dict[str, Any]) -> dict[str, Any]:
    qty = STOCK.get(args["sku"])
    if qty is None:
        # tự soạn thông báo lỗi để Claude biết nên làm gì tiếp
        return {"content": [{"type": "text", "text": f"Unknown SKU {args['sku']}"}],
                "is_error": True}
    return {"content": [{"type": "text", "text": f"{args['sku']}: {qty} units"}]}

inventory = create_sdk_mcp_server(name="inventory", version="1.0.0", tools=[get_stock])

async def main():
    options = ClaudeAgentOptions(
        mcp_servers={"inventory": inventory},               # key "inventory" = {server_name}
        allowed_tools=["mcp__inventory__get_stock"],       # mcp__{server}__{tool}
        tools=[],                                          # gỡ mọi built-in: least privilege
    )
    async for m in query(prompt="Còn bao nhiêu SKU-001?", options=options):
        if isinstance(m, ResultMessage) and m.subtype == "success":
            print(m.result)

asyncio.run(main())

🔒Permissions: agent được làm gì, khi nào cần duyệt

Claude quyết định gọi tool nào; bạn quyết định lời gọi đó có được thực thi không. Đây là chỗ áp dụng trực tiếp nguyên tắc least privilege – chỉ cấp quyền tối thiểu cần thiết cho nhiệm vụ.

Thứ tự đánh giá một tool call

  • Deny rule thắng tất cả: lời gọi khớp deny rule bị từ chối kể cả ở bypassPermissions và kể cả khi hook trả allow.
  • Hook trả allow không bỏ qua bước deny rule và ask rule.
  • Lời gọi đã được tự duyệt ở bước trước (bởi acceptEdits, bypassPermissions hoặc allow rule) không bao giờ tới canUseTool ⇒ kiểm tra đặt trong callback bị bỏ qua âm thầm. Muốn kiểm tra cả những lời gọi đó, dùng hook PreToolUse.
  • Mode dontAsk bỏ qua bước 6 và từ chối luôn.

Rule có phạm vi theo đường dẫn: Edit(path) áp cho mọi tool ghi file (Write, NotebookEdit…); viết Write(path) sẽ không khớp lời gọi nào. Rule cũng có thể khai báo trong .claude/settings.json (được đọc khi setting source project bật – mặc định với query()).

Lỗi thường gặp – subagent kế thừa quyền

Nếu phiên chính ở bypassPermissions, subagent kế thừa mode đó và có toàn quyền hệ thống – trong khi subagent có thể có system prompt khác, ít ràng buộc hơn. Tương tự, nếu phiên chính ở plan thì subagent đặt acceptEdits vẫn chạy ở plan. Đừng dùng bypassPermissions ngoài môi trường cô lập.

Mẹo thực chiến (Pro Tip)

Ứng dụng web cho người dùng cuối, cần hiện nút "Cho phép / Từ chối" ⇒ permission_mode="default" + callback canUseTool, và không đưa tool cần duyệt vào allowedTools (nếu có, callback không bao giờ được gọi). Agent chạy trên CI không người ⇒ dontAsk + allow list tối thiểu; chỉ dùng bypassPermissions trong container dùng-xong-bỏ.

🪝Hooks: chen code của bạn vào vòng đời agent

Hooks là callback chạy khi có sự kiện: tool sắp được gọi, tool trả kết quả, subagent bắt đầu/kết thúc, agent dừng… Hooks chạy trong tiến trình ứng dụng của bạn, không nằm trong cửa sổ ngữ cảnh, nên không tốn context.

Các hook trên có ở cả Python và TypeScript; TypeScript có thêm nhiều sự kiện khác (vd SessionStart, SessionEnd chỉ đăng ký callback được trong TypeScript).

# Chặn mọi Write/Edit vào file .env
from claude_agent_sdk import ClaudeAgentOptions, HookMatcher

async def protect_env_files(input_data, tool_use_id, context):
    file_path = input_data["tool_input"].get("file_path", "")
    if file_path.split("/")[-1].lower() == ".env":
        return {
            "hookSpecificOutput": {
                "hookEventName": input_data["hook_event_name"],
                "permissionDecision": "deny",                       # chặn
                "permissionDecisionReason": "Cannot modify .env files",  # Claude đọc lý do
            }
        }
    return {}   # không quyết định ⇒ luồng permission bình thường

options = ClaudeAgentOptions(
    hooks={"PreToolUse": [HookMatcher(matcher="Write|Edit", hooks=[protect_env_files])]}
)
  • Input của callback: dữ liệu sự kiện (chung có session_id, cwd, hook_event_name; PreToolUse có tool_name, tool_input), tool_use_id, và context (TypeScript có signal để hủy).
  • Output: trường cấp cao systemMessage (hiện cho người dùng, không phải model), continue; và hookSpecificOutput – với PreToolUse là permissionDecision ("allow"/"deny"/"ask"/"defer"), permissionDecisionReason, updatedInput.
  • Nhiều hook trả quyết định khác nhau ⇒ ưu tiên deny > defer > ask > allow. Các hook khớp chạy song song, nên viết mỗi hook độc lập.
  • matcher chỉ so với tên tool (vd "Write|Edit", "^mcp__"), không so với đường dẫn – lọc đường dẫn phải làm trong callback. Timeout mặc định 600 giây cho đa số sự kiện.
  • updatedInput thay toàn bộ input ⇒ luôn trả object mới gồm cả các trường cũ.
Lỗi thường gặp – hook không phải hàng rào tuyệt đối

Matcher Write|Edit không chạy khi Claude ghi .env bằng lệnh Bash. Trên Windows, file_path dùng dấu \ nên ví dụ tách bằng / ở trên không chặn được C:\project\.env. Theo mặc định, callback bị lỗi (throw) thì hành động vẫn được tiếp tục – đặt on_failure="block" / onFailure: "block" cho hook bảo vệ. Muốn cưỡng chế ở mức hệ điều hành, dùng sandbox.

An toàn khi agent có "cả một chiếc máy tính"

⚠️Rủi ro

  • Prompt injection: nội dung từ web (WebFetch), file, email, MCP server bên thứ ba có thể chứa chỉ thị độc hại.
  • Lệnh Bash phá hủy, ghi vào file bí mật, rò rỉ API key.
  • Subagent kế thừa bypassPermissions ⇒ toàn quyền hệ thống.
  • Chi phí "bùng nổ" khi agent sinh cả cây subagent.

🛡️Biện pháp (least privilege)

  • Giới hạn tools, allow list tối thiểu, disallowed_tools cho lệnh nguy hiểm (deny luôn thắng).
  • Hook PreToolUse kiểm tra input; on_failure="block" cho hook bảo vệ.
  • bypassPermissions chỉ trong container cô lập; dùng sandbox cho Bash.
  • API key qua biến môi trường ANTHROPIC_API_KEY; đặt max_turns, max_budget_usd, giới hạn số subagent.
Lưu ý

Từ Claude Code v2.1.210, message cuối của subagent được quét các mẫu "giống chỉ thị" (vd thẻ điều khiển giả, dòng bắt đầu bằng Human:) trước khi agent cha đọc – một lớp phòng vệ prompt injection giữa các agent. Đây là lớp bổ sung, không thay thế cấu hình quyền chặt chẽ.

Prompt: "Use the code-reviewer agent to review utils.py".

Tóm tắt ghi nhớ

Key takeaways
  • Agent SDK = harness của Claude Code dưới dạng thư viện (Python claude-agent-sdk, TypeScript @anthropic-ai/claude-agent-sdk); tên cũ là Claude Code SDK.
  • Khác Client SDK: SDK tự chạy vòng lặp và thực thi tool; bạn chỉ tiêu thụ luồng message từ query().
  • Chu trình agent: gather context → take action → verify work → repeat; ưu tiên agentic search và kiểm chứng bằng quy tắc.
  • Luôn kiểm tra ResultMessage.subtype trước khi đọc result; đặt max_turns/max_budget_usd cho production.
  • tools = có mặt hay không; allowedTools = tự duyệt; disallowedTools = chặn (deny thắng mọi mode).
  • Thứ tự quyền: hooks → deny → ask → mode → allow → canUseTool. Lời gọi đã tự duyệt không tới canUseTool.
  • Custom tool = in-process MCP server; tên mcp__{server}__{tool}; trả isError để Claude xử lý lỗi.
  • Sessions: continue (gần nhất), resume (theo ID), fork (nhánh mới, gốc giữ nguyên) – chỉ tách hội thoại, không tách file.
  • Subagents cô lập ngữ cảnh, chạy song song, giới hạn tool; hooks chạy ngoài ngữ cảnh để chặn/sửa/audit.

Câu hỏi luyện tập

Một startup muốn xây agent tự đọc repo, chạy test, sửa code và lặp lại cho tới khi test xanh, chạy trên server của chính họ bằng Python. Họ không muốn tự viết vòng lặp tool_use/tool_result. Lựa chọn phù hợp nhất?
  1. Client SDK với Messages API, tự viết các tool đọc file và chạy lệnh.
  2. Claude Agent SDK, gọi query() với các built-in tool như Read, Edit, Bash.
  3. Claude.ai Projects, tải repo lên làm knowledge.
  4. Managed Agents, vì đây là cách duy nhất có built-in tools.
Đáp án B. Agent SDK nhúng agent loop của Claude Code vào ứng dụng Python/TypeScript chạy trong tiến trình bạn vận hành; SDK tự thực thi tool. A sai: Client SDK bắt bạn tự viết vòng lặp tool – đúng điều họ muốn tránh. C sai: Projects là tính năng ứng dụng Claude, không chạy test hay sửa code trên server. D sai: Managed Agents do Anthropic host; không phải "cách duy nhất" – Agent SDK cũng có built-in tools và hợp với yêu cầu chạy trên server riêng.
Đọc cấu hình sau. Nhận định nào đúng? 
options = ClaudeAgentOptions(
    allowed_tools=["Read", "Grep"],
    permission_mode="bypassPermissions",
)
  1. Claude chỉ có thể dùng Read và Grep; mọi tool khác bị gỡ khỏi ngữ cảnh.
  2. Lời gọi Bash sẽ đi tới callback canUseTool để duyệt.
  3. Cấu hình lỗi: allowed_tools không dùng chung được với bypassPermissions.
  4. Bash, Write, Edit vẫn được tự duyệt vì allowed_tools không ràng buộc bypassPermissions.
Đáp án D. Tài liệu cảnh báo: allowed_tools chỉ tự duyệt tool liệt kê; ở bypassPermissions, lời gọi tới tool không liệt kê cũng được duyệt (trừ các hành động không mode nào tự duyệt). A sai: giới hạn tool có mặt là việc của tools, không phải allowed_tools. B sai: ở bypass, Bash thường được duyệt ở bước permission mode, không tới callback. C sai: đây là cấu hình hợp lệ, chỉ là không có tác dụng giới hạn như nhiều người tưởng.
Những nhận định nào đúng về thứ tự đánh giá permission trong Agent SDK? (Chọn 2)
  1. Lời gọi khớp deny rule bị từ chối kể cả ở bypassPermissions.
  2. Hook PreToolUse trả allow sẽ bỏ qua toàn bộ deny rule.
  3. Lời gọi đã được allow rule tự duyệt sẽ không tới callback canUseTool.
  4. Ở mode dontAsk, mọi lời gọi không được duyệt trước sẽ đi tới canUseTool.
  5. canUseTool là bước đầu tiên, trước cả hooks.
Đáp án A, C. Thứ tự: hooks → deny → ask → mode → allow → canUseTool. Deny rule áp ở mọi mode (A), và lời gọi đã tự duyệt ở bước trước không bao giờ tới callback (C). B sai: hook trả allow không bỏ qua deny/ask rule. D sai: dontAsk bỏ qua bước canUseTool và từ chối luôn. E sai: canUseTool là bước cuối cùng.
Một agent kết thúc và đoạn code sau ném lỗi AttributeError hoặc in None ở dòng in kết quả. Nguyên nhân khả dĩ nhất? 
async for m in query(prompt=task, options=ClaudeAgentOptions(max_turns=3)):
    if isinstance(m, ResultMessage):
        print(m.result)          # dòng có vấn đề
        print(m.total_cost_usd)
  1. ResultMessage không có trường total_cost_usd.
  2. max_turns phải đặt ở query(), không phải trong options.
  3. Agent dừng với subtype == "error_max_turns"; trường result chỉ có ở biến thể success, cần kiểm tra subtype trước.
  4. Phải dùng ClaudeSDKClient mới đọc được result.
Đáp án C. Với giới hạn 3 turn, tác vụ dài dễ chạm error_max_turns; khi đó không có result. Ngoài ra single-shot query() còn raise sau khi phát result lỗi, nên cần try. A sai: mọi subtype đều có total_cost_usd, usage, num_turns, session_id (Python khai báo optional). B sai: max_turns là trường của ClaudeAgentOptions. D sai: query() trả ResultMessage bình thường.
Bạn tạo server bằng create_sdk_mcp_server(name="crm", tools=[lookup_customer]) và truyền mcp_servers={"crm": crm_server}. Muốn tự duyệt tool này, bạn thêm chuỗi nào vào allowed_tools?
  1. "mcp__crm__lookup_customer"
  2. "lookup_customer"
  3. "crm.lookup_customer"
  4. "mcp__*"
Đáp án A. Tên đầy đủ theo quy ước mcp__{server_name}__{tool_name}, với {server_name} là key trong mcp_servers. B sai: thiếu tiền tố nên không khớp. C sai: không phải cú pháp của SDK. D sai: allow rule bỏ qua glob không neo như "mcp__*" – glob chỉ hợp lệ sau tiền tố server cụ thể, vd "mcp__crm__*".
Một ứng dụng SaaS phục vụ hàng nghìn người dùng, mỗi người có cuộc hội thoại agent riêng kéo dài nhiều ngày. Cách quay lại đúng ngữ cảnh của từng người là gì?
  1. Dùng continue_conversation=True cho mọi request.
  2. Dùng fork_session=True mỗi lần người dùng quay lại.
  3. Gửi lại toàn bộ lịch sử chat vào prompt mỗi lần.
  4. Lưu session_id từ ResultMessage theo từng người dùng và truyền vào resume.
Đáp án D. Tài liệu: resume theo ID là bắt buộc khi có nhiều session (vd mỗi người dùng một session). A sai: continue chỉ lấy session gần nhất trong thư mục – sẽ trộn người dùng. B sai: fork tạo nhánh mới mỗi lần, lịch sử không được nối tiếp trên một session. C sai: tốn token và mất các tool result/ngữ cảnh mà session đã lưu; resume giải quyết trực tiếp.
Agent chính đã phân tích 40 file và tìm ra lỗi ở src/auth/token.ts. Nó giao cho subagent fixer sửa lỗi, nhưng subagent hỏi lại "lỗi nằm ở đâu?". Vì sao?
  1. Subagent luôn dùng model nhỏ hơn nên không đọc được file.
  2. Subagent bắt đầu với ngữ cảnh mới; chỉ chuỗi prompt của tool Agent được truyền sang, nên đường dẫn và thông tin lỗi phải nằm trong prompt đó.
  3. Subagent chỉ nhận được system prompt của agent cha.
  4. Cần bật fork_session=True trên subagent.
Đáp án B. Subagent không phải fork không nhận lịch sử hội thoại hay tool result của cha; thứ duy nhất truyền từ cha là prompt của tool Agent. A sai: model do AgentDefinition.model hoặc thứ tự mặc định quyết định, và không liên quan tới việc thiếu ngữ cảnh. C sai: subagent không nhận system prompt của cha. D sai: fork_session là tùy chọn session của query(), không phải cấu hình subagent.
Đội bảo mật đăng ký hook sau nhưng log cho thấy file .env vẫn bị ghi đè. Giải thích hợp lý nhất? 
hooks={"PreToolUse": [HookMatcher(matcher="Write|Edit", hooks=[protect_env_files])]}
# protect_env_files trả permissionDecision "deny" nếu tên file là ".env"

  2. Matcher phải viết là ".env" để lọc theo tên file.
  3. Claude đã ghi file bằng lệnh Bash (vd echo ... > .env), nên matcher Write|Edit không kích hoạt hook.
  4. Hook chỉ chạy trong TypeScript SDK.
Đáp án C. Tài liệu cảnh báo: matcher Write|Edit giới hạn hook ở hai tool đó; ghi bằng Bash thì hook không chạy (cũng nên kiểm tra đường dẫn Windows dùng \). Biện pháp: thêm deny rule Edit(...), hook cho Bash, hoặc sandbox. A sai: PreToolUse chặn được bằng permissionDecision: "deny". B sai: matcher chỉ so tên tool, không so đường dẫn. D sai: PreToolUse có ở cả Python và TypeScript.
Bạn chạy agent review code trên CI không có người duyệt. Agent chỉ được đọc code, tuyệt đối không chạy shell. Hai cấu hình nào phù hợp nhất? (Chọn 2)
  1. permission_mode="bypassPermissions" để không bị kẹt chờ duyệt.
  2. allowed_tools=["Read","Glob","Grep"] kết hợp permission_mode="dontAsk".
  3. permission_mode="default" không kèm callback, hy vọng agent tự hiểu.
  4. permission_mode="acceptEdits" để agent chạy nhanh.
  5. disallowed_tools=["Bash"] để gỡ hẳn tool Bash khỏi ngữ cảnh.
Đáp án B, E. Tài liệu gợi ý cặp allowedTools + dontAsk cho agent "khóa chặt" (B); tên trần trong disallowed_tools gỡ tool khỏi ngữ cảnh và deny thắng mọi mode (E). A sai: bypass duyệt mọi tool, trái least privilege. C sai: default không callback thì từ chối, nhưng không gỡ Bash và không thể hiện ý đồ rõ như B+E. D sai: acceptEdits tự duyệt sửa file và lệnh như rm – vượt quá quyền "chỉ đọc".

  1. Đặt quy tắc bền vững vào CLAUDE.md (nạp qua setting_sources), vì nội dung này được chèn lại mỗi request; và thêm deny rule cho thư mục đó.
  2. Tắt hoàn toàn compaction để giữ nguyên lịch sử.
  3. Lặp lại quy tắc trong mọi tool result.
  4. Tăng max_turns để agent có thêm thời gian nhớ lại.
Đáp án A. Tài liệu: compaction thay message cũ bằng tóm tắt nên chỉ dẫn ban đầu có thể mất; quy tắc bền vững thuộc về CLAUDE.md. Deny rule Edit(...) bổ sung lớp cưỡng chế. B sai: không có compaction thì session dài sẽ hết ngữ cảnh. C sai: không phải khuyến nghị, tốn context và khó làm với built-in tools. D sai: số turn không liên quan đến việc nhớ quy tắc.
