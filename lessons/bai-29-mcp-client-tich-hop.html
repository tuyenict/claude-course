🔌Host, client và các tính năng phía client

Tài liệu "Understanding MCP clients" phân biệt rõ hai khái niệm hay bị nhầm:

  • Host là ứng dụng người dùng tương tác trực tiếp, ví dụ Claude.ai hay một IDE. Host quản lý trải nghiệm tổng thể và điều phối nhiều client.
  • MCP client là thành phần ở tầng giao thức do host tạo ra. Mỗi client giữ đúng một kết nối trực tiếp tới một server. Host kết nối 3 server thì có 3 client.
Ví dụ đời thường

Host giống một tổng đài viên ngồi trước nhiều điện thoại. Mỗi điện thoại (client) chỉ nối với đúng một đối tác (server). Tổng đài viên quyết định nhấc máy nào, nói gì; còn mỗi chiếc điện thoại chỉ lo truyền đúng lời trên đường dây của nó.

Client không chỉ "dùng" server – client còn cung cấp tính năng cho server

Ngoài việc nhận context từ server, client có thể cung cấp tính năng ngược lại cho server. Trong phiên bản giao thức hiện hành (2026-07-28, theo tài liệu kiểm tra ngày 2026-11-20), tính năng chính phía client là elicitation.

Elicitation – server hỏi thêm người dùng giữa chừng

Elicitation cho phép server tạm dừng và xin thêm thông tin từ người dùng thay vì đòi tất cả từ đầu hoặc thất bại khi thiếu dữ liệu. Ví dụ: server đặt tour du lịch cần người dùng xác nhận tổng tiền và chọn loại ghế trước khi chốt đơn. Có hai chế độ:

📝Form mode

  • Server gửi kèm một JSON schema (requestedSchema).
  • Client dựng form, kiểm tra dữ liệu theo schema rồi gửi lại.
  • Không được dùng để hỏi mật khẩu, API key, access token, thông tin thanh toán.

🔗URL mode

  • Server đưa một URL để người dùng tự mở.
  • Tương tác diễn ra ngoài luồng (out of band): dữ liệu không đi qua client hay context của LLM.
  • Dành cho luồng nhạy cảm: nhập thông tin đăng nhập, ủy quyền OAuth của bên thứ ba.

Client khai báo chế độ hỗ trợ trong capability elicitation: đối tượng rỗng {} nghĩa là chỉ form mode; { "form": {}, "url": {} } nghĩa là cả hai. Người dùng có ba lựa chọn tương ứng ba action: accept (đồng ý gửi), decline (từ chối rõ ràng), cancel (đóng mà không chọn).

Elicitation đi theo mẫu Multi Round-Trip Requests (MRTR): server không gửi một request riêng cho client, mà trả về InputRequiredResult (resultType: "input_required") chứa inputRequests. Client thu thập câu trả lời rồi gửi lại chính request ban đầu với id mới, kèm inputResponses và requestState nguyên văn.

// Server trả về: cần người dùng xác nhận trước khi đặt tour (rút gọn từ tài liệu MCP)
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "input_required",
    "inputRequests": {
      "bookingConfirmation": {
        "method": "elicitation/create",
        "params": {
          "mode": "form",
          "message": "Please confirm your Barcelona vacation booking ... total $3,000.",
          "requestedSchema": {
            "type": "object",
            "properties": {
              "confirmBooking": { "type": "boolean" },
              "seatPreference": { "type": "string", "enum": ["window", "aisle", "no preference"] }
            },
            "required": ["confirmBooking"]
          }
        }
      }
    },
    "requestState": "opaque-string-from-the-server"   // client phải gửi lại nguyên văn
  }
}

Roots và sampling: đã deprecated

Các bài viết cũ về MCP thường nhắc tới roots và sampling như tính năng phía client. Theo tài liệu hiện hành, cả hai đã deprecated từ phiên bản giao thức 2026-07-28 và sẽ bị gỡ bỏ:

  • Roots → truyền thư mục/file qua tham số của tool, URI của resource hoặc cấu hình server.
  • Sampling → server tích hợp trực tiếp với API của nhà cung cấp LLM. Giao thức không định nghĩa cơ chế thay thế.

Bài 30 sẽ nói kỹ hơn về các chủ đề nâng cao này.

Lỗi thường gặp

Dùng elicitation form mode để hỏi API key của người dùng "cho tiện". Tài liệu MCP cấm điều này: thông tin nhạy cảm phải đi qua URL mode để không bao giờ đi qua client hay context của LLM. Client tốt sẽ cảnh báo các yêu cầu đáng ngờ và cho người dùng xem lại dữ liệu trước khi gửi.

Mã nguồn client (rút gọn, chú thích tiếng Việt)

# client.py – MCP client tối giản theo hướng dẫn chính thức (MCP Python SDK >= 2.0.0)
import asyncio, sys
from mcp import Client, StdioServerParameters
from mcp.client.stdio import stdio_client
from mcp_types import TextContent
from anthropic import Anthropic
from dotenv import load_dotenv

load_dotenv()                      # nạp ANTHROPIC_API_KEY từ .env – không hard-code key
MODEL = "claude-haiku-5-5"         # model ID dùng trong tài liệu
MAX_TOKENS = 10000                 # chừa chỗ cho cả thinking và câu trả lời
MAX_TOOL_TURNS = 10                # chặn vòng lặp tool vô hạn
anthropic = Anthropic()

def server_params(path: str) -> StdioServerParameters:
    # Chỉ là cấu hình: chạy server .py bằng python, .js bằng node
    if path.endswith(".py"): command = "python"
    elif path.endswith(".js"): command = "node"
    else: raise ValueError("Server script must be a .py or .js file")
    return StdioServerParameters(command=command, args=[path])

async def process_query(client: Client, query: str) -> str:
    messages = [{"role": "user", "content": query}]
    # 1) Đổi tool MCP sang định dạng tool của Claude API
    tool_list = await client.list_tools()
    tools = [{"name": t.name, "description": t.description,
              "input_schema": t.input_schema} for t in tool_list.tools]
    out = []
    response = anthropic.messages.create(model=MODEL, max_tokens=MAX_TOKENS,
                                         messages=messages, tools=tools)
    for _ in range(MAX_TOOL_TURNS):
        tool_uses = []
        for block in response.content:
            if block.type == "text": out.append(block.text)
            elif block.type == "tool_use": tool_uses.append(block)
        if not tool_uses:
            return "\n".join(out)
        results = []
        for tu in tool_uses:
            # 2) Client thực thi tool trên MCP server
            r = await client.call_tool(tu.name, tu.input)
            results.append({
                "type": "tool_result", "tool_use_id": tu.id,
                "content": "\n".join(b.text for b in r.content if isinstance(b, TextContent)),
                "is_error": r.is_error,      # tool lỗi KHÔNG raise – báo cho Claude biết
            })
        # 3) Gửi lại nguyên lượt assistant (kể cả thinking), trả lời mọi tool_use trong 1 message
        messages.append({"role": "assistant", "content": response.content})
        messages.append({"role": "user", "content": results})
        response = anthropic.messages.create(model=MODEL, max_tokens=MAX_TOKENS,
                                             messages=messages, tools=tools)
    out.append(f"[Stopped after {MAX_TOOL_TURNS} tool-use turns]")
    return "\n".join(out)

async def main() -> None:
    # async with = toàn bộ vòng đời kết nối: khởi chạy server, thương lượng phiên bản giao thức,
    # khi thoát thì ngắt kết nối và tắt tiến trình con – không cần đóng thủ công
    async with Client(stdio_client(server_params(sys.argv[1]))) as client:
        names = [t.name for t in (await client.list_tools()).tools]
        print("Connected to server with tools:", names)
        while (q := (await asyncio.to_thread(input, "\nQuery: ")).strip()) != "quit":
            print(await process_query(client, q))

if __name__ == "__main__":
    asyncio.run(main())

Chạy: uv run client.py path/to/server.py (server Python) hoặc uv run client.py path/to/build/index.js (server Node). Tài liệu lưu ý lần trả lời đầu tiên có thể mất tới 30 giây vì server khởi động, Claude xử lý và tool chạy; các lần sau thường nhanh hơn.

Còn ClientSession thì sao?

Nhiều ví dụ (kể cả ví dụ client-side helpers trong tài liệu Anthropic ở phần sau) vẫn dùng kiểu cũ: mở stdio_client(...) lấy cặp luồng (read, write), tạo ClientSession(read, write) rồi tự gọi await session.initialize() để bắt tay. Theo hướng dẫn MCP hiện hành, đối tượng Client của SDK 2.0.0+ thay thế phần thiết lập phiên đó bằng một khối async with duy nhất. Ý tưởng không đổi: một phiên = một kết nối tới một server, phải khởi tạo (initialize) trước khi gọi tool.

# Kiểu ClientSession (xuất hiện trong ví dụ helpers của tài liệu Anthropic)
async with stdio_client(StdioServerParameters(command="mcp-server")) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()          # bắt tay: thương lượng phiên bản & capabilities
        tools = await session.list_tools()
Mẹo thực chiến (Pro Tip)

Tool MCP báo lỗi ⇒ đừng nuốt lỗi. Chuyển result.is_error vào trường is_error của tool_result để Claude đọc thông báo lỗi và thử cách khác. Đây là best practice được tài liệu nêu rõ.

Xử lý sự cố (theo tài liệu)
  • FileNotFoundError: kiểm tra đường dẫn server; thử đường dẫn tuyệt đối. Trên Windows dùng dấu / hoặc escape \\.
  • Connection refused: server chưa chạy hoặc sai đường dẫn.
  • Tool execution failed: thiếu biến môi trường mà tool cần.
  • Timeout error: cân nhắc tăng read_timeout_seconds trên Client.

🧰Client-side MCP helpers của Anthropic SDK

Đoạn code chuyển tool.input_schema sang tool của Claude ở trên khá lặp lại. Anthropic SDK cung cấp client-side MCP helpers để chuyển đổi giữa kiểu dữ liệu MCP và kiểu của Claude API. Bạn vẫn tự quản lý kết nối MCP (nên dùng được server stdio cục bộ, prompts, resources), nhưng bớt code chuyển đổi.

  • Python: pip install "anthropic[mcp]" (extra mcp, cần Python 3.10 trở lên).
  • TypeScript: npm install @anthropic-ai/sdk @modelcontextprotocol/sdk.

# Dùng tool MCP với tool runner – SDK tự chạy vòng lặp tool use
import asyncio
from anthropic import AsyncAnthropic
from anthropic.lib.tools.mcp import async_mcp_tool
from mcp import ClientSession
from mcp.client.stdio import StdioServerParameters, stdio_client

client = AsyncAnthropic()          # đọc ANTHROPIC_API_KEY từ biến môi trường

async def main() -> None:
    params = StdioServerParameters(command="mcp-server")
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as mcp_client:
            await mcp_client.initialize()
            tools_result = await mcp_client.list_tools()
            runner = client.beta.messages.tool_runner(
                model="claude-opus-5-5",
                max_tokens=1024,
                messages=[{"role": "user", "content": "What tools do you have available?"}],
                tools=[async_mcp_tool(t, mcp_client) for t in tools_result.tools],
            )
            print(await runner.until_done())

asyncio.run(main())

Với prompts: lấy prompt = await mcp_client.get_prompt(name="my-prompt") rồi truyền messages=[mcp_message(m) for m in prompt.messages]. Với resources: read_resource(uri=...) rồi đặt mcp_resource_to_content(resource) vào content của message người dùng. Nếu giá trị MCP không được Claude API hỗ trợ (kiểu nội dung, MIME type, resource link), hàm chuyển đổi ném UnsupportedMCPValueError; với resource link hãy resolve bằng MCP client trước khi chuyển.

🌐MCP connector trong Messages API (beta)

MCP connector cho phép bạn kết nối tới MCP server từ xa ngay trong Messages API, không cần viết MCP client riêng. Hạ tầng của Anthropic đóng vai client: kết nối server, lấy danh sách tool, gọi tool và đưa kết quả cho Claude trong cùng một response.

Giới hạn cần nhớ

  • Chỉ hỗ trợ tool calls – không có resources, prompts.
  • Server phải public qua HTTP (hỗ trợ cả Streamable HTTP và SSE). Server stdio cục bộ không kết nối trực tiếp được.
  • Không thuộc phạm vi Zero Data Retention (ZDR) và không đủ điều kiện HIPAA: định nghĩa tool và kết quả thực thi được lưu theo chính sách lưu giữ chuẩn của Anthropic.
  • Header mcp-client-2026-09-15 dùng được trên Claude API và Claude Models on Google Cloud (Anthropic managed); Claude Platform on AWS và Microsoft Foundry dùng mcp-client-2025-11-20.

Hai thành phần: mcp_servers và mcp_toolset

  1. mcp_servers (tham số cấp cao nhất) – khai báo kết nối: type, url, name, authorization_token.
  2. mcp_toolset (một phần tử trong mảng tools) – chọn tool nào được bật và cấu hình ra sao.
# Ví dụ cơ bản (Python): bật toàn bộ tool của một MCP server từ xa
import os, anthropic

client = anthropic.Anthropic()   # ANTHROPIC_API_KEY lấy từ biến môi trường

response = client.beta.messages.create(          # lưu ý: client.beta
    model="claude-opus-5-5",
    max_tokens=1000,
    messages=[{"role": "user", "content": "What tools do you have available?"}],
    mcp_servers=[{
        "type": "url",                                   # hiện chỉ hỗ trợ "url"
        "url": "https://example-server.modelcontextprotocol.io/sse",
        "name": "example-mcp",                           # định danh duy nhất
        "authorization_token": os.environ["MCP_TOKEN"],  # OAuth token – không hard-code
    }],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "example-mcp"}],
    betas=["mcp-client-2025-11-20"],
)
print(response)

Gọi bằng cURL thì thêm header anthropic-beta: mcp-client-2025-11-20; ví dụ trong tài liệu dùng anthropic-version: 2026-10-21 (kiểm tra ngày 2026-11-20). Với SDK, beta header được đặt qua tham số betas.

Mỗi tool (trong default_config hoặc configs) có hai tùy chọn: enabled (mặc định true) và defer_loading (mặc định false; nếu true, mô tả tool không gửi cho model lúc đầu – dùng cùng Tool search tool).

Thứ tự ưu tiên khi gộp cấu hình (cao → thấp): configs của từng tool → default_config của set → mặc định hệ thống.

✅Allowlist – chỉ bật vài tool

{
  "type": "mcp_toolset",
  "mcp_server_name": "google-calendar-mcp",
  "default_config": { "enabled": false },
  "configs": {
    "search_events": { "enabled": true },
    "create_event":  { "enabled": true }
  }
}

⛔Denylist – tắt tool nguy hiểm

{
  "type": "mcp_toolset",
  "mcp_server_name": "google-calendar-mcp",
  "configs": {
    "delete_all_events":       { "enabled": false },
    "share_calendar_publicly": { "enabled": false }
  }
}

Tài liệu khuyến nghị denylist các tool ghi/xóa khi xây trợ lý chỉ đọc, hoặc khi bạn muốn có bước xác nhận của con người trước khi thay đổi trạng thái. Allowlist còn chặt hơn: tool mới mà server thêm vào sau này sẽ không tự động được bật (vì default_config.enabled là false).

Quy tắc kiểm tra (validation)

  • Server phải tồn tại: mcp_server_name phải khớp một server trong mcp_servers.
  • Server phải được dùng: mỗi server trong mcp_servers phải được đúng một MCPToolset tham chiếu.
  • Một toolset cho mỗi server: không thể có hai MCPToolset cho cùng một server.
  • Tên tool lạ trong configs: chỉ ghi cảnh báo ở backend, không trả lỗi (vì server có thể thay đổi tool động).

Khối nội dung trong response

Khác với client tool thông thường (bạn phải tự thực thi rồi gửi tool_result), với MCP connector cả lời gọi lẫn kết quả đều nằm sẵn trong response, dưới hai loại khối mới:

// Claude gọi tool trên MCP server
{
  "type": "mcp_tool_use",
  "id": "mcptoolu_014Q35RayjACSWkSj4X2yov1",
  "name": "echo",
  "server_name": "example-mcp",
  "input": { "param1": "value1", "param2": "value2" }
}
// Kết quả do API nhận về từ MCP server
{
  "type": "mcp_tool_result",
  "tool_use_id": "mcptoolu_014Q35RayjACSWkSj4X2yov1",
  "is_error": false,
  "content": [{ "type": "text", "text": "Hello" }]
}

Ghim danh sách tool (beta mcp-client-2026-09-15)

MCP server có thể đổi tool bất cứ lúc nào. Với header mcp-client-2026-09-15 (bao gồm mọi thứ của mcp-client-2025-11-20), khi API hỏi server danh sách tool, response bắt đầu bằng khối mcp_tool_listing cho mỗi server được hỏi. Hệ quả:

  • Nếu code của bạn đọc content[0], hãy bỏ qua các khối này.
  • Gửi lại nguyên lượt assistant (kể cả mcp_tool_listing) và tiếp tục gửi header này; các request sau dùng danh sách đã ghi thay vì hỏi lại server.
  • Muốn tự ghim: sao chép tools của khối listing vào trường tools của MCPToolset. Khi đó API không hỏi server, và response không còn khối mcp_tool_listing.

Nhiều server và tập tool lớn

Có thể kết nối nhiều server trong một request: mỗi server một phần tử mcp_servers và một MCPToolset tương ứng. Claude chọn tool dựa trên tên và mô tả, nên mô tả rõ ràng giúp chọn chính xác hơn. Với tập tool lớn (hàng chục tool qua nhiều server), tài liệu gợi ý bật defer_loading cùng Tool search tool để chỉ những tool liên quan được đưa ra cho mỗi truy vấn.

Xác thực

Với server yêu cầu OAuth, bạn (bên gọi API) phải tự chạy luồng OAuth, lấy access token trước khi gọi API và tự làm mới token khi cần. API chỉ nhận token qua authorization_token. Để thử nghiệm, có thể dùng MCP Inspector:

  1. Chạy npx @modelcontextprotocol/inspector (cần Node.js).
  2. Chọn Transport type là SSE hoặc Streamable HTTP, nhập URL server.
  3. Bấm Open Auth Settings → Quick OAuth Flow, ủy quyền, bấm Continue tới khi thấy Authentication complete.
  4. Sao chép giá trị access_token vào authorization_token.

Khi nào Claude gọi MCP tool?

Claude gọi tool khi yêu cầu của người dùng khớp với khả năng mô tả của tool, dù nói rõ ("tìm các bug đang mở trên Jira") hay ngầm ("cái gì đang chặn bản release?" khi có Jira server). Ngược lại, Claude không gọi tool cho câu hỏi kiến thức chung về dịch vụ: "Notion database hoạt động thế nào?" được trả lời trực tiếp, còn "trong database Projects của tôi có gì?" mới kích hoạt tool. Bạn có thể điều chỉnh mức độ sẵn sàng gọi tool qua system prompt.

Thông tin khác

  • Batch: có thể dùng mcp_servers trong Message Batches API; lời gọi MCP tool tính giá như request Messages API thường.
  • Managed Agents: khai báo MCP server trên agent; mỗi session cung cấp credential bằng cách tham chiếu một vault, nên secret không nằm trong định nghĩa agent.
  • Di chuyển từ mcp-client-2025-04-04: đổi header; bỏ tool_configuration trong định nghĩa server và chuyển sang MCPToolset trong tools. Ví dụ tool_configuration.allowed_tools: [...] ⇒ default_config.enabled: false + bật từng tool trong configs.
Mẹo thực chiến (Pro Tip)

Backend cần gọi một MCP server SaaS có URL https, chỉ cần tools, không muốn duy trì code client ⇒ MCP connector. Nhưng nếu server chỉ chạy stdio trên máy nội bộ, hoặc bạn cần MCP prompts/resources ⇒ MCP connector không dùng được; hãy tự viết client (có thể dùng client-side helpers).

Lỗi thường gặp
  • Khai báo server trong mcp_servers nhưng quên thêm mcp_toolset tương ứng → vi phạm quy tắc "server phải được dùng".
  • Dùng client.messages.create thay vì client.beta.messages.create (hoặc thiếu betas) → tham số mcp_servers không được nhận.
  • Trỏ url vào http://localhost:3000 → không chạy: URL phải là https:// và server phải public.
  • Đọc response.content[0].text khi dùng header mcp-client-2026-09-15 → khối đầu có thể là mcp_tool_listing.

🖥️Claude Desktop và Claude.ai: local server và custom connector

Với người dùng không lập trình, ứng dụng Claude chính là host. Có hai kiểu kết nối khác nhau.

1. Server cục bộ trong Claude Desktop

Claude Desktop tự khởi chạy các server cục bộ mỗi khi mở ứng dụng, dựa trên file cấu hình JSON. Ví dụ chính thức dùng Filesystem Server (cần Node.js).

  1. Mở Settings từ menu Claude trên thanh menu hệ thống (không phải phần cài đặt trong cửa sổ chat).
  2. Tab Developer → Edit Config: tạo file nếu chưa có, hoặc mở file hiện có.
  3. Khai báo server trong khóa mcpServers.
  4. Thoát hẳn và mở lại Claude Desktop để nạp cấu hình mới.
  5. Kiểm tra: bấm nút "Add files, connectors, and more /" ở góc dưới trái ô nhập → Connectors → Manage connectors → chọn server để xem danh sách tool.

Mỗi server có thể thêm khóa env để đặt biến môi trường. Ví dụ tài liệu nêu: nếu log báo lỗi ENOENT có chứa ${APPDATA} trên Windows, hãy thêm giá trị đã mở rộng của %APPDATA% vào env.

  • mcp.log: log chung về kết nối MCP và lỗi kết nối.
  • mcp-server-SERVERNAME.log: stderr của từng server (server stdio có thể ghi mọi log ra stderr).
  • Mọi thao tác của Filesystem Server đều cần bạn phê duyệt trước khi thực thi.
Lỗi thường gặp

Server không xuất hiện sau khi sửa config. Theo tài liệu, hãy kiểm tra lần lượt: đã thoát hẳn và mở lại chưa; cú pháp JSON có hợp lệ không; đường dẫn trong config có phải tuyệt đối (không phải tương đối) không; đọc log; và thử chạy lệnh server bằng tay trong terminal để xem lỗi.

2. Server từ xa: Custom Connectors (Claude.ai và Desktop)

Custom connector là cầu nối giữa Claude và một remote MCP server. Lợi thế của server từ xa: dùng được từ mọi client có Internet, không phải cài đặt trên từng máy.

  1. Mở Settings (Desktop: Ctrl+Comma hoặc menu File › Settings; trình duyệt: ⌘⇧, trên macOS hoặc qua biểu tượng hồ sơ).
  2. Chọn Connectors → Add → Add custom connector, nhập URL đầy đủ có https:// (ví dụ tài liệu: https://example-server.modelcontextprotocol.io/mcp), bấm Add.
  3. Hoàn tất xác thực (thường là OAuth) theo hướng dẫn của server.
  4. Trong khung chat: "Add files, connectors, and more /" → Connectors → chọn resources và prompts của server để đưa vào hội thoại.
  5. Quay lại Connectors, bấm vào server để bật/tắt từng tool và cấu hình các thông số bảo mật.
Mẹo thực chiến (Pro Tip)

Nhóm kinh doanh muốn Claude đọc dữ liệu CRM có MCP server chính thức dạng URL ⇒ custom connector (không cần cài gì trên máy). Kế toán muốn Claude sắp xếp file trong thư mục trên laptop ⇒ local server trong Claude Desktop, và chỉ liệt kê đúng thư mục cần thiết trong args.

⌨️Kết nối MCP vào Claude Code

Claude Code là host thứ ba. Bạn thêm server bằng lệnh claude mcp add, với ba kiểu transport:

# HTTP – khuyến nghị cho server từ xa
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer your-token"

# SSE – deprecated, chỉ dùng khi server chưa hỗ trợ HTTP
claude mcp add --transport sse asana https://mcp.asana.com/sse

# stdio – tiến trình cục bộ; mọi thứ sau "--" được chuyển nguyên cho server
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable \
  -- npx -y airtable-mcp-server

Dấu -- rất quan trọng: mọi thứ trước nó là tùy chọn của Claude Code (--transport, --env, --scope); mọi thứ sau nó là lệnh và tham số của server. Thiếu --, một tham số như --port 8080 sẽ bị Claude Code hiểu nhầm là tùy chọn của chính nó.

// .mcp.json – commit vào git để cả nhóm dùng chung; dùng biến môi trường cho secret
{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}

.mcp.json hỗ trợ ${VAR} và ${VAR:-default} trong command, args, env, url, headers. Lưu ý bảo mật: trong url và headers của remote server, các biến chứa credential như ANTHROPIC_API_KEY được đọc là rỗng, để một file cấu hình dự án không thể gửi credential của bạn tới server mà nó chỉ định.

Quản lý và dùng server

  • claude mcp list / claude mcp get <name> / claude mcp remove <name>; trong phiên làm việc dùng /mcp để xem trạng thái, xác thực, bật/tắt.
  • claude mcp add-json <name> '<json>' thêm server từ một khối JSON; claude mcp add-from-claude-desktop nhập server từ Claude Desktop (chỉ macOS và WSL).
  • OAuth: xác thực qua /mcp (mở trình duyệt) hoặc claude mcp login <name>; token được lưu an toàn và tự làm mới.
  • Resources: gõ @ để chọn, cú pháp @server:protocol://resource/path. Prompts: hiện thành lệnh /servername:promptname (MCP), cũng chạy được bằng /mcp__servername__promptname.
  • Tên đầy đủ của tool có dạng mcp__<server>__<tool>; tool có tên đầy đủ dài hơn 128 ký tự sẽ bị loại khỏi danh sách gửi cho Claude.
  • Tool search hoãn nạp định nghĩa tool cho tới khi Claude cần, nên thêm nhiều server ít ảnh hưởng tới context window.

  • Dọn dẹp định kỳ: gỡ connector không dùng; với Claude Code, chạy claude mcp logout <name> trước remove nếu muốn thu hồi token (vì remove chỉ xóa token cục bộ).

  1. Bài tập 1 – Client Python cho server của bài 28. Dựng dự án mcp-client theo phần 3, chạy uv run client.py <đường-dẫn-tới-server.py> (server bạn viết ở bài 28; nên dùng đường dẫn tuyệt đối).
    Kết quả mong đợi: dòng Connected to server with tools: [...] liệt kê đúng tên tool của server; hỏi một câu cần tool, output có dòng [Calling tool ...] (nếu bạn giữ dòng log như bản gốc) rồi câu trả lời cuối. Thử làm tool ném lỗi và xác nhận Claude nhận được is_error: true và giải thích cho người dùng thay vì chương trình bị crash.
  2. Bài tập 2 – MCP connector có allowlist. Viết script gọi client.beta.messages.create với một remote MCP server bạn được phép dùng (hoặc server ví dụ của tài liệu), cấu hình mcp_toolset theo kiểu allowlist chỉ bật một tool. In ra [b.type for b in response.content]. 
    for b in response.content:
    if b.type == "mcp_tool_use":
        print("CALL", b.server_name, b.name, b.input)
    elif b.type == "mcp_tool_result":
        print("RESULT error=", b.is_error)
    elif b.type == "text":
        print("TEXT", b.text)
    Kết quả mong đợi: chuỗi khối kiểu ['text', 'mcp_tool_use', 'mcp_tool_result', 'text']; Claude chỉ gọi tool đã bật. Thử xóa MCPToolset và quan sát lỗi validation; lấy token từ biến môi trường, không ghi vào code.
  3. Bài tập 3 – Claude Desktop với Filesystem Server. Mở Settings › Developer › Edit Config, khai báo filesystem chỉ với một thư mục thử nghiệm (ví dụ C:\\Users\\<bạn>\\mcp-sandbox). Khởi động lại và nhờ Claude: "Tạo file ghi-chu.txt trong thư mục sandbox với nội dung là 3 ý chính của bài học này."
    Kết quả mong đợi: Claude hỏi phê duyệt trước khi ghi file; file xuất hiện đúng thư mục; yêu cầu đọc thư mục ngoài sandbox bị server từ chối. Nếu lỗi, mở mcp.log và mcp-server-filesystem.log.
  4. Bài tập 4 – Chia sẻ server cho nhóm trong Claude Code. Trong một repo, chạy claude mcp add --transport http --scope project docs https://example.com/mcp (thay bằng URL thật), mở .mcp.json, đổi header bí mật sang ${DOCS_TOKEN}. Chạy claude mcp list, rồi /mcp trong phiên.
    Kết quả mong đợi: .mcp.json chỉ chứa tham chiếu biến môi trường; đồng nghiệp clone repo sẽ được hỏi phê duyệt server trước khi dùng; claude mcp list hiển thị trạng thái như ✔ Connected hoặc ! Needs authentication.

Tóm tắt ghi nhớ

Key takeaways
  • Host là ứng dụng người dùng thao tác; MCP client là thành phần giao thức, mỗi client nối một server.
  • Tính năng phía client hiện hành: elicitation (form mode / URL mode, theo mẫu MRTR với InputRequiredResult). Roots và sampling đã deprecated từ 2026-07-28.
  • Tự viết client: Client + stdio_client(StdioServerParameters) trong async with; list_tools → đổi sang tool của Claude → call_tool → tool_result có is_error; giới hạn số vòng.
  • Client-side helpers (async_mcp_tool, mcp_message, mcp_resource_to_content, mcp_resource_to_file) giảm code chuyển đổi, dùng với tool runner.
  • MCP connector (beta, mcp-client-2025-11-20): mcp_servers + một mcp_toolset cho mỗi server; chỉ tool calls; server phải public https://; response có mcp_tool_use / mcp_tool_result; tự lo OAuth token; không thuộc ZDR.
  • Claude Desktop: claude_desktop_config.json → mcpServers (command/args/env), khởi động lại. Remote: Settings › Connectors › Add custom connector.
  • Claude Code: claude mcp add (http / sse deprecated / stdio với --), scope local/project/user, .mcp.json chia sẻ qua git với ${VAR}.
  • Bảo mật: least privilege (allowlist), không hard-code secret, cảnh giác prompt injection, giữ con người phê duyệt hành động thay đổi dữ liệu.

Thuật ngữ (Glossary)

Host
Ứng dụng chủ – ứng dụng người dùng tương tác (Claude.ai, IDE, Claude Code…), tạo và điều phối các MCP client.
MCP client
Máy khách MCP – thành phần giao thức trong host, giữ một kết nối trực tiếp tới một MCP server.
Elicitation
Hỏi thêm thông tin người dùng – server yêu cầu client thu thập input từ người dùng giữa chừng (form mode hoặc URL mode).
Multi Round-Trip Requests (MRTR)
Yêu cầu nhiều vòng – server trả InputRequiredResult; client gửi lại request gốc kèm inputResponses và requestState.
Roots / Sampling
Tính năng phía client cũ (thư mục được phép / server nhờ client gọi LLM), deprecated từ phiên bản giao thức 2026-07-28.
stdio transport
Vận chuyển qua stdin/stdout – client khởi chạy server như tiến trình con trên cùng máy.
Streamable HTTP
Transport qua HTTP cho server từ xa; SSE là kiểu cũ, Claude Code đánh dấu deprecated.
ClientSession / Client
Đối tượng phiên làm việc của MCP Python SDK; Client (SDK 2.0.0+) gộp bước thiết lập phiên và initialize vào một khối async with.
MCP connector
Trình kết nối MCP (beta) – tính năng Messages API cho phép kết nối remote MCP server qua tham số mcp_servers.
MCPToolset (mcp_toolset)
Phần tử trong tools chọn và cấu hình tool của một MCP server (default_config, configs).
Allowlist / Denylist
Danh sách cho phép / danh sách chặn – chỉ bật vài tool (mặc định tắt) hoặc tắt vài tool (mặc định bật).
mcp_tool_use / mcp_tool_result
Khối response thể hiện lời gọi tool MCP và kết quả do API nhận về.
mcp_tool_listing
Khối ghi lại danh sách tool của server (header mcp-client-2026-09-15), dùng để ghim tool list.
defer_loading
Hoãn nạp – không gửi mô tả tool cho model lúc đầu; dùng với Tool search tool.
Client-side MCP helpers
Hàm hỗ trợ MCP phía client của Anthropic SDK để chuyển đổi tool, prompt, resource MCP sang kiểu Claude API.
Tool runner
Trình chạy tool của SDK, tự thực thi vòng lặp tool use (tool_runner() / toolRunner()).
Custom connector
Trình kết nối tùy chỉnh – cách thêm remote MCP server vào Claude.ai / Claude Desktop qua Settings › Connectors.
claude_desktop_config.json
File cấu hình server cục bộ của Claude Desktop, khóa mcpServers.
.mcp.json
File cấu hình MCP phạm vi project của Claude Code, đặt ở gốc dự án, chia sẻ qua git.
MCP scope
Phạm vi cấu hình trong Claude Code: local (mặc định), project, user.
MCP Inspector
Công cụ thử nghiệm/gỡ lỗi MCP server (npx @modelcontextprotocol/inspector), có thể lấy access token OAuth để test.
Zero Data Retention (ZDR)
Không lưu giữ dữ liệu – thỏa thuận lưu giữ dữ liệu; MCP connector không thuộc phạm vi này.

Câu hỏi luyện tập

Một startup có MCP server nội bộ chỉ chạy qua stdio trên máy chủ build, và backend của họ cần Claude dùng cả tools lẫn MCP prompts của server đó. Cách tích hợp nào phù hợp?
  1. Dùng MCP connector: khai báo đường dẫn file server trong mcp_servers.url.
  2. Dùng MCP connector với type: "stdio" trong mcp_servers.
  3. Tự viết MCP client trong backend (có thể dùng client-side MCP helpers như async_mcp_tool và mcp_message).
  4. Thêm server làm custom connector trong Claude.ai.
Đáp án C. Tài liệu nói rõ: dùng client-side helpers khi cần server cục bộ, prompts, resources hoặc kiểm soát kết nối. A sai: url phải bắt đầu bằng https:// và server phải public qua HTTP. B sai: type hiện chỉ hỗ trợ url; server stdio cục bộ không kết nối trực tiếp được, và connector chỉ hỗ trợ tool calls, không có prompts. D sai: custom connector dành cho remote server và dùng trong ứng dụng Claude, không phải trong backend của họ.
Đọc request sau và cho biết điều gì xảy ra: 
"mcp_servers": [
  {"type": "url", "url": "https://a.example.com/mcp", "name": "crm"},
  {"type": "url", "url": "https://b.example.com/mcp", "name": "wiki"}
],
"tools": [{"type": "mcp_toolset", "mcp_server_name": "crm"}]
  1. Request thành công; Claude dùng tool của cả crm và wiki.
  2. Request vi phạm quy tắc validation vì server wiki không được MCPToolset nào tham chiếu.
  3. Request thành công; server wiki bị bỏ qua và chỉ ghi cảnh báo ở backend.
  4. Request lỗi vì thiếu authorization_token ở cả hai server.
Đáp án B. Quy tắc "Server must be used": mỗi server trong mcp_servers phải được đúng một MCPToolset tham chiếu. A sai: không có toolset cho wiki. C sai: "chỉ ghi cảnh báo" là cách xử lý tên tool lạ trong configs, không phải server thiếu toolset. D sai: authorization_token là tùy chọn, chỉ cần khi server yêu cầu OAuth.
Đội bảo mật yêu cầu trợ lý lịch chỉ được dùng list_events và search_events, kể cả khi sau này server thêm tool mới. Cấu hình mcp_toolset nào đáp ứng tốt nhất?
  1. Không có default_config; trong configs đặt delete_event và create_event thành enabled: false.
  2. default_config: {"defer_loading": true} và không có configs.
  3. Đặt tool_configuration.allowed_tools trong định nghĩa server.
  4. default_config: {"enabled": false} và trong configs bật list_events, search_events.
Đáp án D. Đây là mẫu allowlist: mặc định tắt, chỉ bật đúng tool cần; tool mới sẽ kế thừa enabled: false. A sai: denylist – mọi tool khác (kể cả tool mới) vẫn bật theo mặc định hệ thống. B sai: defer_loading chỉ hoãn gửi mô tả tool, không tắt tool. C sai: tool_configuration thuộc bản deprecated mcp-client-2025-04-04.
Những phát biểu nào đúng về MCP connector của Messages API? (Chọn 2)
  1. Trong các tính năng của MCP, hiện chỉ tool calls được hỗ trợ.
  2. API tự chạy luồng OAuth và làm mới token cho bạn.
  3. Dữ liệu trao đổi với MCP server thuộc phạm vi Zero Data Retention.
  4. Ứng dụng phải tự thực thi tool rồi gửi tool_result cho mỗi khối mcp_tool_use.
  5. Server phải public qua HTTP; hỗ trợ cả Streamable HTTP và SSE.
Đáp án A, E. Cả hai nằm trong mục Limitations của tài liệu. B sai: bên gọi API phải tự lấy và làm mới access token, truyền qua authorization_token. C sai: MCP connector không thuộc ZDR, dữ liệu lưu theo chính sách chuẩn. D sai: API tự gọi tool và trả mcp_tool_result ngay trong response; tự thực thi là việc của client tool thông thường.
Trong client Python tự viết, một tool MCP trả về CallToolResult với is_error = True. Cách xử lý nào đúng với best practice trong hướng dẫn chính thức?
  1. Bắt exception do call_tool ném ra và dừng chương trình.
  2. Đưa nội dung lỗi vào tool_result với "is_error": true để Claude đọc và thử cách khác.
  3. Bỏ qua tool đó và không gửi tool_result cho tool_use_id tương ứng.
  4. Gọi lại tool vô hạn lần cho tới khi thành công.
Đáp án B. Tài liệu: tool lỗi đặt is_error thay vì raise, giúp Claude đọc lỗi và thử hướng khác; best practice là kiểm tra result.is_error. A sai: call_tool không raise khi tool lỗi. C sai: mọi khối tool_use cần được trả lời trong message kế tiếp. D sai: phải giới hạn số vòng (MAX_TOOL_TURNS), không lặp vô hạn.
Một kế toán đã sửa claude_desktop_config.json để thêm Filesystem Server nhưng không thấy server trong Claude Desktop. Bước nào không nằm trong hướng dẫn xử lý sự cố chính thức?
  1. Thoát hẳn và khởi động lại Claude Desktop.
  2. Kiểm tra đường dẫn trong config là tuyệt đối và hợp lệ.
  3. Chuyển URL của server sang https:// trong mcp_servers.
  4. Xem mcp.log và mcp-server-filesystem.log trong thư mục log.
Đáp án C. mcp_servers và yêu cầu https:// thuộc MCP connector của Messages API, không liên quan tới server stdio cục bộ của Claude Desktop (khai báo bằng command/args trong mcpServers). A, B, D đều là bước trong mục Troubleshooting: khởi động lại, kiểm tra cú pháp và đường dẫn tuyệt đối, xem log (ngoài ra còn chạy lệnh server bằng tay).
Lệnh nào thêm đúng một server stdio Python nhận tham số --port 8080 vào Claude Code?
  1. claude mcp add --env KEY=value --transport stdio myserver -- python server.py --port 8080
  2. claude mcp add --transport stdio myserver python server.py --port 8080
  3. claude mcp add --transport http myserver python server.py --port 8080
  4. claude mcp add myserver --env KEY=value -- --port 8080 python server.py
Đáp án A. Tùy chọn của Claude Code đặt trước --; lệnh và tham số của server đặt sau. B sai: thiếu -- nên Claude Code sẽ cố hiểu --port là tùy chọn của nó. C sai: --transport http cần một URL, không phải lệnh cục bộ. D sai: thứ tự sau -- phải là lệnh của server trước (python server.py) rồi mới tới tham số của nó; ở đây --port bị đặt lên đầu nên server sẽ không chạy đúng.
Một nhóm 8 lập trình viên muốn mọi người dùng chung server MCP tài liệu nội bộ khi làm việc trong repo, nhưng mỗi người có token riêng. Cách nào phù hợp nhất?
  1. Mỗi người chạy claude mcp add với scope user và gửi token cho nhau qua chat.
  2. Ghi token của trưởng nhóm thẳng vào .mcp.json rồi commit.
  3. Dùng scope local (mặc định) để cấu hình tự đồng bộ qua git.
  4. Thêm với --scope project để tạo .mcp.json, header dùng ${DOCS_TOKEN}, commit file; mỗi người tự đặt biến môi trường.
Đáp án D. Scope project lưu ở .mcp.json và chia sẻ qua git; .mcp.json hỗ trợ mở rộng biến môi trường nên không lộ secret. A sai: scope user không chia sẻ, và gửi token qua chat vi phạm quản lý bí mật. B sai: hard-code token vào file commit là lỗi bảo mật nghiêm trọng. C sai: scope local lưu trong ~/.claude.json của từng người, không chia sẻ.
Về các tính năng phía client trong phiên bản giao thức MCP hiện hành, những phát biểu nào đúng? (Chọn 2)
  1. Server nên dùng elicitation form mode để hỏi mật khẩu của người dùng.
  2. URL mode phù hợp cho nhập thông tin đăng nhập vì dữ liệu không đi qua client hay context của LLM.
  3. Sampling là cách được khuyến nghị để server gọi LLM trong các triển khai mới.
  4. Khi cần input, server trả InputRequiredResult và client gửi lại request gốc kèm inputResponses và requestState.
  5. Mỗi MCP client có thể kết nối đồng thời tới nhiều server.
Đáp án B, D. B: URL mode giữ dữ liệu ngoài luồng. D: mô tả đúng mẫu MRTR. A sai: tài liệu cấm dùng form mode cho mật khẩu, API key, token, thông tin thanh toán. C sai: sampling đã deprecated từ 2026-07-28; khuyến nghị tích hợp trực tiếp với API của nhà cung cấp LLM. E sai: mỗi client giữ đúng một kết nối tới một server; host mới điều phối nhiều client.
Code đọc câu trả lời bằng response.content[0].text bỗng lỗi sau khi nhóm đổi beta header sang mcp-client-2026-09-15. Nguyên nhân khả dĩ nhất?
  1. Header mới không còn hỗ trợ mcp_toolset.
  2. Header mới bắt buộc mọi tool phải có defer_loading: true.
  3. Response giờ bắt đầu bằng khối mcp_tool_listing khi API hỏi server danh sách tool, nên content[0] không phải khối text.
  4. Header mới chỉ trả về mcp_tool_result, không còn khối text.
Đáp án C. Tài liệu: với header này, response bắt đầu bằng mcp_tool_listing cho mỗi server được hỏi; nếu code đọc content[0] thì phải bỏ qua các khối này. A sai: header mới bao gồm mọi thứ của mcp-client-2025-11-20, MCPToolset còn nhận thêm trường tools. B sai: defer_loading vẫn là tùy chọn, mặc định false. D sai: Claude vẫn trả khối text như bình thường.
