🧭Server tools và client tools

Ở bài 17–18 bạn đã tự viết tool definition và tự chạy hàm mỗi khi Claude trả về tool_use. Anthropic còn cung cấp sẵn một số tool. Với một vài tool trong số đó, chính API của Anthropic thực thi, nên bạn không cần viết vòng lặp gọi hàm.

Tài liệu chia các tool do Anthropic cung cấp thành hai nhóm:

  • Server tools: API chạy tool ngay trong request rồi chèn kết quả vào hội thoại. Bạn không phải chạy gì và không gửi lại tool_result. Nhóm này gồm web search, web fetch và code execution (ngoài ra còn tool search, MCP connector…).
  • Anthropic-schema client tools: Anthropic định nghĩa sẵn schema mà Claude đã được huấn luyện để dùng, còn ứng dụng của bạn thực thi. Ví dụ là text editor tool, bash tool và computer use.

🔁Vòng lặp phía server và pause_turn

Mọi server tool dùng chung một số cơ chế. Hiểu các cơ chế này trước sẽ giúp bạn đọc response của cả ba tool web search, web fetch và code execution.

Khối server_tool_use

Khi một server tool chạy, response chứa khối server_tool_use với id có tiền tố srvtoolu_. Ngay sau đó, trong cùng lượt assistant, là khối kết quả (ví dụ web_search_tool_result). Hai khối ghép cặp với nhau qua tool_use_id.

// Claude quyết định tìm kiếm: API tự chạy, bạn chỉ "xem" lại
{
  "type": "server_tool_use",
  "id": "srvtoolu_01A2B3C4D5E6F7G8H9",   // tiền tố srvtoolu_ (khác toolu_ của client tool)
  "name": "web_search",
  "input": { "query": "latest quantum computing breakthroughs" }
}

Vòng lặp agent phía server

Với server tools, API thực thi các lần gọi tool trong một server-side agentic loop. Trong một request, Claude có thể tìm kiếm nhiều lần, đọc kết quả rồi tìm tiếp. Nếu một lượt chạy quá lâu, API có thể tạm dừng vòng lặp và trả về stop_reason: "pause_turn".

Theo trang Server tools, khi xử lý pause_turn bạn cần:

  1. Gửi lại nguyên trạng: thêm response đã bị tạm dừng vào messages dưới dạng message assistant, không chỉnh sửa, rồi gọi lại API.
  2. Giữ nguyên tools: lượt bị dừng có thể kết thúc bằng một server_tool_use chưa chạy. Nếu request tiếp theo thiếu tool đó, API trả lỗi validation.
  3. Giữ container: nếu response có container (code execution), hãy gửi lại id của nó. Nếu không, request chạy trong container mới và các file tạo ra trước đó bị mất.
  4. Lặp có giới hạn: lượt tiếp tục vẫn có thể bị dừng lần nữa. Hãy kiểm tra stop_reason sau mỗi lần, đặt số lần tiếp tục tối đa như mọi vòng retry, và giữ tất cả các response bị dừng trong messages theo đúng thứ tự.
# Xử lý pause_turn (Python SDK) – có giới hạn số lần tiếp tục
import anthropic

client = anthropic.Anthropic()  # đọc ANTHROPIC_API_KEY từ biến môi trường, không hard-code
tools = [{"type": "web_search_20250305", "name": "web_search", "max_uses": 10}]
messages = [{"role": "user", "content": "Tổng hợp tin tức mới nhất về điện toán lượng tử"}]

MAX_CONTINUATIONS = 5
for _ in range(MAX_CONTINUATIONS + 1):
    resp = client.messages.create(
        model="claude-opus-5-5", max_tokens=4096,
        tools=tools,              # luôn gửi CÙNG mảng tools
        messages=messages,
    )
    messages.append({"role": "assistant", "content": resp.content})  # giữ nguyên, đúng thứ tự
    if resp.stop_reason != "pause_turn":
        break

for block in resp.content:
    if block.type == "text":
        print(block.text)

Trộn server tool và client tool trong cùng một lượt

Claude có thể gọi song song một server tool (ví dụ web_fetch) và một client tool của bạn (ví dụ run_command). Khi đó API chưa chạy server tool mà trả về ngay để bạn chạy client tool trước:

  • stop_reason là "tool_use", không phải "pause_turn".
  • content có khối server_tool_use nhưng không có khối kết quả tương ứng. Đây là dấu hiệu duy nhất cho biết server tool đang chờ.
  • Để tiếp tục, gửi một message user chỉ gồm các khối tool_result (mỗi tool_use một khối) và giữ nguyên mảng tools. API sẽ chạy server tool đang chờ ở đầu request kế tiếp.
Lỗi thường gặp
  • Thêm text sau các tool_result trong message tiếp tục: API hiểu là lượt assistant đã kết thúc, để lại một server tool chưa có kết quả, và trả lỗi 400 invalid_request_error. Nếu muốn hỏi thêm, hãy gửi một message user riêng sau khi lượt hoàn tất.
  • Bỏ tool khỏi tools khi tiếp tục: lỗi 400 với thông báo kết thúc bằng but no `web_fetch` tool was provided.
  • Chỉ gửi response cuối mà bỏ các response pause_turn trước đó: mất phần việc đã làm và có thể bị lỗi 400.
Mẹo thực chiến (Pro Tip)

Phân biệt nhanh: pause_turn ⇒ gửi lại assistant content nguyên trạng, không thêm gì. tool_use có kèm server_tool_use chưa có kết quả ⇒ chạy client tool và gửi message user chỉ chứa tool_result. Cả hai trường hợp đều phải giữ nguyên tools.

Định nghĩa tool và các tham số

{
  "type": "web_search_20250305",
  "name": "web_search",
  "max_uses": 5,                                     // tùy chọn: giới hạn số lần tìm trong 1 lượt
  "allowed_domains": ["example.com", "trusteddomain.org"], // chỉ lấy kết quả từ các domain này
  // "blocked_domains": ["untrustedsource.com"],      // HOẶC chặn domain – không dùng cả hai
  "user_location": {                                 // tùy chọn: địa phương hóa kết quả
    "type": "approximate",                            // bắt buộc là "approximate"
    "city": "Hanoi", "country": "VN",                 // country: mã ISO 3166-1 alpha-2
    "timezone": "Asia/Ho_Chi_Minh"                    // IANA time zone ID
  }
}
  • max_uses: giới hạn số lượt tìm trong một lượt (turn). Câu hỏi về một sự kiện đơn lẻ thường cần 1–3 lượt tìm. Nghiên cứu so sánh nhiều đối tượng có thể cần từ 10 lượt trở lên. Lượt tìm bị lỗi vẫn bị tính. Vượt giới hạn thì kết quả trả về lỗi max_uses_exceeded.
  • allowed_domains / blocked_domains: chỉ dùng một trong hai. Gửi cả hai sẽ bị lỗi 400. Domain không ghi scheme (example.com, không ghi https://). Subdomain được bao gồm tự động. Web search hỗ trợ đường dẫn con (example.com/blog). Wildcard chỉ dùng được trong phần path (example.com/*), không dùng được trong domain (*.example.com là không hợp lệ).
  • user_location: cần ít nhất một trong các trường city, region, country, timezone.
Lỗi thường gặp: tấn công homograph

Ký tự Unicode trong tên miền có thể qua mặt bộ lọc domain. Ví dụ аmazon.com dùng chữ а Cyrillic, trông giống hệt amazon.com nhưng là một domain khác. Tài liệu khuyên chỉ dùng tên miền ASCII trong danh sách allow/block và rà soát các mục chứa ký tự ngoài ASCII.

Lỗi nằm trong body của response 200

Khi tool gặp lỗi (ví dụ vượt rate limit), API vẫn trả HTTP 200. Lỗi nằm trong khối kết quả, và lúc này content là một object lỗi thay vì danh sách kết quả:

{ "type": "web_search_tool_result", "tool_use_id": "srvtoolu_a93jad",
  "content": { "type": "web_search_tool_result_error", "error_code": "max_uses_exceeded" } }

Các mã lỗi: too_many_requests, invalid_tool_input, max_uses_exceeded, query_too_long, request_too_large (thường do danh sách domain quá dài), unavailable. Nếu tìm thành công nhưng không có kết quả nào, API trả về danh sách content rỗng, không phải lỗi.

Dynamic filtering

Với web search cơ bản, mọi kết quả tìm kiếm đều được nạp vào context window, kể cả những phần không liên quan. Từ web_search_20260209, Claude viết và chạy code để lọc kết quả trước, nên chỉ phần liên quan mới vào context. Cách này giảm token cho các request phải tìm nhiều. Dynamic filtering chạy bên trong code execution: trường allowed_callers mặc định là ["code_execution_20260120"], và API tự cấp code execution nên bạn không cần thêm vào tools. Tài liệu ghi rõ không tính thêm phí cho code execution trong trường hợp này, ngoài phí token thông thường.

  • Muốn gọi trực tiếp, không dùng dynamic filtering, hãy đặt "allowed_callers": ["direct"]. Với model không hỗ trợ programmatic tool calling, thiết lập này là bắt buộc, nếu thiếu sẽ bị lỗi 400.
  • Dynamic filtering không đủ điều kiện ZDR/HIPAA. Cần ZDR thì dùng bản cơ bản, hoặc đặt allowed_callers: ["direct"].

Kiểm tra URL: hàng rào chống rò rỉ dữ liệu

Vì lý do bảo mật, web fetch chỉ tải được URL đã từng xuất hiện trong ngữ cảnh hội thoại:

  • URL trong message của người dùng;
  • URL trong kết quả của client tool;
  • URL từ kết quả web search hoặc web fetch trước đó.

Claude không tải được URL chỉ có trong output của chính nó, hoặc chỉ có trong system prompt. Muốn tải URL trong system prompt thì phải đưa URL đó vào message của người dùng. Kết quả của các server tool khác (code execution, MCP connector, tool search) cũng không được tính là nguồn hợp lệ. Ngoài ra tool từ chối URL có vẻ chứa thông tin xác thực như API key hay mật khẩu, trừ khi thông tin đó có trong system prompt hoặc text của message người dùng.

Cảnh báo bảo mật: data exfiltration

Theo tài liệu, bật web fetch trong môi trường mà Claude vừa xử lý đầu vào không tin cậy vừa có dữ liệu nhạy cảm sẽ tạo rủi ro data exfiltration. Ví dụ, một trang web độc hại chèn lệnh để Claude gắn dữ liệu bí mật vào URL rồi tải URL đó. Các quy tắc kiểm tra URL ở trên giảm rủi ro nhưng vẫn còn rủi ro tồn dư. Tài liệu đề xuất: tắt hẳn web fetch, giới hạn max_uses, dùng allowed_domains cho các domain an toàn đã biết, và dùng url_sources để không tính kết quả của client tool là nguồn URL.

# Text editor tool – client tool: ỨNG DỤNG CỦA BẠN thao tác file
import anthropic
from pathlib import Path

BASE = Path("./workspace").resolve()   # least privilege: chỉ cho phép trong thư mục này
MAX_CHARS = 10000

def safe_path(p: str) -> Path:
    full = (BASE / p).resolve()
    if not full.is_relative_to(BASE):      # chặn path traversal (../../etc/passwd)
        raise PermissionError("Path outside workspace")
    return full

def handle_editor(inp: dict) -> str:
    cmd, path = inp["command"], safe_path(inp["path"])
    if cmd == "view":
        if path.is_dir():
            return "\n".join(sorted(x.name for x in path.iterdir()))
        lines = path.read_text(encoding="utf-8").splitlines()
        start, end = inp.get("view_range", [1, -1])
        end = len(lines) if end == -1 else end
        text = "\n".join(f"{i}: {l}" for i, l in enumerate(lines[start-1:end], start))
        return text[:MAX_CHARS]                # tự cắt theo max_characters
    if cmd == "str_replace":
        src = path.read_text(encoding="utf-8")
        n = src.count(inp["old_str"])
        if n != 1:                           # 0 hoặc nhiều chỗ khớp ⇒ báo lỗi để Claude thử lại
            raise ValueError(f"Found {n} matches. Provide more context for a unique match.")
        path.write_text(src.replace(inp["old_str"], inp["new_str"]), encoding="utf-8")
        return "Successfully replaced text at exactly one location."
    if cmd == "create":
        path.write_text(inp["file_text"], encoding="utf-8")
        return f"Created {inp['path']}"
    if cmd == "insert":
        lines = path.read_text(encoding="utf-8").splitlines(keepends=True)
        lines.insert(inp["insert_line"], inp["insert_text"])
        path.write_text("".join(lines), encoding="utf-8")
        return "Inserted."
    raise ValueError(f"Unknown command {cmd}")

client = anthropic.Anthropic()
tools = [{"type": "text_editor_20250728", "name": "str_replace_based_edit_tool",
          "max_characters": MAX_CHARS}]       # không có input_schema
messages = [{"role": "user", "content": "There's a syntax error in my primes.py file. Can you fix it?"}]

for _ in range(10):                          # giới hạn số vòng lặp agent
    resp = client.messages.create(model="claude-sonnet-5-5", max_tokens=2048,
                                  tools=tools, messages=messages)
    messages.append({"role": "assistant", "content": resp.content})
    if resp.stop_reason != "tool_use":
        break
    results = []
    for b in resp.content:
        if b.type == "tool_use":
            try:
                results.append({"type": "tool_result", "tool_use_id": b.id,
                                "content": handle_editor(b.input)})
            except Exception as e:           # lỗi ⇒ is_error: true để Claude tự sửa
                results.append({"type": "tool_result", "tool_use_id": b.id,
                                "content": f"Error: {e}", "is_error": True})
    messages.append({"role": "user", "content": results})

Tài liệu hướng dẫn xử lý các lỗi sau bằng cách trả tool_result có "is_error": true: file không tồn tại, str_replace khớp nhiều chỗ, không khớp chỗ nào, lỗi quyền ghi. Tài liệu cũng khuyên sao lưu file trước khi sửa, ghi rõ đường dẫn file trong prompt, và nêu cụ thể vấn đề cần sửa (“There's a syntax error in my primes.py file…” sẽ tốt hơn “Can you fix my code?”).

Các phiên bản cũ computer_20251124 và computer_20250124 vẫn cần beta header (computer-use-2025-11-24, computer-use-2025-01-24) và dành cho các model đời trước. Mỗi ảnh chụp màn hình tốn khoảng 1.000–1.800 input token. Nếu tác vụ chỉ trên trang web, tài liệu gợi ý browser use tool sẽ phù hợp hơn.

Tài liệu computer use khuyến nghị: dùng VM hoặc container riêng với quyền tối thiểu; không đưa dữ liệu nhạy cảm hay thông tin đăng nhập cho model; giới hạn Internet bằng allowlist domain; yêu cầu con người xác nhận các hành động có hậu quả (thanh toán, chấp nhận điều khoản). Ảnh chụp màn hình được quét bằng classifier chống prompt injection. Chi tiết computer use được học sâu hơn ở module Agents.

🛡️Bảo mật khi dùng built-in tools

Phần này tổng hợp khuyến nghị của Anthropic và đối chiếu với các nguyên tắc chung của IPA (「安全なウェブサイトの作り方」, 「セキュア・プログラミング講座」): kiểm tra đầu vào, cấp quyền tối thiểu, không để lộ thông tin bí mật.

  1. Không hard-code API key: SDK đọc ANTHROPIC_API_KEY từ biến môi trường. Đừng để key xuất hiện trong prompt hay URL, vì web fetch từ chối URL có vẻ chứa thông tin xác thực, và chính bạn cũng không nên để lộ key.
  2. Coi mọi nội dung web là không tin cậy: trang web có thể chứa prompt injection, tức các chỉ dẫn ẩn để điều khiển Claude. Không cho kết quả web search/fetch kích hoạt trực tiếp các hành động có hậu quả (gửi email, chuyển tiền, ghi file) mà không có human-in-the-loop.
  3. Least privilege: dùng allowed_domains và max_uses ở mức cần thiết. Text editor chỉ được truy cập một thư mục làm việc, có chặn path traversal. Computer use chạy trong VM riêng.
  4. Tách dữ liệu nhạy cảm khỏi đầu vào không tin cậy khi bật web fetch, hoặc tắt web fetch và dùng url_sources để thu hẹp nguồn URL.
  5. Quản trị tập trung: quản trị viên có thể tắt web search/fetch hoặc giới hạn domain cho cả tổ chức trong Claude Console (Capabilities). allowed_domains ở cấp request phải là tập con của danh sách cho phép cấp tổ chức.
  6. Lưu giữ dữ liệu: code execution lưu dữ liệu container tối đa 30 ngày (không ZDR). Dynamic filtering của web tools cũng không đủ điều kiện ZDR. Hãy cân nhắc khi xử lý dữ liệu cá nhân.

Tóm tắt ghi nhớ

Key takeaways
  • Server tools (web search, web fetch, code execution) do API của Anthropic thực thi. Response có server_tool_use (id srvtoolu_) và khối kết quả, bạn không gửi tool_result.
  • Client tools, kể cả loại có schema của Anthropic (text editor, computer use), do ứng dụng của bạn thực thi và trả tool_result.
  • pause_turn ⇒ gửi lại nguyên assistant content với cùng tools (và container nếu có), lặp có giới hạn. Trộn server và client tool ⇒ stop_reason: "tool_use" và gửi message chỉ gồm tool_result.
  • Lỗi của server tool trả về HTTP 200, nằm trong body (*_tool_result_error + error_code).
  • Web search: citations luôn bật. max_uses, allowed_domains hoặc blocked_domains, user_location. Phí $10/1.000 lượt tìm cộng token. Phải gửi lại encrypted_content nguyên vẹn.
  • Web fetch: chỉ tải URL đã có trong hội thoại. Citations mặc định tắt. Có max_content_tokens. Không tính phí thêm. Cẩn thận rủi ro data exfiltration.
  • Code execution: sandbox Linux, Python 3.11, 5 GiB RAM, 1 CPU, không Internet. Tái sử dụng bằng container. Mỗi tháng có 1.550 giờ miễn phí, sau đó $0,05/giờ. Miễn phí khi dùng cùng web tools bản 20260209 trở lên.
  • Text editor: text_editor_20250728 + str_replace_based_edit_tool, không cần schema. Gồm 4 lệnh view / str_replace / create / insert. Nên giới hạn thư mục và sao lưu trước khi sửa.

Thuật ngữ (Glossary)

Server tool
Công cụ phía server: tool do API của Anthropic thực thi trong request. Kết quả nằm sẵn trong response, không cần tool_result.
Client tool
Công cụ phía client: tool do ứng dụng của bạn thực thi. Claude trả về tool_use, bạn gửi lại tool_result.
Anthropic-schema client tool
Công cụ phía client theo schema của Anthropic: schema do Anthropic định nghĩa (text editor, bash, computer use) nhưng bạn thực thi.
server_tool_use
Khối trong response cho biết Claude đã gọi một server tool. id có tiền tố srvtoolu_.
Server-side agentic loop
Vòng lặp agent phía server: API tự gọi server tool nhiều lần trong một request.
pause_turn
stop_reason cho biết API đã tạm dừng một lượt chạy dài. Gửi lại assistant content nguyên trạng để chạy tiếp.
max_uses
Giới hạn số lần web search/web fetch trong một lượt. Lần gọi bị lỗi vẫn bị tính.
allowed_domains / blocked_domains
Danh sách domain được phép / bị chặn. Chỉ dùng một trong hai.
user_location
Vị trí xấp xỉ (type: "approximate") để địa phương hóa kết quả web search.
encrypted_content
Nội dung kết quả tìm kiếm đã mã hóa, phải gửi lại nguyên vẹn ở các lượt sau.
Dynamic filtering
Lọc động: từ phiên bản _20260209, Claude viết code để lọc kết quả web search/fetch trước khi đưa vào context.
allowed_callers
Quy định tool được gọi trực tiếp ("direct"), từ code execution, hay cả hai.
Data exfiltration
Rò rỉ dữ liệu ra ngoài: dữ liệu nhạy cảm bị gửi ra ngoài, ví dụ được nhúng vào URL mà Claude tải.
url_sources
Tham số của web fetch, dùng để tắt hoặc thu hẹp các nguồn URL hợp lệ (user input, kết quả client tool, kết quả server tool).
max_content_tokens
Giới hạn xấp xỉ số token của nội dung văn bản mà web fetch đưa vào context.
Cache bypass (use_cache)
Bỏ qua bộ nhớ đệm: đặt use_cache: false để web fetch lấy nội dung mới (từ web_fetch_20260309).
Sandboxed container
Vùng chứa cách ly: môi trường Linux của code execution, không có mạng, cách ly hoàn toàn.
container (tham số)
ID container của response trước, truyền lại để giữ file giữa các request.
$OUTPUT_DIR
Thư mục mà file đặt ở cấp cao nhất được trả về dưới dạng file_id sau mỗi lần gọi bash_code_execution.
container_upload
Content block dùng để tham chiếu file (đã tải lên bằng Files API) vào container code execution.
Schema-less tool
Công cụ không cần khai báo schema: schema đã có sẵn trong model (text editor tool).
str_replace_based_edit_tool
Tên bắt buộc của text editor tool từ phiên bản cho Claude 4.
Computer use
Điều khiển máy tính: bộ client tool để Claude thao tác màn hình, chuột, bàn phím trong môi trường của bạn.
Prompt injection
Chèn lệnh độc hại vào prompt: chỉ dẫn ẩn trong nội dung (trang web, file) nhằm điều khiển Claude.
Least privilege
Đặc quyền tối thiểu: chỉ cấp cho tool hoặc agent đúng quyền cần thiết.

Câu hỏi luyện tập

Một công ty fintech xây chatbot trả lời câu hỏi về giá cổ phiếu hôm nay. Yêu cầu: thông tin phải mới, có nguồn rõ ràng, và chỉ lấy từ hai trang tin tài chính mà bộ phận pháp chế đã duyệt. Cách nào phù hợp nhất và tốn ít công sức nhất?
  1. Tự viết một client tool gọi API của công cụ tìm kiếm, tự trích dẫn nguồn bằng code, rồi gửi kết quả qua tool_result.
  2. Bật web fetch với blocked_domains liệt kê mọi trang tin không được duyệt.
  3. Bật web search tool với allowed_domains chứa hai domain đã duyệt và đặt max_uses phù hợp.
  4. Chỉ cần ghi vào system prompt “chỉ dùng hai trang này” vì Claude đã biết giá cổ phiếu từ dữ liệu huấn luyện.
Đáp án C. Web search là server tool, cho thông tin vượt knowledge cutoff, luôn có citations, và allowed_domains giới hạn nguồn. A làm được nhưng tốn công tự xây và tự lo trích dẫn, trong khi đã có tool dựng sẵn. B sai: web fetch cần URL cụ thể đã xuất hiện trong hội thoại, không “tìm” giá mới được, và danh sách chặn không thể liệt kê hết mọi trang. D sai: giá hôm nay nằm sau knowledge cutoff, và system prompt không phải hàng rào kỹ thuật.
