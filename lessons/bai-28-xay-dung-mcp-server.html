Sau bài này bạn sẽ

  • Phân biệt ba building blocks của một MCP server – tools, resources, prompts – và biết ai điều khiển mỗi loại (model, ứng dụng, người dùng).
  • Dựng một MCP server bằng MCP Python SDK (bản 2.x, lớp MCPServer – tên mới của FastMCP) với uv và gói mcp[cli].
  • Định nghĩa tool bằng @mcp.tool(), resource tĩnh và resource template bằng @mcp.resource(), prompt bằng @mcp.prompt().
  • Xử lý lỗi đúng cách (ToolError), tránh làm hỏng kênh stdio khi ghi log.
  • Kiểm thử server bằng MCP Inspector (web / CLI / TUI), bằng Client in-memory trong pytest, rồi kết nối vào Claude for Desktop.

🧩MCP server là gì và gồm những gì?

Theo tài liệu MCP, MCP server là chương trình phơi bày (expose) các năng lực cụ thể cho ứng dụng AI thông qua các giao diện giao thức đã chuẩn hóa. Ví dụ quen thuộc: server hệ thống file để truy cập tài liệu, server database để truy vấn dữ liệu, server GitHub để quản lý mã nguồn, server Slack để nhắn tin nhóm, server lịch để lên lịch họp.

Ở bài 27 bạn đã biết kiến trúc host – client – server. Bài này chuyển sang phía người viết server: bạn sẽ tự viết một server Python, khai báo các năng lực của nó và kiểm thử trước khi đưa vào Claude.

Một server cung cấp chức năng qua ba khối xây dựng (bảng dịch từ trang Understanding MCP servers):

KhốiGiải thíchVí dụAi điều khiển
ToolsHàm mà LLM có thể chủ động gọi; model tự quyết định khi nào dùng dựa trên yêu cầu của người dùng. Tool có thể ghi database, gọi API ngoài, sửa file, kích hoạt logic khác.Tìm chuyến bay, gửi tin nhắn, tạo sự kiện lịchModel
ResourcesNguồn dữ liệu thụ động, chỉ đọc, cung cấp ngữ cảnh: nội dung file, schema database, tài liệu API.Lấy tài liệu, truy cập knowledge base, đọc lịchApplication (ứng dụng)

Ví dụ đời thường

Hình dung một nhà hàng: tools là các món bếp nấu theo yêu cầu (nhân viên – tức model – quyết định gọi món nào cho phù hợp), resources là thực đơn và bảng thành phần dán trên bàn (nhà hàng – tức ứng dụng – chọn đặt cái gì trước mặt khách), còn prompts là các “set menu” khách tự chọn bằng cách chỉ tay (người dùng chủ động gọi).

Mẹo thực chiến (Pro Tip)

Khi phân vân nên làm một tính năng thành tool hay resource, hãy hỏi: “Ai nên quyết định lúc nào dùng nó?” Cần model tự gọi khi thấy cần (có thể có tác dụng phụ) ⇒ tool. Dữ liệu chỉ đọc mà ứng dụng/người dùng chọn đính kèm làm ngữ cảnh ⇒ resource. Quy trình lặp lại mà người dùng muốn bấm một phát là chạy ⇒ prompt.

🐍Python SDK: từ FastMCP đến MCPServer

MCP có SDK chính thức cho nhiều ngôn ngữ (Python, TypeScript, Java, Kotlin, C#, Ruby, Rust, Go – đều có tab riêng trong hướng dẫn Build an MCP server). Bài này dùng Python SDK vì nó cho phép khai báo năng lực chỉ bằng decorator và type hints.

Đổi tên quan trọng ở bản 2.x

Nhiều tài liệu, khóa học cũ (kể cả bản đầu của khóa Academy) dùng lớp FastMCP. Theo trang What's new in v2 của Python SDK, pip install mcp hiện cài bản 2.x, và lớp server cấp cao đã được đổi tên cùng với module của nó:

🕰️v1.x (cũ)

✨v2.x (hiện hành)

Một số thay đổi khác của v2 cần biết khi đọc code cũ:

  • Thuộc tính Python chuyển sang snake_case (structured_content, is_error, input_schema, next_cursor), nhưng JSON trên đường truyền vẫn là camelCase như trước (structuredContent, isError, inputSchema).
  • Tùy chọn transport chuyển từ hàm khởi tạo sang run(): MCPServer("x", port=9000) giờ báo TypeError.
  • Handler đồng bộ (def thường) chạy trên worker thread để không chặn server.
  • SDK v2 triển khai bản đặc tả MCP 2026-07-28 và vẫn phục vụ được client đời 2025.
  • Đã bỏ: WebSocket transport, Tasks API thử nghiệm và một số đường import mcp.shared.
Lỗi thường gặp

Copy code mẫu from mcp.server.fastmcp import FastMCP từ blog cũ vào dự án vừa uv add "mcp[cli]" (cài bản 2.x) rồi gặp ImportError. Cách sửa: đổi sang from mcp.server import MCPServer, hoặc ghim phiên bản 1.x nếu bạn cố ý duy trì code cũ (tài liệu v1 vẫn còn tại py.sdk.modelcontextprotocol.io/v1/).

🛠️Định nghĩa tools

Tools cho phép model thực hiện hành động. Mỗi tool định nghĩa một thao tác cụ thể với đầu vào/đầu ra có kiểu. Tool là giao diện có schema; MCP dùng JSON Schema để kiểm tra hợp lệ. Tool có thể yêu cầu người dùng đồng ý trước khi chạy, giúp con người giữ quyền kiểm soát các hành động do model đề xuất.

MethodMục đíchTrả về

Ví dụ đầy đủ: weather server (từ hướng dẫn chính thức)

Hướng dẫn Build an MCP server xây server thời tiết có hai tool get_alerts và get_forecast, gọi API của National Weather Service (Mỹ). Phần khởi tạo và hàm trợ giúp:

# weather.py – phần đầu
from typing import Any

import httpx2                                   # HTTP client mà SDK đã kéo theo sẵn
from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError

mcp = MCPServer("weather")

NWS_API_BASE = "https://api.weather.gov"
USER_AGENT = "weather-app/1.0"


async def make_nws_request(url: str) -> dict[str, Any] | None:
    """Make a request to the NWS API with proper error handling."""
    headers = {"User-Agent": USER_AGENT, "Accept": "application/geo+json"}
    async with httpx2.AsyncClient(follow_redirects=True) as client:
        try:
            response = await client.get(url, headers=headers, timeout=30.0)
            response.raise_for_status()
            return response.json()
        except Exception:
            return None

Hai tool – chú ý docstring có mục Args: mô tả từng tham số; đây là thông tin Claude đọc để quyết định gọi tool nào và truyền gì:

@mcp.tool()
async def get_alerts(state: str) -> str:
    """Get weather alerts for a US state.

    Args:
        state: Two-letter US state code (e.g. CA, NY)
    """
    url = f"{NWS_API_BASE}/alerts/active/area/{state.upper()}"
    data = await make_nws_request(url)

    if not data or "features" not in data:
        raise ToolError("Unable to fetch alerts.")   # thông báo lỗi tới được model

    if not data["features"]:
        return "No active alerts for this state."

    alerts = [format_alert(feature) for feature in data["features"]]
    return "\n---\n".join(alerts)


@mcp.tool()
async def get_forecast(latitude: float, longitude: float) -> str:
    """Get weather forecast for a location.

    Args:
        latitude: Latitude of the location
        longitude: Longitude of the location
    """
    points_data = await make_nws_request(f"{NWS_API_BASE}/points/{latitude},{longitude}")
    if not points_data:
        raise ToolError("Unable to fetch forecast data for this location.")
    # ... lấy URL forecast, định dạng 5 kỳ dự báo đầu tiên, nối bằng "\n---\n"


if __name__ == "__main__":
    mcp.run(transport="stdio")   # chạy: uv run weather.py

(Hàm format_alert và phần định dạng forecast được rút gọn; mã đầy đủ ở repo modelcontextprotocol/quickstart-resources, thư mục weather-server-python.)

Schema được sinh thế nào?

Theo trang Tools của Python SDK:

  • Tham số không có giá trị mặc định được đưa vào required; tham số có mặc định là tùy chọn.
  • Annotated[T, Field(description=..., ge=1, le=50)] thêm mô tả và ràng buộc minimum/maximum.
  • Literal[...] sinh ra enum; tham số kiểu Pydantic BaseModel được lồng qua $defs và hàm nhận về một instance đã được kiểm tra hợp lệ.
  • Đối số sai bị từ chối trước khi hàm chạy; lỗi được trả về model như kết quả tool (ví dụ “Input should be less than or equal to 50”) để model tự sửa.
  • Tham số của decorator: name (mặc định = tên hàm), title (nhãn dễ đọc cho UI), description (mặc định = docstring), annotations (gợi ý hành vi).
# Tool có ràng buộc tham số và annotations (theo trang Tools của SDK)
from typing import Annotated, Literal
from pydantic import Field
# ToolAnnotations: xem đường import trong tài liệu SDK (mcp.types)

@mcp.tool(title="Search the catalog",
          annotations=ToolAnnotations(read_only_hint=True, open_world_hint=False))
def search_books(
    query: str,
    limit: Annotated[int, Field(description="Số kết quả tối đa", ge=1, le=50)] = 10,
    sort: Literal["relevance", "newest"] = "relevance",
) -> str:
    """Search the catalog by title or author."""
    ...

Phía giao thức, client nhận được tool definition dạng JSON (ví dụ trong trang Server concepts) – để ý inputSchema và outputSchema viết camelCase:

{
  "name": "searchFlights",
  "title": "Search Flights",
  "description": "Search for available flights",
  "inputSchema": {
    "type": "object",
    "properties": {
      "origin": { "type": "string", "description": "Departure city" },
      "destination": { "type": "string", "description": "Arrival city" },
      "date": { "type": "string", "format": "date", "description": "Travel date" }
    },
    "required": ["origin", "destination", "date"]
  },
  "outputSchema": { /* … mảng flights { flightNumber, priceUsd } … */ }
}

Tool annotations – gợi ý, không phải bảo mật

open_world_hintCho biết tool làm việc với “thế giới mở” (như web) hay một tập dữ liệu khép kín.

Lưu ý

Tài liệu SDK nói rõ annotations là gợi ý cho client, không phải cơ chế bảo mật. Client có thể dùng chúng để quyết định có hỏi xác nhận hay không, nhưng server vẫn phải tự kiểm tra quyền và đầu vào.

Kết quả: content và structured_content

Kiểu trả về quyết định kết quả. Với -> str hay -> int, SDK trả structured_content dạng {'result': ...} kèm content dạng text cho model. content là phần dành cho model; structured_content là dữ liệu có kiểu dành cho ứng dụng client. Ở tầng giao thức, structuredContent tuân theo outputSchema, và để tương thích ngược kết quả cũng chứa JSON đã serialize dưới dạng text.

Xử lý lỗi: ToolError và ngoại lệ thường

✅raise ToolError("…")

  • Import: from mcp.server.mcpserver.exceptions import ToolError.
  • Lệnh gọi vẫn thành công ở tầng giao thức, nhưng kết quả có is_error=True.
  • Thông báo của bạn (có tiền tố tên tool) tới được model ⇒ model đọc và có thể thử lại.
  • Server log ở mức INFO, không kèm traceback.

💥Ngoại lệ khác (vd KeyError)

  • Model chỉ nhận “Error executing tool <tên>”, không có nội dung ngoại lệ.
  • Traceback đầy đủ được log ở mức ERROR trên server ⇒ chi tiết nội bộ không lộ ra.
  • MCPError là đường thứ ba: làm hỏng cả request bằng lỗi JSON-RPC, model không nhận được kết quả.
Mẹo thực chiến (Pro Tip)

Lỗi mà model có thể tự khắc phục (sai mã bang, không tìm thấy sách, thiếu quyền đọc thư mục) ⇒ raise ToolError với thông điệp rõ ràng, gợi ý cách sửa. Lỗi nội bộ (chuỗi kết nối DB, stack trace) ⇒ để ngoại lệ thường, SDK sẽ tự che nội dung khỏi model – đúng tinh thần không để lộ thông tin nhạy cảm qua thông báo lỗi.

Context: tiến độ, đọc resource, hỏi người dùng

Thêm một tham số có annotation Context (from mcp.server.mcpserver import Context) và SDK sẽ tiêm vào ở mỗi request. Tham số này không xuất hiện trong input schema nên model không thấy. Một số thành viên: ctx.request_id, await ctx.report_progress(progress, total, message), await ctx.read_resource(uri), await ctx.elicit(message, schema), và các hàm thông báo thay đổi danh sách. Lưu ý: logging không nằm trong Context – tài liệu khuyên dùng module logging chuẩn của Python.

from mcp.server import MCPServer
from mcp.server.mcpserver import Context

mcp = MCPServer("Bookshop")

@mcp.tool()
def search_books(query: str, ctx: Context) -> str:
    return f"[request {ctx.request_id}] Found 3 books matching {query!r}."

📄Định nghĩa resources và resource templates

Resources cung cấp quyền truy cập có cấu trúc tới thông tin mà ứng dụng AI có thể lấy về và đưa cho model làm ngữ cảnh. Chúng phơi bày dữ liệu từ file, API, database… Ứng dụng truy cập trực tiếp và tự quyết định cách dùng: chọn phần liên quan, tìm bằng embeddings, hay đưa nguyên cho model. Mỗi resource có một URI duy nhất (vd file:///path/to/document.md) và có thể khai báo MIME type.

Resources hỗ trợ hai kiểu khám phá:

  • Direct resources (resource trực tiếp) – URI cố định trỏ tới dữ liệu cụ thể. Ví dụ: calendar://events/2027-06.
  • Resource templates – URI có tham số cho truy vấn linh hoạt. Ví dụ: travel://activities/{city}/{category}; khi điền, travel://activities/Barcelona/museums trả về mọi bảo tàng ở Barcelona. Template có thể kèm metadata như title, description, MIME type dự kiến.
MethodMục đíchTrả về
resources/listLiệt kê direct resourcesMảng resource descriptor
resources/templates/listKhám phá resource templatesMảng định nghĩa template
resources/readLấy nội dung resourceDữ liệu kèm metadata
completion/completeGợi ý giá trị tham sốMảng giá trị gợi ý
subscriptions/listenTheo dõi thay đổi resourceLuồng thông báo cập nhật

Viết resource trong Python SDK

  • Resource tĩnh: @mcp.resource("config://app") gắn một URI cố định vào một hàm. Tên hàm thành tên resource, docstring thành description, giá trị trả về thành nội dung. Hàm chỉ chạy khi client đọc URI đó, không chạy khi liệt kê.
  • Template: placeholder trong ngoặc nhọn như {user_id}. Hàm phải có tham số trùng tên; nếu lệch tên, decorator ném ValueError ngay lúc import. Kết quả báo URI cụ thể mà client đã yêu cầu.
  • mime_type: đặt trên decorator; mặc định là plain text, SDK không tự suy ra từ giá trị trả về.
  • Kiểu trả về: str → text; bytes → blob mã hóa base64; dict, list, Pydantic model, dataclass → serialize thành JSON text.
  • Resource được định danh bằng URI, không phải tên; có thể ghi đè bằng name=, title=, description=.
  • Resource tĩnh xuất hiện trong resources/list; template bị loại khỏi danh sách đó và xuất hiện trong resources/templates/list với trường uriTemplate.
# docs_server.py – resource tĩnh + resource template
from mcp.server import MCPServer

mcp = MCPServer("DocumentMCP")

docs = {
    "deposition.md": "Lời khai của nhân chứng Angela Smith…",
    "report.pdf": "Báo cáo kỹ thuật về tháp ăng-ten 20m…",
}

@mcp.resource("docs://documents", mime_type="application/json")
def list_docs() -> list[str]:
    """Danh sách ID tài liệu hiện có."""
    return list(docs.keys())                     # list → JSON text

@mcp.resource("docs://documents/{doc_id}", mime_type="text/plain")
def fetch_doc(doc_id: str) -> str:             # tên tham số khớp {doc_id}
    """Nội dung một tài liệu theo ID."""
    if doc_id not in docs:
        # ngoại lệ thường ⇒ client nhận lỗi -32603 chỉ nêu URI, traceback ở log server
        raise KeyError(doc_id)
    return docs[doc_id]

Ghi chú: trang Handling errors của SDK nêu ResourceNotFoundError (mã -32602, kèm URI trong data) và ResourceError (mã -32603, kèm thông điệp của bạn). Resource không có kết quả is_error như tool – chỉ có đường lỗi giao thức. Muốn client thấy thông điệp cụ thể, dùng ResourceError (tra đường import trong tài liệu API của SDK); ngoại lệ thường như ví dụ trên chỉ trả -32603 nêu URI.

Ở tầng giao thức, client đọc resource bằng resources/read. Kết quả theo bản đặc tả 2026-07-28 có thêm caching hints:

{
  "jsonrpc": "2.0", "id": 2,
  "result": {
    "resultType": "complete",
    "contents": [{
      "uri": "calendar://events/2027-06",
      "mimeType": "application/json",
      "text": "{\"busy\":[{\"startDate\":\"2027-06-03\",\"endDate\":\"2027-06-04\"}]}"
    }],
    "ttlMs": 60000,            // client được coi kết quả là "tươi" trong 60 000 ms
    "cacheScope": "private"    // không chia sẻ cache giữa các ngữ cảnh ủy quyền khác nhau
  }
}

Parameter completion

Server khai báo capability completions có thể gợi ý giá trị cho tham số template. Ví dụ gõ “Par” cho city trong weather://forecast/{city}/{date} có thể gợi ý “Paris” hoặc “Park City”. Khi template có nhiều tham số, client nên gửi các giá trị đã chọn trong context.arguments để server thu hẹp gợi ý (vd đã chọn origin = JFK, gõ “Bar” cho destination ⇒ gợi ý BCN, BGI).

Theo dõi thay đổi

Để theo dõi resource cụ thể, client gửi subscriptions/listen với danh sách URI trong bộ lọc resourceSubscriptions. Server hỗ trợ thông báo cho từng resource khai báo "subscribe": true trong capability resources, và gửi notifications/resources/updated mỗi khi resource được theo dõi thay đổi.

Mẹo thực chiến (Pro Tip)

Người dùng muốn gõ @report.pdf trong ô chat để đính kèm nội dung tài liệu ⇒ phơi bày tài liệu thành resource (template docs://documents/{doc_id}) để ứng dụng chèn thẳng vào ngữ cảnh – không tốn một vòng tool call như khi để model tự gọi tool read_doc.

💬Định nghĩa prompts

Prompts là các mẫu tái sử dụng. Chúng cho phép tác giả MCP server cung cấp prompt có tham số cho một lĩnh vực, hoặc “trình diễn” cách dùng server hiệu quả nhất. Prompts do người dùng điều khiển: phải được gọi tường minh chứ không tự kích hoạt. Prompt có thể tham chiếu tới resources và tools có sẵn để tạo thành quy trình hoàn chỉnh, và cũng hỗ trợ parameter completion như resources.

MethodMục đíchTrả về
prompts/listKhám phá các promptMảng định nghĩa prompt, gồm các arguments mỗi prompt nhận
prompts/getLấy một promptMảng prompt messages
completion/completeGợi ý giá trị đối sốMảng giá trị gợi ý
Lưu ý

Theo trang Server concepts: đối số của prompt không có kiểu. Mọi giá trị được gửi dưới dạng chuỗi, nên hãy dùng description để nói rõ định dạng mong đợi (vd “as YYYY-MM-DD”). Đối số là tùy chọn trừ khi required là true.

Viết prompt trong Python SDK

  • Trang trí hàm bằng @mcp.prompt(): tên prompt = tên hàm, description = docstring; thêm title="..." để có nhãn dễ đọc, ví dụ @mcp.prompt(title="Code review").
  • Mô tả từng đối số bằng Annotated[str, Field(description=...)] như với tool.
  • Đối số là danh sách phẳng các giá trị chuỗi có tên, không phải JSON Schema. Tham số không có mặc định là bắt buộc; thiếu đối số bắt buộc ⇒ request thất bại trước khi hàm chạy, với lỗi JSON-RPC “Invalid params” (mã -32602).
  • Trả str ⇒ một user message. Trả list[Message] ⇒ hội thoại nhiều lượt, theo thứ tự.
  • UserMessage, AssistantMessage (lớp cơ sở Message) import từ mcp.server.mcpserver.prompts.base. Mỗi lớp nhận một str (được bọc thành text); role lấy từ tên lớp. Prefill một AssistantMessage giúp định hướng câu trả lời kế tiếp của model.
# Thêm vào docs_server.py – hai prompt
from typing import Annotated
from pydantic import Field
from mcp.server.mcpserver.prompts.base import Message, UserMessage, AssistantMessage

@mcp.prompt(title="Format document")
def format_doc(
    doc_id: Annotated[str, Field(description="ID tài liệu cần định dạng lại")],
) -> str:                                        # str ⇒ một user message
    """Viết lại một tài liệu sang Markdown."""
    return (
        f"Hãy đọc tài liệu {doc_id} bằng tool read_doc, "
        "viết lại sang Markdown có tiêu đề, gạch đầu dòng, bảng nếu cần, "
        "rồi lưu bằng tool edit_document."
    )

@mcp.prompt(title="Summarize document")
def summarize_doc(doc_id: str, language: str = "tiếng Việt") -> list[Message]:
    """Tóm tắt một tài liệu."""
    return [
        UserMessage(f"Tóm tắt tài liệu {doc_id} bằng {language}, tối đa 5 gạch đầu dòng."),
        AssistantMessage("Tóm tắt:"),          # prefill định hướng câu trả lời
    ]

Khi người dùng chọn prompt, client gửi prompts/get kèm đối số (đều là chuỗi), server trả về messages để ứng dụng thêm vào hội thoại:

{ "jsonrpc": "2.0", "id": 4, "method": "prompts/get",
  "params": { "name": "summarize_doc",
              "arguments": { "doc_id": "report.pdf", "language": "tiếng Việt" } } }

Ứng dụng thường phơi bày prompts qua: slash command (gõ “/” để thấy prompt như /plan-vacation), command palette, nút bấm riêng cho prompt hay dùng, hoặc menu ngữ cảnh gợi ý prompt liên quan. Nguyên tắc: dễ khám phá, mô tả rõ, nhập đối số tự nhiên có kiểm tra, và hiển thị minh bạch template bên dưới.

user/summarize_doc doc_id: report.pdf
system[Ứng dụng gọi prompts/get → chèn user message “Tóm tắt tài liệu report.pdf bằng tiếng Việt…” + prefill “Tóm tắt:”]
assistantTóm tắt: • Báo cáo mô tả tháp ăng-ten cao 20m…
Mẹo thực chiến (Pro Tip)

Người dùng doanh nghiệp liên tục gõ lại cùng một prompt dài “hãy đọc tài liệu X, định dạng lại theo chuẩn công ty…” ⇒ đóng gói thành MCP prompt do server cung cấp. Tác giả server hiểu rõ tool của mình nhất, nên prompt được viết và kiểm thử sẵn sẽ cho kết quả ổn định hơn prompt người dùng tự gõ.

🚀Chạy server, ghi log và kết nối Claude for Desktop

Transport và lệnh chạy

  • mcp.run(transport="stdio") rồi uv run weather.py: server lắng nghe message từ host qua stdin/stdout.
  • CLI của SDK: uv run mcp dev server.py mở server trong MCP Inspector; uv run mcp run server.py --transport streamable-http phục vụ server qua Streamable HTTP.
  • SDK hỗ trợ các transport stdio, Streamable HTTP và SSE.

Quy tắc vàng khi ghi log với stdio

Lỗi thường gặp

Với server dùng stdio: không bao giờ ghi ra stdout. Ghi vào stdout sẽ làm hỏng các message JSON-RPC và làm server hỏng. Hàm print() mặc định ghi ra stdout, nên hãy loại nó khỏi server stdio. Với server HTTP, ghi log ra stdout không sao vì không ảnh hưởng HTTP response.

import logging

logger = logging.getLogger(__name__)   # mỗi module một logger

# ❌ Sai (STDIO)
print("Processing request")

# ✅ Đúng (STDIO)
logger.info("Processing request")    # module logging chuẩn ghi ra stderr

Kiểm thử tự động: Client in-memory

Trang Testing của SDK: truyền chính đối tượng server vào Client và nó kết nối trực tiếp, không subprocess, không cổng mạng (giống TestClient của FastAPI). Mỗi test nhận một kết nối in-memory mới.

# test_server.py   (cài: uv add --dev pytest inline-snapshot)
import pytest
from mcp import Client
from server import mcp

@pytest.fixture
def anyio_backend():
    return "asyncio"

@pytest.fixture
async def client():
    async with Client(mcp, raise_exceptions=True) as c:   # chỉ bật raise_exceptions trong test
        yield c

@pytest.mark.anyio
async def test_add(client: Client):
    result = await client.call_tool("add", {"a": 1, "b": 2})
    assert result.content[0].text == "3"
  • Ngoại lệ trong tool luôn trả kết quả is_error=True, dù có bật raise_exceptions hay không.
  • raise_exceptions=True cho test thấy thông điệp thật của lỗi ngoài thân tool (bình thường bị che thành lỗi nội bộ chung). Chỉ bật trong test.
  • Client(mcp) tự dò server và chọn nhánh giao thức; cần hành vi legacy (sampling, elicitation push…) thì dùng Client(mcp, mode="legacy").

🔐Bảo mật khi viết MCP server

  • Prompt injection: dữ liệu mà tool/resource trả về (trang web, email, file người dùng tải lên) đi thẳng vào ngữ cảnh của Claude. Văn bản độc hại trong đó có thể cố “ra lệnh” cho model. Hãy coi mọi dữ liệu ngoài là dữ liệu, không phải chỉ thị; tool có tác dụng phụ (gửi email, xóa file, chuyển tiền) nên để host yêu cầu người dùng duyệt.
  • Least privilege (đặc quyền tối thiểu): mỗi tool chỉ làm một việc, chỉ truy cập đúng thư mục/bảng cần thiết; tách tool đọc và tool ghi để client có thể duyệt riêng tool ghi. Annotations như read_only_hint chỉ là gợi ý – quyền thật phải được kiểm tra trong code server.
  • Kiểm tra đầu vào: tận dụng schema (Literal, Field(ge=…, le=…)) để SDK từ chối đối số sai trước khi hàm chạy; với đường dẫn file, chặn .. (path traversal); với SQL, dùng truy vấn tham số hóa thay vì nối chuỗi.
  • Bí mật: không hard-code API key trong code server; đọc từ biến môi trường hoặc trường env trong cấu hình host. Inspector lưu secret (OAuth token, client secret, giá trị env: của stdio) trong keychain của hệ điều hành; nếu máy không có keychain, chúng được ghi vào ~/.mcp-inspector/secrets.json không mã hóa trừ khi bạn cung cấp khóa.
  • Thông báo lỗi: chỉ đưa vào ToolError những gì model cần để sửa; chi tiết nội bộ để SDK tự che và ghi vào log server.

Tóm tắt ghi nhớ

Key takeaways
  • Ba primitive: Tools (model điều khiển, hành động), Resources (ứng dụng điều khiển, dữ liệu chỉ đọc theo URI), Prompts (người dùng điều khiển, template có tham số).
  • Python SDK 2.x: from mcp.server import MCPServer – tên mới của FastMCP; module mcp.server.fastmcp.* → mcp.server.mcpserver.*. Cài bằng uv add "mcp[cli]".
  • @mcp.tool(): type hints + docstring sinh ra inputSchema; tham số không mặc định là bắt buộc; đối số sai bị chặn trước khi hàm chạy.
  • raise ToolError ⇒ is_error=True, thông điệp tới model; ngoại lệ khác bị che nội dung, traceback chỉ ở log server.
  • @mcp.resource("scheme://..."): URI tĩnh vào resources/list; URI có {param} là template vào resources/templates/list; tên tham số hàm phải khớp placeholder; mime_type mặc định plain text.
  • @mcp.prompt(): đối số luôn là chuỗi; trả str (1 user message) hoặc list[Message] với UserMessage/AssistantMessage.
  • Server stdio: không bao giờ print() ra stdout – dùng logging (stderr).
  • MCP Inspector: npx @modelcontextprotocol/inspector (Web / --cli / --tui), hoặc uv run mcp dev server.py; test tự động bằng Client(mcp) in-memory.

Thuật ngữ (Glossary)

MCP server
Máy chủ MCP – chương trình phơi bày tools, resources, prompts cho ứng dụng AI qua giao thức MCP.
Primitive / building block
Khối xây dựng – ba loại năng lực cốt lõi của server: tools, resources, prompts.
Tool (MCP)
Công cụ – hàm có schema mà model chủ động gọi qua tools/call.
Resource
Tài nguyên – dữ liệu chỉ đọc, định danh bằng URI, ứng dụng chọn đưa vào ngữ cảnh.
Direct resource
Tài nguyên trực tiếp – resource có URI cố định, liệt kê qua resources/list.
Resource template
Mẫu tài nguyên – URI có tham số {param}, khám phá qua resources/templates/list.
Prompt (MCP)
Mẫu prompt – template có đối số dạng chuỗi, người dùng gọi tường minh (vd slash command).
MCPServer
Lớp server cấp cao của Python SDK 2.x (trước đây tên FastMCP).
FastMCP
Tên cũ (v1.x) của lớp server cấp cao trong Python SDK, module mcp.server.fastmcp.
Decorator
Bộ trang trí – cú pháp @... của Python dùng để đăng ký hàm thành tool/resource/prompt.
inputSchema / outputSchema
Lược đồ đầu vào / đầu ra – JSON Schema mô tả đối số và kết quả có cấu trúc của tool.
structured_content
Nội dung có cấu trúc – dữ liệu có kiểu cho ứng dụng client (trên dây: structuredContent).
ToolError
Ngoại lệ báo lỗi tool mà model đọc được; kết quả có is_error=True.
Tool annotations
Chú thích hành vi tool – gợi ý như read_only_hint, destructive_hint; không phải cơ chế bảo mật.
Context (SDK)
Ngữ cảnh request – đối tượng tiêm vào handler: request_id, report_progress, read_resource, elicit…
MIME type
Kiểu nội dung – nhãn định dạng dữ liệu của resource (vd application/json).
Parameter completion
Gợi ý giá trị tham số – completion/complete, server gợi ý giá trị cho template/prompt.
stdio transport
Kênh vào/ra chuẩn – host chạy server như tiến trình con, trao đổi JSON-RPC qua stdin/stdout.
Streamable HTTP

Câu hỏi luyện tập

Một công ty luật xây MCP server cho kho hồ sơ vụ án. Luật sư muốn gõ @hop-dong-123 trong ô chat để đính kèm nội dung hợp đồng làm ngữ cảnh, không cần Claude tự quyết định. Nên phơi bày hồ sơ bằng primitive nào?
  1. Tool read_contract(id), vì tool là cách duy nhất để server trả dữ liệu.
  2. Prompt attach_contract, vì người dùng là người kích hoạt.
  3. Resource template contracts://{id}, để ứng dụng đọc và chèn nội dung vào ngữ cảnh.
  4. Sampling, để server tự gọi Claude đọc hợp đồng.
Đáp án C. Resources là dữ liệu chỉ đọc do ứng dụng điều khiển – ứng dụng (theo thao tác @ của người dùng) đọc qua resources/read và đưa vào ngữ cảnh; template phù hợp vì có tham số id. A sai: tool do model quyết định gọi và tốn thêm một vòng tool call; tool cũng không phải cách duy nhất trả dữ liệu. B sai: prompt là template chỉ dẫn, không phải kênh đính kèm dữ liệu tài liệu. D sai: sampling là server nhờ client gọi LLM, không liên quan tới việc đính kèm nội dung.
Bạn chép đoạn code sau từ một blog năm 2024 vào dự án vừa tạo bằng uv add "mcp[cli]" và gặp ImportError. Cách sửa phù hợp nhất với Python SDK hiện hành là gì? 
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("notes")
  1. Đổi thành from mcp.server import MCPServer và mcp = MCPServer("notes").
  2. Cài thêm gói fastmcp vì SDK chính thức đã bỏ hỗ trợ server cấp cao.
  3. Đổi thành from mcp import FastMCP vì module đã được đưa lên cấp gốc.
  4. Hạ Python xuống 3.9 vì FastMCP chỉ chạy trên Python cũ.
Đáp án A. Theo trang What's new in v2, pip install mcp cài bản 2.x và lớp cấp cao được đổi tên cùng module: FastMCP → MCPServer, mcp.server.fastmcp.* → mcp.server.mcpserver.*. B sai: SDK vẫn có server cấp cao, chỉ đổi tên. C sai: không có đường import đó. D sai: lỗi do đổi tên, không phải do phiên bản Python (SDK cần Python mới hơn, không phải cũ hơn).
Server MCP dùng stdio của bạn chạy tốt khi test bằng hàm, nhưng khi Claude for Desktop kết nối thì liên tục báo lỗi phân tích message. Trong code có dòng print(f"Calling API {url}") trong mỗi tool. Nguyên nhân và cách sửa?
  1. Thiếu async ở các tool; thêm async def sẽ hết lỗi.
  2. Claude for Desktop chỉ hỗ trợ Streamable HTTP; phải đổi transport.
  3. Docstring quá dài làm schema vượt giới hạn; cần rút ngắn.
  4. print() ghi ra stdout, làm hỏng các message JSON-RPC; thay bằng logging (ghi ra stderr).
Đáp án D. Tài liệu ghi rõ: với server stdio, không bao giờ ghi ra stdout vì sẽ làm hỏng JSON-RPC; print() mặc định ghi ra stdout; dùng module logging (ghi stderr). A sai: tool đồng bộ vẫn hợp lệ (SDK chạy chúng trên worker thread). B sai: hướng dẫn chính thức kết nối Claude for Desktop qua stdio (command + args). C sai: không có dấu hiệu nào liên quan đến độ dài docstring.
Đọc đoạn code sau. Điều gì xảy ra? 
@mcp.resource("users://{user_id}/profile")
def get_profile(uid: str) -> dict:
    return db.load(uid)
  1. Chạy bình thường; SDK tự ánh xạ placeholder đầu tiên vào tham số đầu tiên.
  2. Decorator ném ValueError ngay lúc import vì tên tham số uid không khớp placeholder {user_id}.
  3. Resource được đăng ký là resource tĩnh và xuất hiện trong resources/list.
  4. Lỗi chỉ xuất hiện khi client gọi tools/call.
Đáp án B. Trang Resources của SDK: hàm phải có tham số trùng tên với placeholder; nếu khác, decorator raise ValueError lúc import. A sai: SDK ghép theo tên, không theo vị trí. C sai: URI có {...} là template, nằm trong resources/templates/list, không phải list tĩnh. D sai: resource không đi qua tools/call, và lỗi xảy ra sớm hơn – lúc import.
Những phát biểu nào đúng về prompts trong MCP và Python SDK? (Chọn 2)
  1. Đối số của prompt không có kiểu; mọi giá trị được gửi dưới dạng chuỗi.
  2. Prompts do model điều khiển: Claude tự gọi prompts/get khi thấy cần.
  3. Hàm @mcp.prompt() có thể trả list[Message] gồm UserMessage và AssistantMessage để tạo hội thoại nhiều lượt.
  4. Thiếu đối số bắt buộc thì hàm prompt vẫn chạy với giá trị None.
  5. Prompt phải khai báo inputSchema dạng JSON Schema như tool.
Đáp án A, C. A đúng theo Server concepts: “Prompt arguments don't have types”, mọi giá trị là chuỗi. C đúng: trả list[Message] để seed hội thoại, lớp import từ mcp.server.mcpserver.prompts.base. B sai: prompts do người dùng điều khiển, cần gọi tường minh. D sai: thiếu đối số bắt buộc ⇒ request thất bại trước khi hàm chạy, lỗi -32602. E sai: đối số prompt là danh sách phẳng giá trị chuỗi có tên, không phải JSON Schema.
Tool get_invoice(invoice_id) không tìm thấy hóa đơn. Bạn muốn Claude biết lý do để hỏi lại người dùng mã đúng, nhưng không để lộ chuỗi kết nối database khi có lỗi kết nối. Cách làm nào đúng?
  1. Trả về chuỗi "OK" trong mọi trường hợp để không lộ lỗi.
  2. Bọc mọi ngoại lệ và đưa str(e) vào ToolError, kể cả lỗi kết nối.
  3. Raise MCPError cho cả hai trường hợp để client tự xử lý.
  4. Không tìm thấy ⇒ raise ToolError("Không có hóa đơn ... hãy kiểm tra mã"); lỗi kết nối ⇒ để ngoại lệ thường lan ra cho SDK che nội dung và ghi traceback vào log.
Đáp án D. ToolError đưa thông điệp tới model (is_error=True) để model tự khắc phục; ngoại lệ khác chỉ trả “Error executing tool …”, traceback ghi ở mức ERROR trên server. A sai: che lỗi khiến model trả lời sai sự thật. B sai: đưa str(e) của lỗi kết nối vào ToolError làm lộ chi tiết nội bộ. C sai: MCPError làm hỏng cả request, model không nhận được kết quả để hỏi lại người dùng; lại còn chuyển nguyên message/data không che.
Nhóm DevOps muốn mỗi pull request tự động kiểm tra MCP server vẫn phơi bày đủ các tool, kết quả dạng JSON để so sánh, chạy trên runner không có trình duyệt. Lựa chọn nào phù hợp nhất?
  1. Mở Inspector bản web và chụp màn hình tab Tools mỗi lần merge.
  2. npx @modelcontextprotocol/inspector --cli <lệnh server> --method tools/list (kèm --format json khi cần).
  3. Cấu hình server vào Claude for Desktop trên runner và hỏi Claude liệt kê tools.
  4. Dùng npx @modelcontextprotocol/inspector --tui vì TUI chạy được trong terminal.
Đáp án B. Tài liệu mô tả client CLI là “scriptable, machine-readable client for CI, shell pipelines, and coding agents”, ví dụ --method tools/list. A sai: web UI cần trình duyệt và thao tác tay. C sai: không tự động, không xác định, phụ thuộc model. D sai: TUI là giao diện tương tác trong terminal, không phù hợp chạy tự động trong CI.
Đọc đoạn code sau. JSON Schema mà client nhận được trong tools/list có đặc điểm gì? 
@mcp.tool()
def search(query: str,
           ctx: Context,
           limit: Annotated[int, Field(ge=1, le=50)] = 10) -> str:
    """Search the catalog."""
  1. required gồm query, limit, ctx.
  2. Không có schema vì hàm không khai báo input_schema thủ công.
  3. required chỉ có query; limit có minimum: 1, maximum: 50; ctx không xuất hiện.
  4. ctx xuất hiện như một tham số kiểu object để model truyền request ID.
Đáp án C. SDK sinh schema từ type hints: tham số không mặc định (query) là bắt buộc, limit có mặc định nên tùy chọn, Field(ge, le) thành minimum/maximum; tham số Context do SDK tiêm và không xuất hiện trong input schema. A sai: limit có mặc định, ctx không thuộc schema. B sai: “type hints là schema” – không cần viết tay. D sai: model không bao giờ thấy ctx.
Bạn đã thêm server vào claude_desktop_config.json nhưng server không hiện trong menu Connectors. Hai bước kiểm tra nào được hướng dẫn chính thức khuyến nghị? (Chọn 2)
  1. Đảm bảo đường dẫn tới dự án là tuyệt đối (trên Windows dùng \\ hoặc /), và có thể ghi đường dẫn đầy đủ tới uv.
  2. Đổi khóa mcpServers thành servers cho đúng chuẩn mới.
  3. Đóng cửa sổ Claude rồi mở lại là đủ để nạp cấu hình.
  4. Thêm print("ready") vào server để Claude biết server đã sẵn sàng.
  5. Thoát hẳn ứng dụng (system tray → Quit trên Windows, Cmd+Q trên macOS) rồi xem mcp.log và mcp-server-TÊN.log.
Đáp án A, E. Phần Troubleshooting yêu cầu kiểm tra cú pháp file, dùng đường dẫn tuyệt đối, khởi động lại hoàn toàn ứng dụng, và đọc log mcp.log / mcp-server-SERVERNAME.log; cảnh báo cũng nói có thể phải ghi đường dẫn đầy đủ tới uv. B sai: khóa đúng là mcpServers. C sai: tài liệu nói chỉ đóng cửa sổ thì cấu hình chưa có hiệu lực. D sai: print ghi ra stdout và làm hỏng giao tiếp stdio.
Server của bạn có tool delete_record(id) và đặt annotations=ToolAnnotations(destructive_hint=True). Một đồng nghiệp cho rằng “có annotation rồi thì client sẽ chặn mọi lệnh xóa trái phép, server khỏi cần kiểm tra quyền”. Nhận định nào đúng?
  1. Đúng – destructive_hint buộc mọi client hỏi xác nhận và từ chối nếu người dùng không có quyền.
  2. Sai – annotations chỉ là gợi ý cho client, không phải cơ chế bảo mật; server vẫn phải kiểm tra quyền, đầu vào và áp dụng least privilege.
  3. Đúng – nếu thêm cả read_only_hint=True thì tool sẽ không thể xóa được.
  4. Sai – nên bỏ annotation vì nó làm Claude không bao giờ gọi tool.
Đáp án B. Trang Tools của SDK nói annotations là “hints for clients, not a security mechanism”. A sai: annotation không bắt buộc client làm gì và không biết gì về quyền người dùng. C sai: read_only_hint chỉ là khai báo, không thay đổi hành vi code; lại mâu thuẫn với tool xóa. D sai: annotation không ngăn Claude gọi tool, nó giúp client quyết định UX (vd hỏi xác nhận) – nên giữ lại.
